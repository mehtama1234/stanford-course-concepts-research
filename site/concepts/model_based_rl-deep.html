Model-Based RL — learn the world's rules first, then plan in your head

An agent that learns by pure trial and error — trying actions and learning their costs after the fact — wastes experience. Each lesson requires actually taking the action, which is slow, costly, or dangerous in the real world. Model-based reinforcement learning flips this: first build an internal model of how the world works (where each action leads, what it pays), then simulate thousands of possibilities in your head against that model, planning the best route without moving. Here is the idea, a real measurement on a maze showing it saves enormous experience, why learning a model first is so much better, where it breaks, and how this insight powers AlphaZero and the frontier of robotics.

1 · The problem — trial and error wastes the world

Learning by pure trial and error in the real world is brutally expensive. An autonomous robot learning to grasp has a limited number of real interactions before it breaks; a self-driving car cannot practice crashes; a warehouse agent has a finite number of attempts before mistakes pile up in cost. Every lesson requires actually taking the action and observing the outcome. The agent flails, stumbles toward the goal, and pays for every mistake in steps, time, or damage.

The need is stark: how can an agent learn efficiently when the world is slow, costly, or dangerous — so that real interactions are the scarcest resource?

2 · The reframe — learn the world's rules, then simulate

Here is the move. Instead of learning values purely by bumping into the world, first invest a small budget of real experience to learn a model — a prediction of what each action does. The model is a map: 'if I am here and move north, I land there and get this reward'. Once you have the map, stop taking real actions and start imagining them. Simulate thousands of paths through your learned world for free, play them out in your head, and pick the best one. The real world is used only to gather the map; all the trial and error — the search, the planning — happens inside the model. This is model-based reinforcement learning. The insight is profound: real experience is spent learning once how the world works, then the agent can do infinite imagined trial and error at no cost.

3 · Seen on a real run — the model saves real steps

We tested both approaches on a maze: a 6 by 6 grid with a goal somewhere in it. Each step costs 1 point (penalty), reaching the goal earns 10 points, so the best possible is a 10-step path (net +1 after penalties). The test: how many real steps in the actual world does each agent need to solve it? We ran each method 5 times and took the median.

The discovered fact: model-free trial and error requires 705 real steps; model-based learning takes only 300 real steps and then solves the maze by planning. The model-based agent spends its real interactions gathering a mental map. Once it has the map, it can imagine paths for free. The model-free agent has no map — it tries the same state-action pairs over and over, learning the value of each purely by accumulation, a much slower process in the real world.

4 · Why learning a map first saves trial and error

The key is leverage. A model learned from even a modest amount of data can be queried infinitely. Once the agent knows 'from here, north takes me to the next cell', it can simulate: 'if I take north, then west, then south, what do I get?' without touching the world. A blind search algorithm — depth-first, breadth-first, even Monte Carlo tree search — takes these mental predictions and explores millions of paths for free. The model-free approach has no mental leverage; it must try each move in reality and wait for the outcome, then try another. Over time, both converge, but the model-based agent reaches the goal far sooner because it is doing its exploration in the cheap domain (imagination) and using the expensive domain (reality) only to refine the map. In a task where real steps cost time, energy, or safety, this difference is everything.

5 · The one real weakness — the plan is only as good as the model

The trap is compounding error. A model learned from limited data will be imperfect — it might mispredict where an action leads or get the reward slightly wrong. When an agent plans far into the future using a flawed model, the errors accumulate. A small mistake about immediate outcomes becomes a large mistake 20 steps ahead. Also, learning an accurate model of a complex world — one with many states, many actions, and rich outcomes — is itself a hard learning problem. Sometimes the agent spends so much effort learning the model that model-free methods, which sidestep this work, end up faster on the same wall-clock time. The tradeoff is real: model-based is sample-efficient (fewer real interactions) but computationally expensive; model-free is sample-inefficient but simpler.

6 · The surprise — this idea powers AlphaZero and the frontier of robotics

Model-based planning is far larger than gridworld mazes. AlphaZero learned to play chess and Go by learning a model of the game (what moves are legal, how the board changes) and then using Monte Carlo tree search — exhaustive imagined planning — to decide on each move without trial and error. MuZero extends this: it learns not a perfect model but a compressed model that is just good enough for planning, throwing away irrelevant details and keeping what matters for the decision. In robotics, the frontier is 'world models' — agents that learn a model of the physical world and then dream, practicing skills in imagined simulation before trying them in reality. The same principle — invest in understanding, then exploit that understanding with cheap imagination — appears in domains from drug discovery (model the chemistry, simulate reactions) to traffic optimization (model driver behavior, plan signal timings). Once you see it, the idea is everywhere: wherever imagination is cheaper than experience, model-based planning wins.

the run recipe — reproduce every number above

Run a 6x6 gridworld with two learning algorithms: (1) model-free: train Q-values purely by trial and error, taking real steps and observing outcomes; (2) model-based: use the first ~300 real steps to learn a state-transition model (a lookup table of 'state, action -> next state, reward'), then use that model to plan via breadth-first search. Measure how many real steps each takes to solve the maze (reach the goal optimally). Repeat 5 times and report the median.

model_free: V(s) := V(s) + alpha * (reward + gamma * max_a V(next_s) - V(s)) model_based: learn P(s' | s, a) and R(s, a) from data; plan via argmax_a E[return | simulate(s, a, model)]
