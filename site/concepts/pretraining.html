Pretraining

Large-scale practice before the model is asked to be useful in a specific way.

What real-world problem is this about?

The problem is that labeled examples are scarce, but raw text, images, actions, and videos are abundant.

Why does this problem exist?

A learner can absorb structure by being given a simple prediction game over huge data, even before people specify the final task.

What is the mathematical idea underneath?

Training reduces a loss, which is a number measuring how surprised or wrong the model was. Lower loss means the model assigns more probability to what actually happened.

Why is this concept important?

It creates broad reusable knowledge that later tuning can steer.

What breaks without it?

Every task would need its own large hand-labeled dataset, and models would learn narrow behavior from scratch.

Naive Starting Point

Start with the simplest version: The problem is that labeled examples are scarce, but raw text, images, actions, and videos are abundant. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because a learner can absorb structure by being given a simple prediction game over huge data, even before people specify the final task. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Pretraining: Training reduces a loss, which is a number measuring how surprised or wrong the model was. Lower loss means the model assigns more probability to what actually happened. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Pretraining, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: before becoming a helpful assistant, a language model spends massive compute learning to autocomplete text and code. CME295 says pretraining teaches the model the structure of language and code at large scale, but the result is still only a next-token predictor. That distinction is the point: pretraining creates broad competence by repeated prediction, while later tuning changes how that competence is used.

What the Lectures Emphasize

The tuning lecture emphasizes pretraining as the compute-heavy first stage. It happens on a lot of data, requires parallel training systems, and produces a model that knows patterns in text and code but is not yet helpful. This frames pretraining as broad practice, not final behavior.

Common Misunderstanding

A common misunderstanding is that pretraining alone creates an assistant. The lecture explicitly separates knowing how to autocomplete from behaving helpfully. Without later fine-tuning or preference tuning, the model may be knowledgeable and fluent but not aligned to the user's task.

How to Recognize This in a New Paper or Model

In a new paper, recognize pretraining when a large model learns from abundant raw data through a general prediction or reconstruction task before downstream adaptation. The method may be next-token prediction, masked prediction, denoising, contrastive pretraining, or self-supervised learning. The shared primitive is practice from cheap feedback.

Connected Concepts

The same primitive reappears near fine tuning, scaling laws, generalization. Across the three courses, the shared pattern is feedback, scale: choose what to keep, how to move, what feedback means, or how to measure whether the behavior really improved.
