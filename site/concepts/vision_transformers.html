Vision Transformers

A way to let different regions of an image communicate directly with each other instead of through a pipeline.

What real-world problem is this about?

Imagine sorting photos: you spot that a face is happy by reading both the smile and the eyes, which sit far apart. If you can only look at tiny neighborhoods at a time, you'll miss the connection. The distance matters.

Why does this problem exist?

Images encode meaning in spatial relationships: a face's emotion comes from eyes, nose, and mouth together; a scene's layout emerges from how objects relate to each other. A system that only patches together local clues will miss these global patterns. Any vision system solving realistic problems must let distant image parts influence each other.

What is the mathematical idea underneath?

Start with an image and chop it into rectangular patches (say, 16×16 pixels each). Represent each patch as a vector (a list of numbers). Compute attention: for each patch, measure how much it should listen to every other patch using a dot product (multiply corresponding numbers and sum them, which measures how similar two vectors are). Then divide by the square root of the vector's size to keep the numbers stable. Pass this through softmax (a function that turns numbers into percentages that sum to 100%). Finally, multiply each other patch's vector by those percentages and sum them. This gives each patch a weighted combination of all other patches, letting distant regions influence each other in one step.

Why is this concept important?

This single mechanism replaces hand-built rules about which parts of an image should matter. The model learns which regions to link during training, adapting to different image types and tasks. This same idea scales to billions of images and foundation models.

What breaks without it?

Without global communication, a model relies on stacked local filters (convolution layers), which must pass information slowly from the edge inward. Understanding a face requires the border pixels to influence the center through many layers, introducing delays and bottlenecks. Some long-range patterns stay invisible.

Naive Starting Point

A beginner might think: images have local structure (edges, textures), so just apply local filters everywhere, like standard computer vision does. Chain enough layers and information propagates.

Why the Simple Approach Fails

Local filters take many layers to move information across the image. A 300×300 pixel image needs maybe 10 layers of 3×3 filters before the center pixel even knows about the edges. With a billion pixels in a high-resolution image, that becomes impractical. Attention skips this hierarchy: every patch reaches every other patch in one step.

The Mathematical Object

The attention weights: a square table with one row and column per image patch, where each cell (i, j) holds a percentage saying how much patch i should blend in patch j's output. This table emerges from the patch vectors and updates during training, so the model learns which regions to link.

The Operation

First, split the image into patches and turn each into a vector. Next, for each patch, compute how similar it is to every other patch (dot product). Normalize those scores and convert to percentages (softmax). Then, blend all other patches using those percentages. The result is a new vector for each patch that carries information from the whole image.

Worked Mini-Example

Take a 4×4 image (16 pixels) and divide it into four 2×2 patches: top-left (a red corner), top-right (a blue corner), bottom-left (green), bottom-right (yellow). Each patch becomes a vector, say [0.8, 0.1] for red. Compute dot products: red·red = 0.65, red·blue = 0.05, red·green = 0.1, red·yellow = 0.2. Scale and softmax: these become roughly [0.6, 0.1, 0.1, 0.2]. The red patch's new vector is 0.6×[0.8, 0.1] + 0.1×[0.3, 0.9] + 0.1×[0.1, 0.8] + 0.2×[0.9, 0.1] = [0.67, 0.25]. The red patch now contains a hint of blue, green, and yellow—global context in one step.

What the Lectures Emphasize

The CME296 lecture stresses the core transfer: the vision transformer takes the transformer idea from language (patches exchange information via attention) and applies it to images by cutting images into patches and treating those patches as tokens. This move unified vision and language under one architecture, enabling multimodal models. CME295 notes that this extends the transformer beyond text, showing how the same mechanism handles different input types.

Common Misunderstanding

Students often think vision transformers succeed because they copy language transformers exactly. In reality, images need spatial position encoding (so the model knows where each patch sits), careful patch size choices (too small is expensive, too large loses detail), and sometimes visual priors. Patches are the starting move; they are not the whole insight.

How to Recognize This in a New Paper or Model

Look for images split into patches or visual tokens that are then embedded and processed with attention blocks. Papers naming ViT (Vision Transformer), DiT (Diffusion Transformer for images), or CLIP (which attends over image patches) are using this primitive. In medical imaging or satellite analysis, if the system splits an image and lets all regions communicate globally, vision transformers are at work.

Connected Concepts

Vision transformers sit at the intersection of three course themes: (1) Transformers (CME295) — the attention mechanism itself; (2) Diffusion and vision (CME296) — diffusion models often use transformer backbones to process image features; (3) RL (CS224R) — vision encoders in RL agents often use attention-based architectures to extract state features. Position encoding (from 'Position and Order') tells the model where patches sit. Latent space (from 'Latent Space') is what the patch vectors occupy. Attention (from 'Attention') is the mechanism that powers the whole thing.
