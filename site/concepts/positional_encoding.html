Position And Order

A set of numbers attached to each piece of data that tells the model what slot that piece occupies in a sequence or grid.

Go deeper: this concept has a first-principles deep dive with a result we actually computed — the real run, an honest limit, and a surprising connection. See the whole deep track →

What real-world problem is this about?

You hear two sentences: "dog bites man" and "man bites dog." Same three words, but they mean opposite things because the order is different. Now imagine a listener who hears all three words at once, jumbled in a cloud, with no sense of which came first. Without marking each word with its position, that listener cannot tell the two sentences apart.

Why does this problem exist?

Modern AI systems called transformers work by comparing every piece of data to every other piece at the same time, all at once. This is different from older systems that read data one piece after another, where the order was automatic. When everything is compared in parallel, the system needs a way to know where each piece came from in the original sequence, or that information is lost forever.

What is the mathematical idea underneath?

Each position gets a set of numbers (called a vector) built from repeating waves of different speeds. Position 0 might be [1.0, 0, 0.5, 0, ...], position 1 might be [0.84, 0.54, 0.38, 0.92, ...], position 2 might be [0.41, 0.91, -0.94, 0.75, ...]. The waves move at different rates: some change slowly (positions far apart look very different), some change fast (positions next to each other look similar). This pattern is then mixed together with the data the model sees.

Why is this concept important?

Without position information, the system cannot tell apart grammar rules (which word is the subject, which is the object), where things sit in images (top-left versus bottom-right), or time sequences. With position signals, the system learns to use distance and order as clues, so it can handle language structure, spatial layout, and time-ordered data.

What breaks without it?

The system treats inputs as a pile of data with no internal order. It would confuse "dog bites man" with "man bites dog" as the same thing. In images, it would lose track of which square of pixels is where. Any meaning that comes from structure and sequence collapses into noise.

Naive Starting Point

A first attempt might seem obvious: just give each position a plain number. Position 1 gets the number 1, position 2 gets the number 2, position 3 gets the number 3.

Why the Simple Approach Fails

Plain numbers do not work. The system does math on those numbers during comparison. The distance between position 1 and position 2 (a difference of 1) gets treated the same way as the distance between position 1000 and position 1001 (also a difference of 1). The system cannot learn that neighbors should interact differently from distant positions. Also, a system trained on sequences up to 100 positions long will fail on a sequence of 500 positions—it has never seen those numbers before.

The Mathematical Object

The position encoding is a lookup table where each position number k maps to a list of numbers (same length as the data the model processes). For positions 0, 1, 2, and so on, these lists are built using sine and cosine waves at different frequencies. Each position gets a unique pattern, but the pattern is structured so that nearby positions have overlapping numbers while distant positions differ more.

The Operation

For each piece of data: find what position it is (call it k), look up or compute the list of numbers for position k, then add those numbers to the data the model will process. Now the position signal is woven into the actual data the model compares.

Worked Mini-Example

A sequence has 8 tokens representing 'the cat sat on the mat.' Each token gets a 128-dimensional embedding. Position 0 ('the') adds a position encoding [sin(0), cos(0), sin(0/10000^(2/128)), cos(0/10000^(2/128)), ...], computed as sine-cosine waves at different frequencies. This produces roughly [1.0, 0.0, 0.9998, 0.0198, 0.9991, 0.0393, ...]. Position 1 ('cat') adds [sin(1), cos(1), sin(1/10000^(2/128)), cos(1/10000^(2/128)), ...], roughly [0.841, 0.540, 0.9998, 0.0200, 0.9991, 0.0395, ...]. These are similar: positions 0 and 1 are neighbors, and their encodings overlap in the low frequencies (slow sine waves). Position 7 ('mat') adds encodings with much higher-frequency components that differ sharply from position 0. When the attention mechanism compares 'the' and 'cat' to see if they influence each other, the position encodings are woven into those comparisons, and the system learns that positions 0 and 1 should interact more strongly than positions 0 and 7. A model trained on sequences up to length 8 can still process sequences of length 512 because the sine-cosine pattern extrapolates smoothly.

What the Lectures Emphasize

The Stanford course explains that transformers process all data in parallel instead of one piece at a time, which is how older systems worked. By processing in parallel, transformers save time but lose the automatic sense of position. The solution is to glue position information directly into the numbers each piece carries. Vision courses show the same idea: when an image is cut into patches and processed all at once, each patch's grid location must be encoded as numbers if the system is to understand the image's layout.

Common Misunderstanding

People often think the system somehow remembers order just because the data is listed in order in the input. But the system only sees numbers. If position is not encoded as part of those numbers (mixed in from the start), the system has no mathematical way to know order. It sees a jumble, not a sequence.

How to Recognize This in a New Paper or Model

In new papers and systems, look for any way position or location is encoded: standard position embeddings (lists of numbers built from waves), relative position biases (differences between positions added during comparison), rotary position embeddings (a rotation applied to the numbers based on position), ALiBi (penalties added during comparison based on distance), patch embeddings in vision models (location of each image square), or timestep embeddings in diffusion systems (where in the noise-to-clean sequence). These are all the same idea: turn position into a number signal the system can use.

Connected Concepts

In Stanford's transformer course, position embeddings sit inside the core system, paired with the comparison mechanism. In vision courses, diffusion systems and image-processing systems both add location or time signals: diffusion adds timestep numbers (which step from messy to clean), vision adds patch location numbers. In reinforcement learning, agent states often include position or location features to ground the agent in where it is. The common thread across all these is that structure—order, space, time—must be turned into numbers or the system cannot reason about it.
