Position And Order

A numerical tag attached to each input that tells the model which slot in the sequence or image it occupies.

What real-world problem is this about?

Imagine you're listening to a friend describe a scene, but they rattle off words in a jumbled order: "dog bites man" versus "man bites dog." Same words, opposite meaning. The order matters. Now imagine a listener who hears all the words at the same time, as a cloud with no internal sequence. That listener has no built-in way to know which word came first unless you mark each one with a position tag.

Why does this problem exist?

Transformers work by comparing any token to any other token directly in parallel, unlike older systems that processed tokens one-by-one and thus learned sequence order naturally. Because attention links bypass the sequential order, the model has no automatic way to know where each token sits in the sequence. Something must explicitly label position, or the model loses that information entirely.

What is the mathematical idea underneath?

A position embedding is a vector (a list of numbers) assigned to position k. The simplest version uses sinusoidal functions: embed(k) = [sin(k/10000^0), cos(k/10000^0), sin(k/10000^2), cos(k/10000^2), ...]. Each dimension oscillates at a different frequency—low frequencies change slowly (far-away positions look different), high frequencies change quickly (nearby positions stay similar). Adding this vector to the token's embedding lets attention patterns attend based on distance, because the position signal is now mixed into the data the model compares.

Why is this concept important?

Without position signals, the transformer cannot distinguish grammar (subject-verb-object order), spatial layout in images, time sequences in data, or any structure that depends on where something is. With it, the model learns to use distance and order as features, enabling it to handle syntax, narrative, and spatial reasoning.

What breaks without it?

The model sees the same set of tokens regardless of order. It might confuse "dog bites man" with "man bites dog." In vision, it loses track of which patch is top-left versus bottom-right. Relationships that depend on structure collapse into meaninglessness.

Naive Starting Point

A beginner might think: "Just give the model the position as a plain number—position 1, position 2, position 3." This seems direct and simple.

Why the Simple Approach Fails

Plain position numbers don't work because the model's attention layer does math on those numbers. A distance of 1 (positions 1 and 2) gets treated the same way as a distance of 1000 (positions 1000 and 1001). The model cannot learn that nearby tokens interact differently from distant ones. Also, plain numbers don't generalize—a model trained on sequences up to length 100 sees unexpected inputs if a sequence is 500 tokens long.

The Mathematical Object

The position embedding is a lookup table or a function that maps each position k to a vector of D numbers (usually the same dimension as the token embedding). For k=0, 1, 2, ... you compute the vector using sines and cosines at different frequencies, producing a unique but structured pattern for each position. This table is added to the token embedding before attention runs.

The Operation

For each token in the sequence: look up its position k, compute or retrieve the position embedding for k, and add it element-by-element to the token embedding. Pass the combined embedding into the attention layer. The position signal is now woven into the values the model compares.

Worked Mini-Example

Consider the sentence "cat sat on mat" with positions 0, 1, 2, 3, 4. The token "cat" has embedding [0.2, -0.1, 0.5, ...]. Position 0's embedding might be [1.0, 0, 0.5, 0, ...] (using sinusoids). We add them: cat's final embedding is [1.2, -0.1, 1.0, ...]. Token "sat" at position 1 gets [0.1, -0.2, 0.3, ...] added (a different position pattern). When attention computes the similarity between "cat" and "sat", the embedded positions are part of that comparison—nearby positions produce overlapping position vectors, so the attention scores reflect distance.

What the Lectures Emphasize

The Stanford CME295 lecture on transformer architecture explains that attention removes the sequential processing that older models had—tokens interact in parallel, not one after another. Position embeddings repair this loss by injecting a location signal directly into the data. The CME296 lecture on vision transformers emphasizes the same need: image patches sit in a 2D grid, and direct attention links erase that geometry unless position is explicitly encoded.

Common Misunderstanding

A common wrong belief is that the model "just knows" the order because tokens are listed in order in the input. The transformer architecture only receives numbers. Unless position is encoded into those numbers (as an embedding added to each token), the model has no mathematical access to order—it sees a set, not a sequence.

How to Recognize This in a New Paper or Model

When reading new papers, look for any mechanism that marks location: absolute position embeddings, relative position biases, rotary position embeddings (RoPE—a rotation-based position signal), ALiBi (attention-linear-biases—a distance penalty added during attention scoring), patch coordinate embeddings in vision models, or time embeddings in diffusion models. All are variations on the same idea: encode position as a numerical signal the model can use.

Connected Concepts

In CME295, position embeddings sit inside the transformer block, paired with attention and self-attention mechanisms. In CME296, diffusion models and vision transformers both add spatial or temporal position signals—diffusion uses timestep embeddings (which position in the noise-to-clean path), vision transformers use patch locations. In CS224R reinforcement learning, state representations often include position or location features to ground the agent in its environment. The shared principle across courses is that structure (order, space, time) must be explicit in the numbers if the model is to reason about it.
