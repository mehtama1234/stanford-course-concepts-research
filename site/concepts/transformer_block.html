Transformer Block

A repeating layer that lets information flow between positions, updates each position independently, and preserves old state while adding new updates.

What real-world problem is this about?

Imagine you're reading a long email on a phone screen that shows only one sentence at a time. You glance at "The bank is closed on Sundays." To understand "bank," you need to scroll back to see "The river ran past the old bank." But your brain is finite—you can't hold all context at once. You need a system that repeatedly focuses on relevant parts, updates your understanding, and carries important ideas forward to the next thought.

Why does this problem exist?

Understanding complex text or images requires multiple passes. On pass one, you might spot that "bank" appears near "river." On pass two, you notice grammar ties it to a verb. On pass three, you connect it to earlier context about geography. A single lookup doesn't build this layered meaning. You need a reusable recipe: focus on dependencies, reshape information based on that focus, preserve what you learned, and repeat. That's why layers stack.

What is the mathematical idea underneath?

A transformer block has four moving parts. First, multi-head attention mixes information: for each position, compute how similar it is to every other position (dot-product similarity, scaled by a constant to keep numbers stable), then use those similarity scores as weights to average all the information at those positions. The scaling prevents any single similarity from dominating. Second, a feed-forward network (a small nonlinear function applied to each position separately) reshapes the mixed information—like adding learned color to a grayscale image. Third, residual connections (adding the input to the output of each step) preserve old state so information doesn't wash away through layers. Fourth, layer normalization (centering and scaling activations) keeps numbers in a comfortable range, which makes training stable. These four pieces fit together: mix → reshape → carry old state → keep numbers sane.

Why is this concept important?

This structure scales. You can stack hundreds of blocks without training collapse because residual paths carry gradients backward and normalization prevents explosion. The same block pattern appears in language models, vision systems, and generative models. It's the universal recipe for depth.

What breaks without it?

Without attention, positions cannot learn dependencies—each token operates blind. Without the feed-forward network, the block cannot perform complex per-position transformations. Without residual connections, deep stacks degrade and gradients vanish during training. Without normalization, activations explode and training becomes chaotic.

Naive Starting Point

A beginner might think one attention layer solves understanding: compute which words matter to each other, then you're done. That handles one layer of relationships—"bank" might learn to focus on "river." But the model still hasn't integrated that insight into new features, prepared for the next layer, or preserved useful old information.

Why the Simple Approach Fails

A single attention layer lets positions learn what to focus on, but it doesn't reshape the information or prepare it for further layers. If you then stack more attention layers without residual paths or normalization, gradients shrink exponentially as they backpropagate through hundreds of multiplications. The model trains too slowly to learn. Without per-position reshaping (the feed-forward network), the model cannot extract complex patterns—it just averages neighbors.

The Mathematical Object

The thing you inspect and modify during training is the set of weight matrices inside the attention heads (how to compute similarity), the feed-forward weights (how to reshape), and the normalization parameters (learned scaling and centering). These weights accumulate the model's learned recipes for reading dependencies, transforming information, and scaling activations. During inference, these fixed weights operate on the input positions deterministically.

The Operation

Take the current state of all positions (their embeddings). Compute similarities between every pair of positions using attention. Use those similarities to create a weighted average of all information, done separately for each position and each attention head (a head is an independent copy of this process). Concatenate the outputs of all heads. Add the input back to preserve old state. Apply the feed-forward network to each position. Add the input again. Normalize the resulting activations. Pass the output to the next block.

Worked Mini-Example

Suppose three positions hold embeddings for "the river bank." Attention computes: position 2 ("river") has similarity score 0.7 to position 3 ("bank"), 0.3 to position 1 ("the"). Position 3 ("bank") has similarity 0.8 to position 2 ("river"), 0.2 to position 1 ("the"). After softmax (turning similarities into weights that sum to 1), position 2 outputs 0.7 × embedding[3] + 0.3 × embedding[1], a blend emphasizing "bank." Position 3 outputs 0.8 × embedding[2] + 0.2 × embedding[1], emphasizing "river." The feed-forward network then reshapes each position's embedding independently—for instance, position 3 might learn to activate features that mark "bank" as a noun when preceded by "river." Residual paths add back the original embeddings so information persists. Normalization scales the results. The block passes its output to the next block for another round.

What the Lectures Emphasize

The Stanford transformer lectures emphasize that a single block is not magic—it's a repeatable unit. The course builds from raw text through tokenization, embeddings, and then repeated transformer blocks. Each block performs the same steps: mix information across positions (attention), reshape each position (feed-forward), preserve old state (residuals), stabilize training (normalization). Stacking many blocks with these four pieces creates the depth that captures complex patterns. The block is not just attention; it's the complete unit that makes deep learning work.

Common Misunderstanding

Many beginners believe a transformer block is "just attention." In fact, attention is only one part—the communication step. The block also needs per-position reshaping (feed-forward), preservation of old information (residuals), and numerical stabilization (normalization). Attention tells you what to read; the feed-forward network tells you what to write; residuals prevent forgetting; normalization prevents numeric chaos. Remove any piece and training breaks.

How to Recognize This in a New Paper or Model

When reading papers, spot this pattern when a model alternates global mixing (attention or similar mechanisms that let distant positions interact) with local reshaping (nonlinear transformations per position), adds old state back (residual or skip connections), and repeats. It might be called an encoder block, decoder layer, DiT (diffusion transformer) block, ViT (vision transformer) block, or cross-attention block. The shared name varies, but the structure is the same: mix → reshape → preserve → stabilize → repeat.

Connected Concepts

In CME295 (Transformers/LLMs), the block is the core unit of language models. In CME296 (Diffusion/Vision), the same block architecture appears in vision transformers and diffusion transformers. In CS224R (Deep RL), sequence models trained on decision history use transformer or recurrent blocks to compress and plan. The unifying idea: composition (stacking simple units), feedback (attention or recurrence), and preservation (residuals or hidden state) enable learning from complex data.
