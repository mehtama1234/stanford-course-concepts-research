Model-Based Reinforcement Learning

Learning a model of what comes next so you can imagine futures before acting.

What real-world problem is this about?

You're teaching a friend to cook a new recipe. If they only learn by trial and error—actually making the dish, tasting it, adjusting—they waste ingredients and time. If they could imagine what the dish would taste like before they serve it, they'd waste far less.

Why does this problem exist?

In any uncertain world, acting blindly means you crash into mistakes. But if you can build a mental model of how the world responds to your actions, you can think ahead: 'If I do X, that leads to Y, which is bad.' Now you don't need to actually do X to learn that lesson.

What is the mathematical idea underneath?

A dynamics model is a function that takes two inputs—the current state (what the world looks like now) and an action (what you choose to do)—and outputs the next state (what the world will look like). Mathematically, it's usually written s_{t+1} = f(s_t, a_t) + noise, where s is state, a is action, f is the function the model learns, and the noise term (random uncertainty) accounts for the world's unpredictability. Planning then searches through imagined action sequences: 'If I pick a_1, then a_2, then a_3, what chain of states unfolds?' and picks the sequence leading to the best imagined outcome.

Why is this concept important?

With a model, you can learn from imagination—running thousands of simulated rollouts—instead of only from real expensive or risky tries. This lets you make decisions before facing the actual consequences, which is essential when real trials are costly (robot damage, medical treatment) or slow (weeks of waiting for results).

What breaks without it?

Without a model, you learn only from direct experience. Every mistake costs real time, money, or risk. You cannot think ahead because you have no way to imagine outcomes. You solve each new problem from scratch instead of transferring what you learned to related situations.

Naive Starting Point

A beginner might think: 'Just memorize which action is best in each situation I encounter.' But this fails immediately when the situation changes slightly or when there are more possible states than you can memorize.

Why the Simple Approach Fails

Pure memorization (a lookup table) breaks because the world has too many states. A robot hand has millions of possible positions; a game board has billions. You can't try them all, and you can't store an answer for each one. You need something that generalizes—a model that captures the underlying rules of how actions change the world.

The Mathematical Object

The concrete object is the dynamics model itself: a neural network or other learned function that maps (state, action) pairs to predicted next states. You can write it down, inspect it, feed it new inputs, and test whether it predicts correctly on held-out data.

The Operation

First, collect real experience (or start with one you already have). Second, use that experience to train a model that predicts the next state from the current state and action. Third, use the trained model to imagine futures: pick an action sequence and roll it forward through the model, simulating what would happen. Fourth, pick the action sequence that leads to the best imagined outcome. Fifth, execute that action in the real world and collect new data to improve the model further.

Worked Mini-Example

You're learning to parallel-park a car. Real learning would be: try, fail, adjust, try again, crash into the curb, adjust, finally succeed—many attempts. Model-based learning works differently. From a few real park attempts, you build a model: 'Turning the wheel this much, at this speed, moves the car that much sideways.' Now you can imagine 20 different steering sequences in your head (or on a simulator) without actually driving. You pick the sequence your model predicts will fit the car in the space. When you execute it in the real car, it works much better than random tries would have.

What the Lectures Emphasize

CS224R emphasizes that model-based RL answers two core questions: how do you learn a dynamics model from experience, and how do you then use that model for planning or data generation? The dexterous robot case study makes this concrete: real robot interactions are expensive (time, hardware wear), so planning with a learned model lets you generate millions of cheap imagined trials before you commit to a real robot move.

Common Misunderstanding

Many people think the learned model must be perfectly accurate to help. In reality, a slightly wrong model often beats no model at all. What matters is that the model captures the trends correctly enough for the planning horizon you care about. A model that says 'turning left moves the car left' is useful even if it's off by 10%; a model that says nothing is useless.

How to Recognize This in a New Paper or Model

In a paper or system, you're seeing model-based RL when: the agent learns or uses a learned model of state transitions; predictions of future states feed into planning or decision-making; simulated rollouts (fake experience generated by the model) are used to train a policy (a decision rule); or the system explicitly manages the trade-off between model accuracy and planning depth. The common thread is thinking ahead with a learned simulator.

Connected Concepts

Model-based RL appears across the three courses in different guises. In Deep RL, it contrasts with model-free learning (learning by pure experience). In Diffusion models, the generative process itself is a learned model of how to reverse randomness step by step—a different domain, same core idea of predicting sequences. In Transformers, attention mechanisms learn patterns in sequences; that learning is itself a lightweight model of which parts of the input matter for the output.
