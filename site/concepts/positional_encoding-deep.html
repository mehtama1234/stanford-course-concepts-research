Positional Encoding — why words need to know their place

Imagine reading a sentence where someone scrambled the word order: 'dog the man bites' instead of 'the man bites dog'. Attention (the mechanism that decides which words matter) compares words by their meaning alone, so it sees no difference between these two — they contain the same words, and to attention, that is all that exists. But meaning depends on order: 'dog bites man' and 'man bites dog' are opposites. Positional encoding solves this by giving each word an extra signal — its own learned vector — that changes based on where it sits in the sentence. Now the word 'bites' at position 2 is literally different from 'bites' at position 3. Here is the idea, the real cost of order when measured on GPT-2, why adding position works, where it hits limits, and why the search for better position schemes became a whole research field.

1 · The problem — attention is blind to order

Attention weighs words by their meaning: is this word relevant to that one? But meaning lives in order. If you shuffle the words in a sentence, the meaning often flips entirely — 'the bank denied the loan' vs 'the loan denied the bank' are near opposites. Yet to attention, which knows only how words relate to each other, a shuffled sentence looks identical to the original — the same words, the same meanings, are all present. The mechanism that decides what to read is blind to where to read it.

So the need is sharp: the model must be told not just what each word means, but where each word sits in the sequence.

2 · The reframe — attach a learned vector to each position and add it to the word

Here is the move. Before attention even runs, the model learns a separate vector (a short list of numbers, same length as each word's vector) for each position in the sequence. Position 1 gets its own vector, position 2 its own, and so on. Now, add this position vector directly to the word vector. So the word 'dog' at position 2 is now the sum of 'dog's meaning plus 'position 2's signal'. The word 'dog' at position 9 is the sum of 'dog's meaning plus 'position 9's signal'. They are now geometrically different, even though the word itself is the same.

When attention compares them, it sees distinct vectors and can tell them apart. Better yet, these learned position vectors come to embody something about relative distance — positions that sit close in the text develop similar vectors, so attention can learn to prefer nearby or distant words as the task demands. Nobody writes the pattern of position vectors; the model learns it. This is called positional encoding: each position gets its own learned signal, and the signal is added to the word.

3 · Seen on a real run — order is worth nearly a factor of two in loss

We ran the actual GPT-2 on a test set and measured how well it predicted the next word in two cases: words in their true order, and the same words shuffled randomly. The measure is loss — how surprised the model is by the right answer. Lower loss means the model was less confused; higher loss means it flailed.

The discovered fact: the same ten words in correct order yield loss 3.98, but shuffled they yield loss 8.00 — twice as bad. This gap measures how much meaning order carries. Without position, the model is nearly lost; with position telling it where each word is, it recovers most of the ground.

4 · Why adding position rescues meaning

The learned position vectors embody a key insight: neighbouring positions should be related. Look at GPT-2's learned position vectors — the cosine of neighbouring positions (the measure of how similar two vectors are) is 1.00, nearly identical. Positions far apart have cosine 0.39, much more distinct. This pattern is learned, not hand-written. It means 'next to each other in the text' is encoded as 'very similar vectors', so attention can learn rules like 'a noun often matters more to the adjective right next to it than to words ten places back'. The extra signal lets attention discover relative distance and use it. When order is erased, this signal vanishes and the model is left guessing from words alone — hence the collapse in performance.

5 · The one real weakness — fixed positions cap how long an input can be

The position vectors are learned only for positions 1, 2, 3, and so on up to some fixed maximum (in GPT-2, position 1024). If the input is longer than that, there is no vector for position 1025, and the model has never learned what to do. This is a hard ceiling on input length. Moreover, a model trained on sequences of length 1024 often generalizes poorly to longer sequences at test time — the position vectors for position 900 are not a reliable guide to position 1,500. This limitation drove a whole research field seeking better position schemes: relative positional attention (only the distance between words matters, not their absolute position), rotary encodings (positions are encoded as rotations in high-dimensional space, and longer sequences follow the same pattern), and learnable relative biases. Each scheme trades off different costs. But the core problem remains: the model must somehow know, at inference time, how to handle sequences longer than any it trained on.

6 · The surprise — the search for better positions is reshaping how long models can be

Every transformer needs positional encoding; it is not optional. But because the learned scheme in vanilla transformers caps input length and generalizes poorly, the hunt for better schemes is a high-stakes problem. Relative positional encodings, rotary position embeddings (RoPE), and alibi (attention with linear biases) all relax the length limit. Some models now handle context windows of 100,000 or even 1 million tokens — not because the core mechanism changed, but because researchers found ways to encode position that scale smoothly with distance and need not be learned for every position in advance. The vision transformer applies positional encoding to image patches instead of words; retrieval and search systems layer relative position on top of absolute, for the same reason: every system that joins many items in a sequence must solve the problem of 'how does position matter'. Position is not a minor detail; it is a central tension that drives how long a model can reach and how well it generalizes.
