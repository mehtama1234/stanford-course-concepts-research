Reward

A signal that says which outcomes should become more likely.

What real-world problem is this about?

The problem is that an agent needs to know not just what happened, but whether it was better or worse.

Why does this problem exist?

Learning from action needs a direction of improvement. Reward supplies that direction, even when the right action was not labeled in advance.

What is the mathematical idea underneath?

Return is accumulated reward over time. The key idea is to value actions by their downstream consequences, not only their immediate effect.

Why is this concept important?

It turns behavior into something trainable when direct answers are unavailable.

What breaks without it?

The agent can collect experience but has no preference over outcomes.

Naive Starting Point

Start with the simplest version: The problem is that an agent needs to know not just what happened, but whether it was better or worse. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because learning from action needs a direction of improvement. reward supplies that direction, even when the right action was not labeled in advance. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Reward: Return is accumulated reward over time. The key idea is to value actions by their downstream consequences, not only their immediate effect. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Reward, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: a base language model can finish sentences fluently, and an instruction-tuned model can answer the requested task, but a person may still dislike the tone, safety, or helpfulness of the response. The CME295 tuning lecture frames the third stage this way: after pretraining and supervised fine-tuning, preference tuning tries to align the model with human preferences or a metric. Reward is the compressed signal that says which behavior should become more likely. In CS224R, the same idea is broader: reward is how an action-taking system learns which outcomes it should prefer.

What the Lectures Emphasize

CME295 emphasizes reward through human preference alignment: the model already knows language and code, but now has to be shaped toward behavior people want. CS224R emphasizes reward as the central feedback signal for sequential decision making. The shared point is that reward is not the task itself; it is an imperfect handle for changing behavior.

Common Misunderstanding

A common misunderstanding is that reward is the same as the real goal. It is only a signal. If the signal rewards the wrong shortcut, the system can optimize the signal while violating the intended purpose. That is why preference tuning, reward modeling, and evaluation have to be treated together.

How to Recognize This in a New Paper or Model

In a new paper, recognize reward when outcomes, preferences, rankings, scores, or human judgments are converted into a number used to change behavior. The method may call it reward, preference signal, utility, advantage, verifier score, or metric, but the primitive is feedback: mark some futures as better so the learner can move toward them.

Connected Concepts

The same primitive reappears near reward modeling, credit assignment, policy gradient. Across the three courses, the shared pattern is feedback, credit: choose what to keep, how to move, what feedback means, or how to measure whether the behavior really improved.
