Reward

A number that tells a system which futures to make more likely.

What real-world problem is this about?

You're teaching a dog a new trick. The dog tries something. Did it help or hurt? Without knowing that, the dog can't learn which behaviors to repeat. You need a way to say "yes, that was better" or "no, try again."

Why does this problem exist?

Any learning system facing a choice needs to know which choice worked. Reward is the answer to that question—a number that marks outcomes as better or worse. Without it, the system collects experience but has no direction to improve.

What is the mathematical idea underneath?

Reward usually measures a single step. Return (often written R) sums rewards across multiple steps into one total. To value an action fairly, look at all the downstream consequences, not just the immediate result. A detour might cost you now but save you later. The formula R = r₀ + r₁ + r₂ + ... adds up each step's reward (rₜ) forward in time. Often future rewards matter less than immediate ones—a coffee today beats a coffee a year from now—so we discount: R = r₀ + γ·r₁ + γ²·r₂ + ..., where γ (gamma, between 0 and 1) shrinks distant rewards. This forces the system to prioritize.

Why is this concept important?

Reward turns a vague preference ("better") into something the system can optimize. Once you have a number for each action's outcome, you can ask: which actions led to higher numbers? Do more of those. This unlocks learning without showing the system the answer in advance.

What breaks without it?

Without reward, the system has experience but no preference. It sees actions and outcomes but cannot distinguish good from bad. It may as well pick randomly. Learning requires a feedback signal; reward is that signal.

Naive Starting Point

A beginner sees a simple world—a small set of situations, each paired with a known best move—and thinks: just memorize the answer. A lookup table ("if situation A, do move B") works when every case is small and labeled.

Why the Simple Approach Fails

The lookup table breaks the moment you face a new situation, or when actions have delayed effects. If a good move only pays off much later, a single-step lookup table never catches it. If the world is large or changing, you can't pre-label every case. You need to learn from experience, not memorize.

The Mathematical Object

The reward function r(state, action) is a procedure you can write down and test. Given a situation and a move, it outputs a number. In practice, reward might come from a human ranking two responses ("I prefer A over B"), a test score, a metric you measure, or a small learned model trained to predict human preference. The key is that it's concrete: you can inspect it, trace it, ask why it gave that number.

The Operation

Step 1: Agent acts (chooses a move given its current situation). Step 2: System delivers a reward signal (a number, or a comparison). Step 3: Agent looks back at its action and the reward it got. Step 4: Agent adjusts—increasing the likelihood of actions that led to high rewards. Repeat.

Worked Mini-Example

A language model is asked to write a grocery list. It outputs: "milk, eggs, bread." A second model outputs: "milk, eggs, bread, butter, cheese, yogurt." A human rater scores them on usefulness and concision: first gets 8/10 (complete but brief), second gets 6/10 (thorough but wasteful). The reward for each response is the score. Now the training process can ask: which action (which list) led to higher reward? The model learns that shorter, focused lists get higher marks. If we train on many examples, the model shifts to produce better lists.

What the Lectures Emphasize

In CME295, reward appears in preference tuning: after pretraining and task training, the model must align with what humans prefer. The lecturer frames it as a third stage—not "solve the task" but "solve it the way humans like." In CS224R, reward is the core signal for sequential decision-making in reinforcement learning. Both courses agree: reward is not the goal itself; it's an imperfect handle for steering behavior toward what we care about.

Common Misunderstanding

Many people think reward equals the goal. It doesn't. Reward is a proxy for the goal. If you reward a system for speed, it might rush and make mistakes. If you reward a language model for length, it will ramble. A misaligned reward signal can make the system optimize something unintended while ignoring what you actually wanted. That's why reward design, monitoring, and alignment are serious problems in practice.

How to Recognize This in a New Paper or Model

In papers and systems, reward appears under many names: preference signal, utility, score, ranking, or verifier output. Look for this pattern: outcomes are compared or ranked, and that comparison is converted into a number, which then drives learning. A paper that says "we train a model to rank responses" or "we use human feedback to score outputs" is using reward, even if it doesn't say that word.

Connected Concepts

In CME295, reward links to preference alignment and fine-tuning: how do we steer a model toward behavior humans prefer? In CS224R, reward is the foundation of value functions and policy gradients: how does an agent learn which actions are good? In CME296, reward appears indirectly in diffusion model guidance: steering generation toward a desired outcome. The thread across all three is feedback—deciding what's better and moving toward it.
