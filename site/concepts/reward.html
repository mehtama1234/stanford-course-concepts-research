Reward

A number you assign to an action or outcome that tells a learning system "this was good" or "this was bad." The system uses this number to learn which choices to make again.

What real-world problem is this about?

You are teaching a dog to sit. The dog hears "sit" and tries something—maybe it crouches, maybe it stays still, maybe it jumps. If you only say "good" or "no," the dog doesn't know why. To learn, the dog needs immediate feedback: a treat right when it crouches (that was good), nothing when it jumps (that was not good). Without this feedback, the dog cannot tell which behavior caused the reward.

Why does this problem exist?

Learning requires two things: trying different actions and knowing which worked. A system that tries actions but never gets told "that worked well" or "that didn't" has no way to know which ones to repeat. Reward fills that gap—it is the number that says "this action led to something I value." Everything in learning hinges on this signal: without it, a system is blind.

What is the mathematical idea underneath?

One reward number per step tells you only how good that single moment was. But real choices have ripple effects: a small choice now might lead to big consequences later. To measure how good a choice truly is, you add up rewards from that moment forward. If step 1 gets a reward of 2, step 2 gets a reward of 5, and step 3 gets a reward of 1, then the total value of choosing in step 1 is 2 + 5 + 1 = 8. But future rewards matter less than immediate ones—a reward today is more valuable than a reward a year from now. So we shrink the rewards as they get further away: Total = 2 + 0.9 × 5 + 0.81 × 1. We use a multiplier (often written γ, the Greek letter gamma) between 0 and 1 that shrinks each future reward more than the last. This forces the system to care about what happens now, not just the distant future.

Why is this concept important?

Without reward, you can only tell a system what to do, not how to improve. With reward, you can ask "which actions led to higher numbers?" and the system can learn to repeat them. This transforms learning from memorization into genuine adaptation. The system builds its own strategy by chasing the reward signal.

What breaks without it?

A system given tasks but no feedback signal has no way to know if it is improving. It might try millions of actions, but it sees no difference between a good one and a bad one. It cannot learn because learning requires knowing what worked. Reward is the only thing that connects an action to whether it was useful.

Naive Starting Point

A beginner looks at a simple world and thinks: I can memorize it. If there are only 10 situations and each one has one correct answer, I can build a table: "When you see situation A, always do move B." This works if the world is tiny, fixed, and fully labeled in advance.

Why the Simple Approach Fails

Memorization fails the moment the world grows or changes. You cannot memorize every situation if there are millions of them. You cannot memorize an answer to a question you have never seen. And if a good action only pays off much later—like investing money that returns profit years later—a memorized single-step table will never capture it. Reward lets you learn the pattern: actions that led to high numbers in the past. That learned pattern works on new situations it has never seen before.

The Mathematical Object

A reward function is a concrete rule you can write down. It takes two inputs—what situation you are in and what action you just did—and outputs a number. That number might come from different sources: a human who read your output and scores it on a scale of 1 to 10, an automatic test that checks if you solved a problem, a measurement of how fast something ran, or a small trained program that learned to predict what humans would like. The key is that you can always run the function, check its output, and ask why it gave that number.

The Operation

Step 1: The system chooses an action based on its current situation. Step 2: The system gets a reward—a number—that measures how good that action was. Step 3: The system looks back at what it did and what reward it received. Step 4: The system adjusts itself to make choices that led to high rewards more likely in the future, and choices that led to low rewards less likely. Step 5: Repeat with a new situation and action. Over many repetitions, the system learns which kinds of actions tend to earn high rewards.

Worked Mini-Example

A language model is asked to write a grocery list. It outputs: "milk, eggs, bread." Another model outputs: "milk, eggs, bread, butter, cheese, yogurt." A human rater scores them: the first list is short and complete, earning a score of 8 out of 10; the second list is long and thorough but repetitive, earning a score of 6 out of 10. These scores are the rewards. The training process now asks: which choice—which list—earned a higher reward? The model learns that short, focused lists get higher marks. If you train it on hundreds of examples like this, the model gradually shifts to writing shorter lists, because those actions earned higher rewards.

What the Lectures Emphasize

In CME295, reward becomes important when a model is already trained on tasks but must now match human taste. The lecturer describes it as a separate step: first you teach the model to solve a task, then you teach it to solve the task in the way humans prefer. This is called alignment, and reward is the signal that makes it possible. In CS224R, reward is the core ingredient: an agent faces choices, and reward tells it which choices led to good outcomes. The agent builds a strategy by chasing high rewards. Both courses agree that reward is essential but imperfect—it is the tool we use to steer systems toward what matters to us.

Common Misunderstanding

Many people think the reward signal automatically captures what you want. It does not. Reward is a number you design, and a poorly designed number will push the system in the wrong direction. If you reward a system for being fast, it will rush and give bad answers. If you reward a language model by its length, it will produce long rambling text. The system does exactly what the reward number incentivizes—even if that is not what you actually wanted. Fixing these mismatches is a serious and ongoing problem in AI: designing a reward that truly points toward the goal you care about.

How to Recognize This in a New Paper or Model

In papers and systems, this concept appears under different names: preference signal (a comparison of which output you like better), utility (a score of how good something is), score (a number assigned to an action), ranking (putting outcomes in order from best to worst), or verifier output (a small model that judges outputs). Look for patterns: are outcomes being compared or ranked? Is that comparison being turned into a number? Does that number drive learning or guide a choice? If yes, then reward—or something equivalent—is at work, whether the paper names it that way or not.

Connected Concepts

CME295 links reward to alignment: how do we teach a model the outcome humans prefer? CS224R links reward to strategy-learning: how does an agent learn which actions are good in the long run? CME296 uses reward indirectly in diffusion models: you can guide generation toward a desired outcome by rewarding certain properties. Across all three courses, the idea is the same: feedback—you decide what is better, and the system learns to move toward it.
