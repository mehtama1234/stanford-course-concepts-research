Evaluation

A controlled way to ask what a model can and cannot do.

What real-world problem is this about?

The problem is that a model can look impressive on examples while failing in places the test did not cover.

Why does this problem exist?

Measurement is sampling. Any score reflects the cases, rules, and incentives used to produce it.

What is the mathematical idea underneath?

A metric maps many behaviors to one number or table. The lost detail is as important as the reported score.

Why is this concept important?

It decides what work is rewarded, what systems ship, and which failures stay hidden.

What breaks without it?

Claims about capability become anecdotes, and progress can be confused with overfitting to a benchmark.

Naive Starting Point

Start with the simplest version: The problem is that a model can look impressive on examples while failing in places the test did not cover. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because measurement is sampling. any score reflects the cases, rules, and incentives used to produce it. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Evaluation: A metric maps many behaviors to one number or table. The lost detail is as important as the reported score. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Evaluation, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: two chatbots both sound fluent, but one fails math, one invents citations, and one follows instructions only on short prompts. Without evaluation, those differences remain anecdotes. CME295 opens the evaluation lecture by saying that if we do not know how to measure LLM performance, we do not know what to improve. CME296 makes the same point for images: a generated picture can be aesthetic but fail prompt adherence.

What the Lectures Emphasize

The evaluation lectures emphasize measurement as a development tool. CME295 focuses on quantifying LLM behavior across cases after studying agents and RAG. CME296 separates image quality from prompt adherence. Together they show that evaluation is not one number; it is a set of probes aimed at different failure modes.

Common Misunderstanding

A common misunderstanding is that a benchmark score is the capability. A score is a compressed measurement under chosen rules. It can miss distribution shift, hidden failure modes, reward hacking, prompt sensitivity, or tasks the benchmark never sampled.

How to Recognize This in a New Paper or Model

In a new paper, recognize evaluation whenever authors turn behavior into metrics, benchmarks, human judgments, failure slices, or ablation tests. The shared primitive is measurement with loss: every score reveals something and hides something.

Connected Concepts

The same primitive reappears near generalization, reward modeling, scaling laws. Across the three courses, the shared pattern is uncertainty, feedback: choose what to keep, how to move, what feedback means, or how to measure whether the behavior really improved.
