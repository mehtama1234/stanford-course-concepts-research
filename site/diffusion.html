Diffusion Lecture Guide

This page reads the course lecture by lecture from the local transcripts. Each section teaches the problem, method, examples, and math moves directly, without lecture-summary filler.

Course Spine

Diffusion and flow models study how to generate structured visual data by moving from something simple to something complex. The course keeps returning to six facts: direct generation is too hard, local directions are learnable, representation changes cost, guidance changes control, architecture changes what information can be used, and evaluation must check several kinds of failure.

Big Picture From First Principles

Start with one ordinary fact: a realistic image is too many choices to make all at once. The model needs a path. Diffusion, score matching, flow matching, latent spaces, guidance, architectures, training, and evaluation are different answers to the same pressure: how do we move from something easy, like random noise, into something structured, like a useful image?

The course keeps rebuilding one loop. Pick a representation, choose a path through that representation, learn the local direction of improvement, follow that direction to make samples, and then check whether the result is realistic, controlled, diverse, and useful.

Generation Needs A Path

Noise is easy to sample and images are hard to sample. The core problem is learning a reliable route between them.

Small Moves Beat One Leap

Diffusion breaks image generation into many cleanup steps, each easier to learn than the full image at once.

Direction Can Replace Probability

Score matching learns which way a noisy point should move without writing down the full data probability.

Flow Means Learned Motion

Flow matching learns arrows that carry simple samples toward data-like samples.

Compression Saves Work

Latent spaces let the model work in a smaller code where important structure remains but raw pixel cost drops.

Guidance Adds Control

A generated image must often obey a prompt or condition, so the sampling direction needs a steering signal.

Architecture Carries Information

The network must combine local detail, global layout, time, and conditions at every update.

Evaluation Has Many Axes

A sample can look good, ignore the prompt, copy data, or fail rare cases, so one score is not enough.

How The Ideas Build

  1. Lectures 1-3: build the three main generation views: denoise step by step, follow score directions, and follow a learned flow.
  2. Lecture 4: adds practical control and cheaper computation through latent spaces and guidance.
  3. Lectures 5-6: turn the ideas into trainable systems: architecture, time inputs, conditioning, losses, schedules, and scale.
  4. Lecture 7: asks how to judge outputs when realism, prompt following, safety, diversity, and usefulness disagree.
  5. Lecture 8: frames new papers by the bottleneck they attack: speed, video, 3D, control, consistency, or evaluation.

Lecture 1

Lecture 1 - Diffusion

Open video

1h 46m · 12646 transcript words

Detailed Topic Explanation

Diffusion starts with a plain trick: make the hard direction easy by first doing the opposite. Take a clean image and add a little noise. Add more noise. Keep going until the image becomes almost pure static. That forward path is easy because we choose the noise. The learning problem is the reverse path: given a noisy image and the current noise level, predict how to clean it a little. Generation then starts from random noise and repeats many small cleanup steps until structure appears.

The reason this works is not magic. A model does not have to invent the whole image at once. At each step it only answers a smaller question: what part of this current picture looks like noise, and what should be kept as signal? Early steps recover rough layout because only broad structure can be trusted. Later steps sharpen edges, texture, and local detail. The price is speed, because many steps are needed. The gain is stable training, because the model gets a clear supervised target: the exact noise that was added.

Core Ideas

  • The forward process corrupts real data with known noise, so training examples can be made without human labels.
  • The reverse process learns many small denoising moves instead of one giant generation jump.
  • A time or noise-level input matters because cleaning a nearly random image is different from cleaning a nearly finished image.
  • Sampling is an iterative loop: start from noise, predict noise, remove some of it, and repeat.

Approaches Taught

DDPM-style denoising

Problem
Directly turning random noise into a clean image is too hard as one step.
How It Works
Add known noise to real images during training, then train a model to predict and remove that noise at many noise levels.
Why It Matters
It turns generation into many small supervised cleanup problems with clear targets.
Where It Breaks
Sampling can be slow, and errors at early high-noise steps can shape the whole output badly.

Noise scheduling

Problem
The model needs to learn every stage between clean data and pure noise.
How It Works
Choose how much noise is added at each time step so training covers light, medium, and heavy corruption.
Why It Matters
The schedule decides which denoising stages the model practices and how hard each stage is.
Where It Breaks
A poor schedule can make some stages too easy, too hard, or undertrained.

Examples Used

  • A clean image of a face slowly becomes static when Gaussian noise is repeatedly mixed into the pixels.
  • At generation time, static slowly becomes a face, an object, or a scene because each step removes a predicted piece of noise.
  • The same idea can apply outside images whenever data can be corrupted and then gradually repaired.

Equations And Algorithm Moves

  • Choose a noise schedule beta_t that says how much noise is added at each step.
  • Sample a clean data point x_0, a time t, and random noise epsilon.
  • Construct x_t, the noisy version of x_0 at time t.
  • Train epsilon_theta(x_t, t) to predict the noise epsilon with a squared-error loss.
  • At sampling time, start from x_T sampled from noise and repeatedly estimate x_{t-1} from x_t and the predicted noise.

What You Should Be Able To Say

You should be able to explain diffusion as learning to undo a known corruption process one small step at a time, rather than producing a whole image in one leap.

Lecture 2

Lecture 2 - Score matching

Open video

1h 48m · 12725 transcript words

Detailed Topic Explanation

Score matching changes the question. Instead of asking for the probability of an image, it asks for the direction that would make a noisy point more data-like. Think of standing on a foggy landscape where high ground means high data probability. You may not know the height of every point, but you can learn which way is uphill. The score is that uphill direction: the gradient of log probability. A score model learns this direction at many noise levels.

This matters because generation can be framed as following directions. If a noisy image is in a low-probability region, the score tells the model how to move it toward regions where real images live. Denoising score matching makes the abstract score trainable: add known noise to clean data, then train the model to point back toward the clean data. The model is not memorizing images. It is learning local directions in the space of possible images. The danger is that local directions can be wrong far from the training distribution, and small errors can accumulate during sampling.

Core Ideas

  • The score is a direction field, not a probability table.
  • Denoising turns score learning into a supervised problem with known noisy-clean pairs.
  • Different noise levels need different score estimates because the data shape changes as noise increases.
  • Sampling follows the learned directions, often with extra noise or an ODE/SDE-style update.

Approaches Taught

Score matching

Problem
The full data probability is hard to know, but local directions toward data can be learned.
How It Works
Train a model to predict the gradient of log probability, which points toward more data-like regions.
Why It Matters
It lets sampling move by following local directions instead of evaluating the whole distribution.
Where It Breaks
Wrong local directions can accumulate during sampling and push samples into bad regions.

Denoising score matching

Problem
The score of clean data is hard to supervise directly.
How It Works
Add known noise to clean data and train the model to point from noisy samples back toward the clean-data structure.
Why It Matters
It converts an abstract probability-gradient idea into a practical training loss.
Where It Breaks
If the denoising setup does not cover the right noise levels, the sampler lacks reliable directions.

Examples Used

  • A blurry or noisy image can be nudged toward a cleaner image by following local directions.
  • A point cloud shaped like a ring can be sampled by learning arrows that point back toward the ring.
  • A probability landscape can be navigated by slope even if its absolute height is unknown.

Equations And Algorithm Moves

  • Define the score as grad_x log p_t(x), the direction in x that increases log probability at noise level t.
  • Corrupt clean samples with known Gaussian noise to obtain x_t.
  • Train s_theta(x_t, t) to match the denoising direction implied by the corruption process.
  • Use Langevin, reverse SDE, or probability-flow updates to move samples according to the learned score.
  • Treat diffusion noise prediction and score prediction as closely related parameterizations.

What You Should Be Able To Say

You should be able to say that score matching learns which way to move a noisy sample so it becomes more like real data, without needing to know the full probability value.

Lecture 3

Lecture 3 - Flow matching

Open video

1h 47m · 12595 transcript words

Detailed Topic Explanation

Flow matching treats generation as movement. Start with a simple distribution, such as Gaussian noise. End with the data distribution, such as real images. Now imagine a path between them. At every time and every location on the path, the model learns an arrow: move this way at this speed. That arrow is a velocity field. Sampling means starting from noise and following the learned arrows until the sample reaches the data side. The model is therefore not mainly guessing pixels; it is learning motion instructions for points in a high-dimensional space.

The advantage is that the training target can be direct. If you choose how to pair or interpolate between noise and data, you know the desired velocity along that path. The model can be trained with an ordinary squared-error loss to predict that velocity. This makes flow matching feel cleaner than thinking only in terms of adding and removing noise. The risk is that the chosen path matters. A path that is easy to train may not give the best samples, and numerical solvers can introduce error if the learned field is rough or if too few steps are used.

Core Ideas

  • A velocity field is a map of arrows telling a sample where to move next.
  • Flow matching learns the path from a simple starting distribution to the data distribution.
  • The training loss can be a direct regression loss on velocities.
  • Sampling solves an ordinary differential equation by repeatedly stepping along the learned arrows.

Approaches Taught

Flow matching

Problem
Generation needs a smooth route from a simple distribution to the data distribution.
How It Works
Train a model to predict a velocity field that tells each sample where to move at each time.
Why It Matters
It frames generation as following learned arrows, often with a simple squared-error loss.
Where It Breaks
Bad path choices or rough velocity fields can make sampling unstable or low quality.

ODE sampling

Problem
A learned velocity field must be turned into an actual sample.
How It Works
Start from noise and numerically integrate the equation dx/dt = v_theta(x,t) with small time steps.
Why It Matters
It gives a direct procedure for using the learned field to generate data.
Where It Breaks
Too few solver steps can be fast but inaccurate; too many steps can be expensive.

Examples Used

  • A cloud of random points can be moved into the shape of a two-dimensional data curve by following learned arrows.
  • An image sample can begin as noise and be transported into an image-like latent or pixel state.
  • A navigation map with arrows at each location gives the everyday picture of a vector field.

Equations And Algorithm Moves

  • Choose a path x_t between a simple sample x_0 and a data sample x_1.
  • Compute or define the target velocity u_t for that path.
  • Train v_theta(x_t, t) to match u_t with an L2 loss.
  • Generate by starting from x_0 and integrating dx/dt = v_theta(x, t).
  • Trade sample quality, compute, and stability through solver step count and path design.

What You Should Be Able To Say

You should be able to explain flow matching as learning arrows that carry noise into data, then generating by following those arrows.

Lecture 4

Lecture 4 - Latent Space & Guidance

Open video

1h 40m · 12358 transcript words

Detailed Topic Explanation

Latent-space generation and guidance solve two practical problems. Latent space is a compressed working space. Instead of denoising every pixel directly, an encoder turns an image into a smaller code, the generator works on that code, and a decoder turns the code back into an image. Guidance solves the steering problem. A user may ask for a red car, a medical image with a certain property, or a picture matching text. The model must not only make something realistic; it must make the requested thing.

The first principle is separation of jobs. Compression handles cost: generate in a smaller space where important structure remains but redundant pixel detail is reduced. Guidance handles control: change the sampling direction so the path is pulled toward the condition. Classifier-free guidance does this by comparing a conditional prediction with a less-conditioned prediction and pushing more strongly toward the condition. The failure modes are also plain. Too much compression loses detail. Too much guidance can overfit the prompt, create artifacts, reduce variety, or make images look forced.

Core Ideas

  • Latent space makes generation cheaper by working on compact codes instead of raw pixels.
  • Guidance changes the sampling direction so the output follows a condition.
  • Classifier-free guidance uses the difference between conditional and unconditional predictions as a steering signal.
  • Control and realism are separate goals, and improving one can hurt the other.

Approaches Taught

Latent diffusion

Problem
Running diffusion in full pixel space is expensive.
How It Works
Compress images into latent codes, run generation in that smaller space, then decode the result back to pixels.
Why It Matters
It reduces compute while keeping enough structure for high-quality images.
Where It Breaks
Compression can discard details or create decoder artifacts that generation cannot recover.

Classifier-free guidance

Problem
The model must make outputs that match a condition, not only outputs that look realistic.
How It Works
Compare conditional and unconditional predictions, then push the sampling update more strongly toward the condition.
Why It Matters
It gives a simple control knob for prompt following and conditional generation.
Where It Breaks
High guidance can reduce diversity, exaggerate features, or create unnatural artifacts.

Examples Used

  • Text-to-image generation uses a text prompt as the condition.
  • Latent diffusion generates inside a compressed image code before decoding to pixels.
  • Increasing guidance weight can make an image match the prompt more strongly while making it less natural.

Equations And Algorithm Moves

  • Encode an image x into a latent code z, generate or denoise z, then decode z back into x.
  • Train or run a conditional model that receives both the noisy sample and the condition c.
  • For classifier-free guidance, combine conditional and unconditional predictions.
  • Use a guidance scale to control how strongly the condition changes the update direction.
  • Evaluate both instruction-following and visual quality because they can diverge.

What You Should Be Able To Say

You should be able to say that latent space reduces the cost of generation, while guidance steers the sample toward a requested condition.

Lecture 5

Lecture 5 - Architectures

Open video

1h 46m · 13529 transcript words

Detailed Topic Explanation

Architecture is the body that carries the diffusion or flow idea. The training objective may say predict noise or velocity, but a real model still needs layers that can process images, time steps, text, and conditioning signals. U-Nets became useful because they combine local image processing with skip connections that preserve detail. Diffusion transformers become useful because attention can compare many parts of the image or latent grid and mix information globally. The architecture decides what the model can see when it predicts the next correction.

The first-principles question is what information must be available at each update. A denoising step needs local texture, larger object layout, the current noise level, and the prompt or condition. Convolutions are good at nearby structure. Attention is good at long-range relationships and conditioning. Time embeddings tell the network what stage of cleanup it is in. Cross-attention lets text or other conditions influence visual features. Architecture fails when it cannot carry the right information: details wash out, global layout breaks, conditioning is ignored, or memory cost becomes too high.

Core Ideas

  • The loss defines what to predict, but the architecture defines what information can be used to make that prediction.
  • U-Net skip connections help preserve fine detail while still allowing broad context.
  • Transformer blocks and attention let distant image regions and conditioning tokens interact.
  • Time and condition embeddings are necessary because the same noisy image can need different updates at different stages or prompts.

Approaches Taught

U-Net denoising architecture

Problem
The model must combine local image detail with broad context during denoising.
How It Works
Use an encoder-decoder image network with skip connections that carry fine spatial detail across scales.
Why It Matters
It preserves detail while still allowing the model to reason about larger structure.
Where It Breaks
It can struggle with global relationships and can become heavy at large image sizes.

Diffusion transformer

Problem
Large visual generators need global mixing and flexible conditioning.
How It Works
Represent images or latents as patches and use attention blocks conditioned on time and prompts.
Why It Matters
Attention lets distant regions and text conditions interact during each update.
Where It Breaks
Memory and compute can grow quickly, and weak conditioning design can make the prompt ignored.

Examples Used

  • A U-Net can preserve edge detail by passing high-resolution features around the bottleneck.
  • A diffusion transformer can let one image patch attend to another distant patch.
  • Text conditioning can enter through cross-attention so visual features know which words matter.

Equations And Algorithm Moves

  • Represent the noisy image or latent as spatial features or patches.
  • Embed the time step t and inject it into the network layers.
  • Use convolution, attention, or transformer blocks to compute the noise or velocity prediction.
  • Use cross-attention or conditioning embeddings to inject text or other controls.
  • Balance model size, memory, receptive field, and sampling cost.

What You Should Be Able To Say

You should be able to explain that diffusion architecture is not decorative: it determines whether the model can combine local detail, global layout, time, and conditioning.

Lecture 6

Lecture 6 - Model Training

Open video

1h 40m · 12382 transcript words

Detailed Topic Explanation

Model training is where the clean idea meets engineering reality. The model needs many image-condition examples, a corruption or path rule, a prediction target, and a loss. Each training step samples data, samples a time or noise level, constructs the corrupted state, asks the model for a prediction, measures the error, and updates the weights. This simple loop hides important choices: data quality, caption quality, noise schedule, batch size, optimizer, precision, architecture scale, and whether the target is noise, clean data, score, or velocity.

The first-principles issue is that the model only learns from the errors we show it. If the data is low quality, the model learns low-quality patterns. If captions are weak, text control is weak. If some noise levels are undertrained, sampling breaks at those stages. If the loss rewards an easy average answer, fine detail may suffer. Training also connects to sampling speed: distillation and consistency-style ideas try to reduce the number of steps needed at generation time by training a model to make larger reliable moves.

Core Ideas

  • Training repeatedly creates noisy or intermediate states from real data and asks the model to predict the right correction.
  • The prediction target can be noise, clean data, score, velocity, or another equivalent parameterization.
  • Data and conditioning quality directly limit what the model can learn.
  • Fast sampling methods try to train models that need fewer reverse steps.

Approaches Taught

Time-sampled training

Problem
The model must learn corrections for all stages of generation.
How It Works
Randomly sample a time or noise level for each training example and train the model on that stage.
Why It Matters
It spreads training across early rough-structure steps and later detail-refinement steps.
Where It Breaks
Uneven time sampling can leave important parts of the generation path weak.

Sampler distillation

Problem
Many-step sampling is too slow for some uses.
How It Works
Train a new model or sampler to imitate the result of many cleanup steps using fewer larger steps.
Why It Matters
It can make generation faster enough for interactive products or large-scale use.
Where It Breaks
Fewer steps can lose detail, diversity, or prompt accuracy if the large moves are not reliable.

Examples Used

  • A captioned image pair teaches the model both visual structure and text control.
  • A model trained poorly at high noise levels may never recover good global structure.
  • A distilled sampler tries to replace many small cleanup steps with fewer larger ones.

Equations And Algorithm Moves

  • Sample a data item and condition c from the training set.
  • Sample a time t and construct x_t using the chosen corruption or path rule.
  • Run the model f_theta(x_t, t, c).
  • Compute a loss against the chosen target, such as epsilon, x_0, score, or velocity.
  • Update theta with gradient descent and monitor validation behavior across time levels.

What You Should Be Able To Say

You should be able to describe training as repeatedly making a known corrupted state and teaching the model the correction it should predict.

Lecture 7

Lecture 7 - Evaluation

Open video

1h 41m · 12691 transcript words

Detailed Topic Explanation

Evaluation asks what it means for a generator to be good. A model can make sharp images that ignore the prompt. It can follow the prompt but look unnatural. It can score well on a metric while failing for people. It can work on common requests and fail on rare ones. So evaluation needs several checks: visual quality, diversity, prompt alignment, factual or spatial correctness, safety, bias, memorization, and task-specific usefulness. The key point is that an image generator is not one skill; it is a bundle of skills that can improve or fail separately.

The first-principles point is that generation has many goals at once. There is no single number that fully measures an image generator. Distribution metrics ask whether generated samples resemble real samples in aggregate. Human preference asks whether people like or trust the outputs. Prompt-alignment tests ask whether the requested objects, relations, counts, and styles appear. Stress tests ask where the model breaks. Evaluation fails when the metric becomes the target: the model can improve the number while getting worse at the actual use case.

Core Ideas

  • Visual quality and instruction following are different measurements.
  • Distribution-level scores can miss individual failures that matter to users.
  • Human preference is useful but noisy, costly, and sensitive to the evaluation setup.
  • Good evaluation includes failure slices, not only average scores.

Approaches Taught

Distribution-level evaluation

Problem
A generator should match the broad statistics of real data, not only produce one good example.
How It Works
Compare generated and real samples using feature statistics or similar aggregate measurements.
Why It Matters
It gives a scalable signal for overall realism and coverage.
Where It Breaks
Aggregate scores can hide prompt failures, safety failures, and bad rare cases.

Prompt-alignment evaluation

Problem
A realistic image is still wrong if it does not obey the request.
How It Works
Check whether objects, counts, relations, styles, and constraints from the prompt appear in the output.
Why It Matters
It measures whether the model is controllable, not just visually plausible.
Where It Breaks
Automatic alignment checks can miss subtle errors or reward superficial keyword matching.

Examples Used

  • A prompt asks for two dogs and one red ball, but the image contains one dog and two balls.
  • An image looks realistic at first glance but has broken hands, text, or object relations.
  • A model can produce diverse images overall while failing badly for a specific user group or domain.

Equations And Algorithm Moves

  • Use distribution metrics such as FID-style scores to compare generated and real feature statistics.
  • Use alignment metrics or human checks for prompt following.
  • Slice evaluation by object type, count, relation, style, demographic attribute, and safety category.
  • Check diversity and memorization separately from image quality.
  • Treat metrics as evidence, not as the definition of success.

What You Should Be Able To Say

You should be able to explain why evaluating image generators requires several tests, because realism, prompt following, diversity, safety, and usefulness can disagree.

Detailed Topic Explanation

Trending topics are not random add-ons. They are attempts to fix the main limits of diffusion and flow systems. Sampling can be slow, so researchers build faster solvers, distillation methods, and consistency-style models. Images are not enough, so the same ideas move into video, 3D, robotics, and multimodal generation. User control is still imperfect, so new conditioning and guidance methods try to make outputs obey structure, layout, motion, identity, and style. The best way to read new work is to ask which bottleneck it attacks and what it gives up to do that.

The first-principles map stays the same: start from a simple state, move through a learned path, and end with structured data. New work changes one part of that map. Some papers change the path so fewer steps are needed. Some change the data type from image to video or 3D. Some change the condition signal so the user can control layout, camera, motion, or identity. Some change evaluation because new outputs introduce new failure modes. The danger is hype: a method may be faster but worse, more controllable but less diverse, or impressive in demos but weak under systematic tests.

Core Ideas

  • Most new diffusion and flow work changes speed, control, data type, architecture, or evaluation.
  • Video and 3D generation add consistency problems across time, view, geometry, and motion.
  • Distillation and consistency methods try to reduce the number of sampling steps.
  • Better control often trades against diversity, realism, or compute cost.

Approaches Taught

Fast generation methods

Problem
High-quality diffusion and flow models can require too many sampling steps.
How It Works
Change the solver, train a distilled model, or use consistency-style objectives so fewer updates are needed.
Why It Matters
Speed decides whether the model can be used interactively or at large scale.
Where It Breaks
Speedups can trade away detail, diversity, stability, or prompt following.

Video and 3D generative extensions

Problem
Images alone do not handle time, motion, geometry, or viewpoint consistency.
How It Works
Extend the generation path so samples remain coherent across frames, camera views, or 3D structure.
Why It Matters
It moves the same generation principles into richer outputs people actually want.
Where It Breaks
Each new dimension adds consistency failures: flicker in video, broken geometry in 3D, or unstable identity across views.

Examples Used

  • A video generator must keep the same object identity across frames, not just make each frame look good.
  • A 3D generator must make views agree about shape, not only render one plausible picture.
  • A fast sampler may generate in a few steps but lose detail or diversity compared with a slower sampler.

Equations And Algorithm Moves

  • Classify a new method by the part it changes: path, solver, architecture, condition, data type, or metric.
  • For speed methods, compare step count against quality and alignment.
  • For video or 3D methods, add consistency checks across time or viewpoint.
  • For control methods, measure both obedience to the condition and damage to realism or diversity.
  • Use the original diffusion and flow loops as the baseline for understanding each extension.

What You Should Be Able To Say

You should be able to read a new diffusion or flow paper by asking which part of the generation loop it changes and what tradeoff that creates.
