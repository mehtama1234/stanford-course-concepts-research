Deep Unsupervised Learning Lecture Guide

This page reads the course lecture by lecture from the local transcripts. Each section teaches the problem, method, examples, and math moves directly, without lecture-summary filler.

Course Spine

Deep unsupervised learning studies how a model can learn from raw data when labels are missing, partial, expensive, or not the main point. The course keeps returning to six facts: data has hidden structure, probability can describe that structure, generation needs a route, representations must keep useful factors, control changes what counts as success, and scale creates new engineering limits.

Big Picture From First Principles

Start with one ordinary fact: most data has no answer key. A pile of images, text, video, molecules, or 3D views does not say what label each example deserves. But the data is not random. It has repeated parts, hidden causes, patterns over time, and rules about what can exist. Deep unsupervised learning asks how a model can use those regularities as its teacher.

The course keeps rebuilding one problem in different forms: choose what structure to learn, choose how to train from raw examples, choose how to generate or represent new examples, and then check whether the learned structure is useful rather than just memorized.

Raw Data Still Teaches

Labels are missing, but every example contains relations among parts that can become a training signal.

Probability Measures Fit

Some methods ask whether the model assigns high probability to real data and low probability elsewhere.

Generation Needs A Route

Models make samples by predicting pieces, transforming noise, decoding hidden codes, competing with a judge, or denoising step by step.

Hidden Codes Explain Causes

Latent variables compress observations into factors that can help reconstruction, sampling, or downstream tasks.

Good Features Drop Noise

Self-supervised learning builds representations that keep stable meaning while ignoring changes that should not matter.

Control Changes The Task

Text, class labels, properties, views, or scientific constraints turn random generation into directed generation.

Scale Changes Bottlenecks

Large models make simple objectives powerful, but memory, communication, sampling speed, and evaluation become central.

Scores Are Incomplete

A model can have good likelihood, sharp samples, useful features, or scientific value; one number rarely captures all of that.

How The Ideas Build

  1. Lectures 1-3: set up unlabeled data, then study exact probability through ordered prediction and invertible transformations.
  2. Lectures 4-6: move through the main generative families: hidden-code models, adversarial generators, and diffusion models.
  3. Lectures 7-8: connect unsupervised objectives to representation learning and large language models.
  4. Lectures 9-10: extend the same ideas to video and semi-supervised learning, where time and limited labels add new constraints.
  5. Lectures 11-13: apply generative modeling to science, 3D scenes, and multimodal systems where outputs must obey outside structure.
  6. Lecture 14: explains the hardware and parallel training moves needed when the models become too large for one machine.

Lecture 1

L1 Introduction

Open video

1h 19m · 42686 transcript words

Detailed Topic Explanation

Deep unsupervised learning starts from a simple pressure: most data has no clean label, but it still contains structure. Images contain repeated shapes, text contains grammar, video contains motion, and scientific data contains physical regularities. The learner must use the data itself as the teacher. Instead of mapping inputs to provided labels, it builds a model of how data is arranged, how examples can be generated, or what representation makes future tasks easier. A useful way to think about the whole course is this: labels are only one kind of information. Repetition, co-occurrence, smooth change, missing-part prediction, and the ability to reproduce examples are also information. A model can learn from those signals if the training objective forces it to keep the real structure and discard accidental noise.

The course introduces families of answers to this pressure. Likelihood models try to assign probability to data. Latent variable models explain observations through hidden causes. GANs learn by comparison with a critic. Diffusion models learn by corrupting and repairing data. Self-supervised methods create their own prediction tasks. The shared first principle is compression with use: learn the hidden regularities that make data predictable, generatable, or useful for another task. This introduction matters because it gives a map for later choices. Autoregressive models make ordered predictions. Flows preserve information through invertible maps. VAEs use hidden codes. GANs use a learned judge. Diffusion uses repair after corruption. Self-supervised learning creates prediction tasks from the input itself. Each family is a different answer to the same question: what signal can raw data provide?

Core Ideas

  • Unsupervised learning uses raw data as the main source of supervision.
  • Generative models learn how data could be produced, not only how to classify it.
  • Representations are useful when they keep important factors and discard noise.
  • Different model families trade tractable likelihood, sample quality, stability, and usable features.

Approaches Taught

Learn From The Data Itself

Problem
Most useful data does not arrive with hand-written answers, but it still has repeated structure.
How It Works
The model is trained on a task made from the data, such as predicting missing parts, reconstructing examples, assigning probability, or producing similar samples.
Why It Matters
This turns large unlabeled collections into training signal instead of waiting for expensive human labels.
Where It Breaks
The model can learn shortcuts that solve the training task without learning structure that helps later.

Separate Modeling Goals

Problem
A method can be good at likelihood, samples, compression, or features, and those are not the same goal.
How It Works
The course sorts methods by what they make easy: exact probability, fast sampling, hidden-code learning, sharp generation, or transferable representations.
Why It Matters
It prevents comparing models by one score when they were built to solve different pressures.
Where It Breaks
A method can look strong under one goal while being weak for the actual use case.

Examples Used

  • A pile of unlabeled images still contains edges, objects, lighting, and scene types.
  • A text corpus teaches grammar and style even without manual labels.

Equations And Algorithm Moves

  • Choose a modeling goal: likelihood, sample generation, representation, or downstream transfer.
  • Define the observed data x and possible hidden variables z.
  • Train by maximizing likelihood, minimizing reconstruction error, matching distributions, or solving a self-supervised task.
  • Evaluate by sample quality, likelihood, representation usefulness, or task transfer.

What You Should Be Able To Say

You should be able to explain deep unsupervised learning as learning structure from raw data when labels are missing or incomplete.

L2 Autoregressive Models

Open video

2h 11m · 67323 transcript words

Detailed Topic Explanation

Autoregressive modeling turns generation into a chain rule. Instead of producing the whole image, audio clip, or sentence at once, the model predicts one piece at a time given previous pieces. This makes likelihood exact because the probability of the full object becomes a product of conditional probabilities. The model learns the next pixel, token, or sample from the context already generated. The method is simple in principle but powerful in scale. If a sentence has ten tokens, the model learns token two from token one, token three from tokens one and two, and so on. For images, the same idea can use pixels or patches. For audio, it can use waveform samples or codes. The order creates a training target at every position, so one example gives many prediction problems.

The strength is clarity: training and evaluation use the same conditional prediction objective, and probabilities are tractable. The weakness is ordering and speed. The model must choose an order, and generation is often sequential because later pieces depend on earlier pieces. If early choices are bad, later predictions must live with them. Autoregressive models are powerful because they replace one huge joint problem with many smaller prediction problems. The lecture also makes clear why this family became central for language. Text already has a natural order, and next-token prediction uses that order directly. But the same idea is less natural for unordered data, because the chosen order can make nearby structure look far away. The model is exact as a probability model only because it commits to a factorization.

Core Ideas

  • The chain rule converts a joint probability into ordered conditional probabilities.
  • Training can use teacher forcing because the true previous pieces are known.
  • Sampling is usually sequential and can be slow.
  • Ordering choices shape what context is available at each prediction.

Approaches Taught

Chain-Rule Likelihood

Problem
The full probability of a high-dimensional object is hard to model directly.
How It Works
Break the object into an order and write its probability as one conditional prediction after another, where each next piece depends on the pieces before it.
Why It Matters
Training and scoring become exact because each conditional probability is a normal supervised prediction problem.
Where It Breaks
Generation is slow and early sampled mistakes become part of the context for later predictions.

Teacher-Forced Training

Problem
During training the model needs clean context, but during generation it must use its own past outputs.
How It Works
Train each next-piece predictor using the true earlier pieces from the data, then sample by feeding generated pieces back into the model.
Why It Matters
This makes large sequence models train efficiently on every position of every example.
Where It Breaks
The model can be surprised by its own imperfect samples because training context was cleaner than sampling context.

Examples Used

  • Next-token language modeling predicts the next token from previous tokens.
  • PixelCNN-style image models predict pixels in raster order.

Equations And Algorithm Moves

  • Factor p(x) as product_i p(x_i | x_<i).
  • Use cross-entropy or negative log likelihood for each conditional prediction.
  • During training, condition on true earlier pieces.
  • During sampling, feed back generated earlier pieces.

What You Should Be Able To Say

You should be able to explain autoregressive modeling as exact probability modeling by predicting one ordered piece at a time.

Lecture 3

L3 Flow Models

Open video

2h 19m · 64331 transcript words

Detailed Topic Explanation

Flow models start with a simple distribution such as a Gaussian and learn an invertible transformation to the data distribution. Because the transformation can be run both ways, the model can map data to noise for likelihood and noise to data for sampling. The key constraint is invertibility: the transformation must not destroy information, because the inverse must exist. Think of a flow as a reversible machine. One direction turns simple noise into a data-like sample. The other direction turns a real example back into simple noise. Because nothing is thrown away, the model can say exactly how surprising a data point is under the base noise after accounting for how the machine stretches space.

The central math handle is change of variables. If the model knows how volume changes under the transformation, it can compute the probability of the transformed point. This gives exact likelihood, but it restricts architecture design. Layers must be invertible and have tractable Jacobian determinants. Flow models show the tradeoff between mathematical cleanliness and expressive flexibility. This is why the Jacobian determinant matters. If a map expands a small region, probability density drops; if it compresses a region, density rises. The determinant measures that volume change. Flow layers are therefore judged by two demands at once: can they express complex transformations, and can their inverse and determinant be computed cheaply enough to train?

Core Ideas

  • Flows learn invertible maps between simple noise and data.
  • Exact likelihood comes from the change-of-variables formula.
  • The Jacobian determinant measures how the map stretches or shrinks volume.
  • Architecture is constrained because every layer must be invertible or tractable.

Approaches Taught

Normalizing Flow

Problem
We want exact probability and sampling, but flexible generators usually hide the probability of each output.
How It Works
Start with simple noise and pass it through an invertible map. Use the inverse map and the volume change to compute exact data likelihood.
Why It Matters
It gives a rare combination: generated samples and exact likelihood from the same model.
Where It Breaks
Every layer must be invertible and have a tractable volume term, which limits architecture choices.

Coupling Layers

Problem
A fully general invertible neural network can make the volume term too costly to compute.
How It Works
Hold part of the vector fixed while using it to transform the other part, so the inverse and determinant stay simple.
Why It Matters
This makes deep invertible models practical instead of only mathematically possible.
Where It Breaks
The split structure can reduce mixing unless many layers and permutations are stacked carefully.

Examples Used

  • A warped grid shows how simple noise can be bent into a complex data shape.
  • RealNVP-style coupling layers update part of a vector while keeping inversion easy.

Equations And Algorithm Moves

  • Sample z from a simple base p(z).
  • Map x = f_theta(z) for generation.
  • Map z = f_theta^{-1}(x) for likelihood.
  • Compute log p(x)=log p(z)+log|det dz/dx|.

What You Should Be Able To Say

You should be able to explain flows as invertible transformations that keep exact probability computation possible.

L4 Latent Variable Models and Variational AutoEncoders

Open video

2h 8m · 62140 transcript words

Detailed Topic Explanation

Latent variable models explain an observation through hidden variables. An image might be caused by object identity, pose, lighting, background, and style. A VAE turns this idea into a trainable model with two parts: an encoder that guesses a distribution over hidden causes from data, and a decoder that reconstructs or generates data from a sampled hidden code. The VAE view starts from a common-sense idea: what we see is often produced by causes we do not see. A face image comes from identity, pose, lighting, expression, camera, and background. The model invents a hidden code for those causes. The encoder maps an image to a distribution over possible codes, because many hidden explanations could fit the same observation.

The hard part is that exact posterior inference over hidden causes is usually intractable. VAEs use an approximate posterior and optimize a lower bound. The reconstruction term asks the decoder to explain the data. The KL term keeps the hidden-code distribution close to a simple prior so sampling works. This creates a tradeoff: too much pressure on the prior can make codes uninformative; too little can make generation messy. The decoder then asks whether a sampled code can explain the data. Training balances two forces. Reconstruction asks the code to carry enough information to rebuild the example. The prior penalty asks the codes to live in a clean, sampleable space. If reconstruction dominates, sampling from the prior may fail. If the prior dominates, the code may stop carrying useful information.

Core Ideas

  • Latent variables represent hidden causes or compressed factors behind observations.
  • The encoder approximates hidden causes from data.
  • The decoder generates or reconstructs data from hidden codes.
  • The VAE objective balances reconstruction against a prior-matching penalty.

Approaches Taught

Variational Autoencoder

Problem
Data may be explained by hidden causes, but those causes are not observed.
How It Works
An encoder guesses a distribution over hidden codes for an input, and a decoder learns to rebuild or generate data from sampled codes.
Why It Matters
It gives a trainable way to learn compressed hidden factors while keeping generation possible.
Where It Breaks
The decoder can ignore the code, or the prior pressure can make the code too weak.

Reparameterized Sampling

Problem
Sampling a hidden code blocks ordinary gradient training if handled naively.
How It Works
Write the random code as a deterministic function of encoder outputs plus separate noise, so gradients can flow through the encoder.
Why It Matters
This makes latent-variable models trainable with standard neural-network optimization.
Where It Breaks
The gradient estimator works only for suitable continuous distributions and can still be noisy or poorly balanced.

Examples Used

  • A face image can be explained by latent factors such as pose, identity, and lighting.
  • A handwritten digit can be encoded into a small vector and decoded back into pixels.

Equations And Algorithm Moves

  • Choose prior p(z), decoder p_theta(x|z), and encoder q_phi(z|x).
  • Sample z through the reparameterization trick.
  • Optimize reconstruction likelihood plus KL regularization.
  • Generate by sampling z from the prior and decoding.

What You Should Be Able To Say

You should be able to explain a VAE as learning hidden codes that reconstruct data while staying sampleable from a simple prior.

Lecture 5

L5 GANs

Open video

2h 32m · 72039 transcript words

Detailed Topic Explanation

GANs set up a contest. The generator tries to produce samples that look real. The discriminator tries to tell real samples from generated samples. The generator improves by finding ways to fool the discriminator. This avoids writing an explicit likelihood and can produce sharp samples because the feedback comes from whether samples look realistic rather than from pixel-by-pixel averaging. GANs replace a hand-written probability with a learned comparison game. The generator does not need to say how likely an image is. It only needs to produce an image that the discriminator cannot separate from real data. The discriminator becomes a moving measurement of what looks fake. This is useful when realism is hard to capture with a fixed formula.

The price is instability. The generator and discriminator learn together, so the target keeps moving. If the discriminator is too strong, the generator gets weak feedback. If the generator finds a narrow trick, it may produce limited kinds of samples, called mode collapse. GANs are important because they made implicit generation powerful, but they also show why adversarial training is hard to control. The contest is also the source of the trouble. The generator is not chasing a fixed target; it is chasing a discriminator that changes after every update. The discriminator can become too good and give little useful gradient, or the generator can find a narrow way to fool it. That narrow behavior is mode collapse: many inputs produce a small range of outputs.

Core Ideas

  • GANs learn an implicit generator without requiring a tractable likelihood.
  • The discriminator supplies a learned training signal by comparing real and fake samples.
  • Sharp samples can emerge because realism is judged distributionally.
  • Training can be unstable because both sides change during learning.

Approaches Taught

Adversarial Training

Problem
Some generators can make samples without giving a usable likelihood to optimize.
How It Works
Train a discriminator to separate real from fake samples, then train the generator to make fake samples the discriminator accepts as real.
Why It Matters
It supplies a learned realism signal and can produce sharp samples without pixel-wise averaging.
Where It Breaks
The target changes while training, so learning can oscillate, collapse, or stop giving useful gradients.

Discriminator As Learned Loss

Problem
Hand-written losses often reward blurry averages rather than realistic samples.
How It Works
Use the discriminator's judgment as the loss signal, so the generator is pushed toward properties that distinguish real data from fake data.
Why It Matters
The loss adapts to the data instead of measuring only fixed pixel distance.
Where It Breaks
The discriminator may focus on superficial clues and give feedback that does not match the desired notion of quality.

Examples Used

  • A fake-image detector gives feedback to an image generator.
  • Mode collapse occurs when many random inputs produce similar-looking outputs.

Equations And Algorithm Moves

  • Sample noise z and generate G(z).
  • Train D(x) high for real data and low for generated data.
  • Train G to make D(G(z)) high.
  • Monitor diversity and discriminator-generator balance.

What You Should Be Able To Say

You should be able to explain GANs as generator-versus-judge training, with sharp samples but unstable optimization.

Lecture 6

L6 Diffusion Models

Open video

2h 22m · 72846 transcript words

Detailed Topic Explanation

Diffusion models learn generation by first making destruction easy. Add noise to real data step by step until it becomes almost pure noise. Then train a model to reverse the process one step at a time. At generation time, start from noise and repeatedly clean it. This turns a huge generation jump into many smaller denoising decisions. Diffusion uses a training trick that gives the model a clear answer key. Start with a real example, choose a noise level, add known noise, and ask the network to predict the noise or the clean direction. Because the corruption is made by us, the target is known. The model practices repair at many noise levels, from nearly clean data to almost pure noise.

The training target is clear because the added noise is known. The model learns how to estimate or remove noise at different noise levels. Early steps decide broad structure; later steps refine details. Diffusion is stable compared with adversarial training, but sampling can be slow because many reverse steps are needed. Guidance and distillation are common ways to improve control or speed. At sampling time the direction reverses. Start from random noise and repeatedly apply the learned repair rule. The time or noise-level input tells the network what kind of repair is needed. High-noise steps decide broad layout because little detail remains. Low-noise steps refine texture and small structure. This makes training stable, but it creates a compute cost during sampling.

Core Ideas

  • Forward diffusion corrupts data with known noise.
  • Reverse diffusion learns many small denoising updates.
  • Noise level or time is an input because each stage needs different behavior.
  • Sampling trades compute for quality and control.

Approaches Taught

Denoising Diffusion

Problem
Making a whole complex sample in one step is difficult and unstable.
How It Works
Add known noise to data over many steps, then train a network to predict the noise or clean direction at each noise level.
Why It Matters
Generation becomes a chain of small repair problems, which is easier to train than a one-shot generator.
Where It Breaks
Sampling can be slow because many reverse steps may be needed for high quality.

Guided Sampling

Problem
A generator must often obey a condition such as a class, text prompt, or desired property.
How It Works
During sampling, modify the denoising direction with an extra signal that points toward the condition while still following the learned data direction.
Why It Matters
It turns an unconditional generator into a controlled generator without changing the whole training setup.
Where It Breaks
Too much guidance can reduce diversity or create samples that satisfy the condition in brittle ways.

Examples Used

  • An image slowly becomes static during the forward process.
  • Static becomes a coherent image through repeated reverse cleanup.

Equations And Algorithm Moves

  • Sample clean x_0, time t, and noise epsilon.
  • Construct noisy x_t.
  • Train epsilon_theta(x_t,t) to predict epsilon.
  • Sample by iterating from x_T noise toward x_0.

What You Should Be Able To Say

You should be able to explain diffusion as learning to undo known noise corruption step by step.

Lecture 7

L7 Self-Supervised Learning

Open video

2h 31m · 73469 transcript words

Detailed Topic Explanation

Self-supervised learning makes labels out of structure already present in data. Instead of asking humans to label every image or sentence, the method hides, transforms, compares, or predicts parts of the input. The model learns representations because solving the pretext task requires understanding meaningful structure. For images, it may compare augmented views. For language, it may predict missing or next tokens. For video, it may use time and motion. Self-supervised learning asks the data to create its own questions. In contrastive learning, two views of the same item should lead to nearby representations. In masked prediction, the visible part should predict the hidden part. In both cases, the model is forced to represent something stable about the example because surface-level copying is made difficult.

The goal is not always generation. Often the goal is a representation that transfers to later tasks with few labels. Contrastive learning pulls related views together and pushes unrelated views apart. Masked prediction asks the model to fill missing content. The failure mode is shortcut learning: the model may solve the artificial task using superficial cues that do not help downstream. The design of the task decides what the representation keeps. If crop, color, or noise changes are treated as irrelevant, the model learns to ignore them. That helps when those changes do not matter for later tasks. It hurts when the ignored detail is actually important. Self-supervision is therefore not label-free magic; it is a choice about which differences should count.

Core Ideas

  • Self-supervision creates training targets from unlabeled data.
  • Representations are judged by transfer, not only by pretext-task accuracy.
  • Contrastive learning compares positive and negative pairs.
  • Masked prediction forces the model to infer missing structure from context.

Approaches Taught

Contrastive Learning

Problem
A model needs useful features without class labels.
How It Works
Create two changed views of the same example, pull their representations together, and push representations of different examples apart.
Why It Matters
It teaches invariances, such as object identity surviving crop or color changes, from raw data.
Where It Breaks
Bad augmentations can erase the very information the representation needs to keep.

Masked Prediction

Problem
The model needs a self-made task that forces it to understand context.
How It Works
Hide part of the input and train the model to predict the missing content from the visible parts.
Why It Matters
This creates a dense training signal for text, images, and other structured data without labels.
Where It Breaks
The model may learn local fill-in tricks instead of broader meaning if the mask task is too easy.

Examples Used

  • Two crops of the same image form a positive pair in contrastive learning.
  • A masked word or image patch must be predicted from context.

Equations And Algorithm Moves

  • Choose an augmentation, mask, or prediction rule.
  • Encode inputs into representation vectors.
  • Optimize contrastive, reconstruction, or prediction loss.
  • Evaluate representations on downstream tasks.

What You Should Be Able To Say

You should be able to explain self-supervised learning as making useful training signals from the data itself.

L8 Large Language Models

Open video

2h 14m · 41135 transcript words

Detailed Topic Explanation

Large language models fit naturally into deep unsupervised learning because next-token prediction creates labels from raw text. The model sees previous tokens and predicts the next token. At huge scale, this teaches grammar, facts, style, code patterns, and task formats. The same transformer machinery from supervised NLP becomes a broad generative model when trained on enough text. Large language models fit naturally into this course because next-token prediction is a self-made target. Text supplies its own supervision: every prefix asks for the next token. The transformer supplies the machinery for using context. Attention lets each token gather information from other tokens, and stacked blocks repeatedly refine the representation before the next-token distribution is produced.

The first-principles point is that prediction compresses structure. To predict well, the model must represent what the context means and what continuations are plausible. But likelihood over text is not the same as truth or usefulness. A model can produce fluent wrong text. Post-training, retrieval, tools, and evaluation are needed because self-supervised pretraining alone does not define desired behavior. The lecture connects objective, architecture, and scale. The objective is simple, but the data is broad and the model is large enough to absorb many patterns. That produces useful behavior, but the training goal is still prediction, not truth or helpfulness. Post-training and evaluation are needed because a predictor can continue a pattern that is fluent while being wrong or unsafe.

Core Ideas

  • Next-token prediction is self-supervised because the next token is already in the text.
  • Scale turns a simple prediction task into broad capability.
  • The output is a probability distribution over tokens, not a truth guarantee.
  • Post-training is needed to shape behavior beyond raw text prediction.

Approaches Taught

Next-Token Pretraining

Problem
Language has no single label, but every text position supplies a next-piece prediction target.
How It Works
Train a model to predict the next token from previous tokens across massive text collections.
Why It Matters
This simple objective teaches syntax, facts, style, code patterns, and some reasoning habits at scale.
Where It Breaks
A good next-token predictor can still produce false, unsafe, or unhelpful answers.

Transformer Context Mixing

Problem
Each word or token must use information from far-away tokens, not only nearby ones.
How It Works
Attention lets each token compute which other tokens matter, copy information from them, and update its representation through stacked blocks.
Why It Matters
It gives language models a scalable way to use long context while training on many positions in parallel.
Where It Breaks
Cost grows with context length, and the model may still miss facts that require exact retrieval or calculation.

Examples Used

  • A web text corpus supplies billions of next-token examples without manual labels.
  • A code model learns syntax and common APIs by predicting code tokens.

Equations And Algorithm Moves

  • Tokenize text into ids.
  • Use transformer blocks to process context.
  • Predict next-token logits.
  • Train with cross-entropy over raw text.

What You Should Be Able To Say

You should be able to explain LLMs as very large self-supervised sequence models trained by next-token prediction.

Lecture 9

L9 Energy-Based Models

Open video

1h 13m · 38182 transcript words

Detailed Topic Explanation

Generative video adds a time problem to image generation. A single image can be plausible on its own, but video requires consistency: objects must keep identity, motion must be smooth, and the scene must obey time. Models can extend diffusion, autoregressive, or latent methods so they generate across frames instead of only pixels in one image. Video generation extends image generation by adding time. The model must produce frames that look realistic by themselves and also agree across time. A person, object, or room cannot randomly change identity from one frame to the next. Motion must be plausible, camera movement must be handled, and long-range events must remain connected.

The hard part is that errors compound through time. If the model changes an object identity, camera path, or physical relation, the video feels broken even if individual frames are sharp. The model must represent temporal context and often use latent video spaces to keep compute manageable. Evaluation is also harder because quality includes frame realism, motion realism, prompt following, and temporal consistency. The lecture’s core pressure is cost and coherence. Raw video is much larger than a single image, so many systems work in latent spaces or use compressed video tokens. But compression does not remove the need for temporal reasoning. The generator must decide what stays fixed, what moves, what appears, what disappears, and how uncertainty should unfold across future frames.

Core Ideas

  • Video generation adds temporal consistency to visual sample quality.
  • Models must represent motion, identity, and scene state across frames.
  • Latent spaces help reduce the cost of generating many frames.
  • Evaluation must check flicker, object persistence, and prompt-conditioned motion.

Approaches Taught

Latent Video Generation

Problem
Raw video is expensive because it has space, time, motion, and many redundant pixels.
How It Works
Compress frames into a smaller latent space and learn generation or denoising there while preserving the main visual and motion structure.
Why It Matters
It makes video generation cheaper and lets the model spend capacity on motion and scene change instead of every pixel.
Where It Breaks
Compression can lose fine details, and small temporal errors can accumulate across frames.

Temporal Consistency Modeling

Problem
A generated video can have good individual frames but bad motion or changing object identity.
How It Works
Condition generation on nearby frames, time embeddings, motion cues, or 3D-aware structure so outputs remain coherent over time.
Why It Matters
Video quality depends on continuity, not just frame-level realism.
Where It Breaks
Long actions, occlusion, and camera motion can still break object identity or physical consistency.

Examples Used

  • A generated person should not change face identity between frames.
  • A moving object should follow a coherent path rather than jump randomly.

Equations And Algorithm Moves

  • Represent video as frames or latent tokens over time.
  • Condition generation on text, previous frames, or motion controls.
  • Use temporal attention, 3D convolutions, or sequential sampling.
  • Evaluate realism, motion, consistency, and alignment.

What You Should Be Able To Say

You should be able to explain generative video as image generation plus the extra burden of time consistency.

Lecture 10

L10 Implicit Models

Open video

1h 27m · 41453 transcript words

Detailed Topic Explanation

Semi-supervised learning combines a few labels with many unlabeled examples. The model uses labels to anchor the task and unlabeled data to learn the shape of the input distribution. Distribution alignment asks how to make predictions or representations behave consistently across related data sources, such as domains with different style, lighting, or sensor properties. Semi-supervised learning sits between supervised and unsupervised learning. A small labeled set says what the task means. A large unlabeled set shows more of the data distribution. The method tries to use both: labels anchor the meaning of classes, while unlabeled examples teach where the real examples lie and how decision boundaries should pass through the space.

The first principle is that unlabeled data is useful when its structure says something about the labels or target behavior. Pseudo-labeling, consistency regularization, and alignment losses all assume that nearby or transformed examples should have compatible predictions. The danger is confirmation error: wrong pseudo-labels can reinforce themselves, and alignment can erase real differences that matter. Distribution alignment adds another pressure. If the model predicts too many examples as one class, or if unlabeled data has a different balance than labeled data, training can drift. Alignment and consistency methods try to keep predictions stable under small changes and keep the output distribution reasonable. These methods help only when their assumptions match the data.

Core Ideas

  • Semi-supervised learning uses labeled and unlabeled data together.
  • Pseudo-labeling turns confident model predictions into temporary labels.
  • Consistency regularization asks predictions to survive harmless changes.
  • Distribution alignment tries to reduce harmful shifts between domains.

Approaches Taught

Pseudo-Labeling

Problem
There are many unlabeled examples and only a small labeled set.
How It Works
Train on labeled data, use the model to assign labels to unlabeled data, then train again on confident guessed labels.
Why It Matters
It converts unlabeled data into extra practice when manual labels are scarce.
Where It Breaks
Wrong confident guesses can reinforce the model's own mistakes.

Distribution Alignment

Problem
The labeled set and unlabeled set may have different class balance or feature statistics.
How It Works
Adjust predictions or representations so the model's output distribution on unlabeled data matches a desired prior or matches the labeled distribution.
Why It Matters
It prevents the model from treating unlabeled data as if it came from a different problem.
Where It Breaks
If the assumed distribution is wrong, alignment can force the model toward false labels.

Examples Used

  • A classifier trained on a few labeled images can use many unlabeled images from the same domain.
  • A model trained on synthetic images may need alignment before working on real camera images.

Equations And Algorithm Moves

  • Train on supervised loss for labeled examples.
  • Generate pseudo-labels for confident unlabeled examples.
  • Apply consistency loss across augmentations.
  • Add alignment loss between source and target distributions.

What You Should Be Able To Say

You should be able to explain semi-supervised learning as using unlabeled data to support a small labeled task without blindly trusting it.

Lecture 12

L12 Applications

Open video

1h 4m · 40652 transcript words

Detailed Topic Explanation

Neural radiance fields model a scene as a continuous function. Given a 3D location and viewing direction, the function predicts density and color. Rendering a camera view means tracing rays through that field and accumulating color along each ray. The model is trained so rendered views match observed images from different cameras. Neural radiance fields start from the fact that a photo is a 2D record of light from a 3D scene. If we know camera poses, each pixel corresponds to a ray through space. The model learns a function over 3D locations and viewing directions. For each point, it predicts density and color, which are combined along rays to match training images.

The core idea is inverse rendering. The model is not handed the full 3D scene; it finds a scene representation that would explain the photos. This requires consistency across views. If one view shows an object at a location, other views must agree. NeRFs are powerful because they store a scene continuously, but they can be slow, need enough views, and struggle when lighting, motion, or geometry assumptions break. The method is unsupervised in the sense that the supervision is ordinary posed images, not hand-labeled 3D geometry. Geometry is recovered because the same scene must explain many views. If a point is truly part of a surface, many camera rays should agree about it. Sparse views, bad poses, or reflective surfaces make that agreement weak and can produce artifacts.

Core Ideas

  • A NeRF represents a scene as a continuous function over 3D position and view direction.
  • Volume rendering turns the field into predicted camera images.
  • Training matches rendered images to observed views.
  • Multi-view consistency is the key constraint that makes 3D recoverable.

Approaches Taught

Neural Radiance Field

Problem
A set of photos shows a scene from some views, but we want to render new views.
How It Works
Train a neural function that maps 3D position and viewing direction to color and density, then render images by accumulating values along camera rays.
Why It Matters
It represents a 3D scene without an explicit mesh and can synthesize realistic novel views.
Where It Breaks
Training and rendering can be slow, and wrong camera poses or sparse views can create artifacts.

Volume Rendering

Problem
A camera ray passes through empty space, surfaces, and transparent regions before reaching a pixel color.
How It Works
Sample points along a ray, estimate density and color at each point, and combine them by how much light each point contributes.
Why It Matters
It connects the learned 3D field to ordinary image supervision from photos.
Where It Breaks
Poor sampling or ambiguous geometry can produce floaters, blurred surfaces, or wrong depth.

Examples Used

  • A set of photos of a room can train a field that renders a new camera angle.
  • A ray through empty space accumulates little density before hitting a surface.

Equations And Algorithm Moves

  • Input 3D point x and view direction d to a neural field.
  • Predict density sigma and color c.
  • Sample points along camera rays.
  • Integrate colors and densities to render pixels.
  • Optimize rendered pixels against real images.

What You Should Be Able To Say

You should be able to explain NeRF as learning a continuous 3D scene that can render many camera views consistently.

Lecture 13

L13 Frontiers

Open video

53m 0s · 26475 transcript words

Detailed Topic Explanation

Multimodal models connect text, images, audio, video, or actions. The problem is that each modality has its own structure: text is token order, images are spatial grids, audio is time signals, and video is space plus time. A multimodal model must encode each form and then align them so a text prompt can refer to an image, an image can be captioned, or a video can be queried. Multimodal models ask how different kinds of data can share meaning. A caption and an image are not the same object, but they can refer to the same scene. Audio and video can describe the same event. A model needs a bridge so that information from one form can guide understanding or generation in another form.

The first-principles operation is alignment across representations. Contrastive learning can pull matching image-text pairs together. Cross-attention can let text guide image features or image features guide text. Generative multimodal systems can condition one modality on another. The failure mode is shallow matching: the model may learn common captions and visual shortcuts without grounding relations, counts, or detailed scene structure. Two main moves appear. Alignment puts paired items near each other in a shared representation space. Conditioning lets one modality directly steer another during generation, often through cross-attention. Both moves are powerful because they make text, images, audio, and other signals usable together. They also inherit bias from pairings in the data and can bind the wrong parts together.

Core Ideas

  • Each modality needs a representation suited to its structure.
  • Alignment connects related items across modalities.
  • Contrastive losses and cross-attention are common alignment tools.
  • A multimodal model can retrieve, caption, answer, or generate across data types.

Approaches Taught

Contrastive Multimodal Alignment

Problem
Images, text, audio, and other signals use different forms but can refer to the same thing.
How It Works
Train matching pairs to have nearby representations and mismatched pairs to be farther apart in a shared space.
Why It Matters
It lets one mode retrieve, guide, or explain another, such as text searching images or text steering generation.
Where It Breaks
The shared space can capture dataset bias or shallow correlations instead of grounded meaning.

Cross-Attention Conditioning

Problem
A generator needs to use information from another mode while producing its own output.
How It Works
Let generated tokens or image features attend to conditioning tokens from text, image, audio, or other inputs at each update.
Why It Matters
It gives the generator a direct path to use outside instructions or context during generation.
Where It Breaks
The model can ignore the condition, overfit to it, or bind the wrong words to the wrong visual parts.

Examples Used

  • An image and its caption should land near each other in representation space.
  • A text prompt can condition an image or video generator.

Equations And Algorithm Moves

  • Encode image patches, text tokens, or audio frames.
  • Project modality features into a shared space.
  • Use contrastive loss on matched and mismatched pairs.
  • Use cross-attention for conditional reasoning or generation.

What You Should Be Able To Say

You should be able to explain multimodal learning as aligning different data forms so they can condition, retrieve, or explain each other.

Lecture 14

L14 Course Wrap-Up

Open video

39m 31s · 17385 transcript words

Detailed Topic Explanation

Parallelization asks how to make large models run fast enough. Some model families are naturally sequential, like autoregressive generation where token i depends on earlier tokens. Transformers allow more parallel training because all positions in a sequence can be processed together under a mask. Hardware efficiency depends on batching, memory movement, attention cost, and how computation is split across devices. Parallelization is part of the learning story because scale changes what methods are possible. A model may have too many parameters for one accelerator, a batch may be too large, or the training run may take too long. Splitting work across devices sounds simple, but every split creates communication: devices must exchange gradients, activations, weights, or partial matrix products.

The first-principles issue is dependency. If one computation truly needs the result of another, it cannot be fully parallelized. If the dependencies can be masked, batched, or rearranged, hardware can do more work at once. This affects which generative models are practical. A mathematically good model may be too slow if it cannot use hardware well. Parallelization is therefore part of the method, not just implementation detail. The lecture separates different bottlenecks. Data parallelism copies the model and splits examples. Model parallelism splits weights or layers. Tensor parallelism splits large operations. Pipeline parallelism sends different microbatches through different layer stages. The right choice depends on memory, bandwidth, compute balance, and whether devices spend time working or waiting.

Core Ideas

  • Parallelism is limited by real dependencies in the computation graph.
  • Transformer training can process many sequence positions at once with causal masks.
  • Autoregressive sampling remains sequential at generation time.
  • Memory bandwidth and device communication can dominate runtime.

Approaches Taught

Data And Model Parallel Training

Problem
Modern models and datasets are too large for one device to train alone.
How It Works
Split batches across devices, split model weights across devices, or split layers across devices, then synchronize the needed values during training.
Why It Matters
It makes large unsupervised and generative models trainable within practical time and memory limits.
Where It Breaks
Communication can dominate compute, and a poor split can waste hardware.

Pipeline And Tensor Parallelism

Problem
Even one forward pass may not fit or run efficiently on a single accelerator.
How It Works
Pipeline parallelism assigns different layers to different devices, while tensor parallelism splits large matrix operations across devices.
Why It Matters
These methods attack memory and speed bottlenecks inside very large models.
Where It Breaks
Bubbles, synchronization cost, and uneven layer sizes can leave devices idle.

Examples Used

  • Training a transformer can compute losses for many positions in one pass.
  • Generating text one token at a time cannot fully parallelize across future tokens.

Equations And Algorithm Moves

  • Represent computation as a dependency graph.
  • Batch independent examples and positions where possible.
  • Use masking to preserve causal correctness.
  • Split tensors or batches across devices when models are too large.

What You Should Be Able To Say

You should be able to explain parallelization as arranging model computation around dependency limits and hardware cost.
