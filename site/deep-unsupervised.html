UC Berkeley CS294-158 Deep Unsupervised Learning

Deep Unsupervised Learning Lecture Guide

Deep unsupervised learning studies how raw data can teach a model without ordinary labels by exposing repeated structure, hidden causes, predictable parts, and useful representations.

Course Spine

Deep unsupervised learning studies how a model can learn from raw data when labels are missing, partial, expensive, or not the main point. The course keeps returning to six facts: data has hidden structure, probability can describe that structure, generation needs a route, representations must keep useful factors, control changes what counts as success, and scale creates new engineering limits.

Big Picture From First Principles

Start with one ordinary fact: most data has no answer key. A pile of images, text, video, molecules, or 3D views does not say what label each example deserves. But the data is not random. It has repeated parts, hidden causes, patterns over time, and rules about what can exist. Deep unsupervised learning asks how a model can use those regularities as its teacher.

The course keeps rebuilding one problem in different forms: choose what structure to learn, choose how to train from raw examples, choose how to generate or represent new examples, and then check whether the learned structure is useful rather than just memorized.

Raw Data Still Teaches

Labels are missing, but every example contains relations among parts that can become a training signal.

Probability Measures Fit

Some methods ask whether the model assigns high probability to real data and low probability elsewhere.

Generation Needs A Route

Models make samples by predicting pieces, transforming noise, decoding hidden codes, competing with a judge, or denoising step by step.

Hidden Codes Explain Causes

Latent variables compress observations into factors that can help reconstruction, sampling, or downstream tasks.

Good Features Drop Noise

Self-supervised learning builds representations that keep stable meaning while ignoring changes that should not matter.

Control Changes The Task

Text, class labels, properties, views, or scientific constraints turn random generation into directed generation.

Scale Changes Bottlenecks

Large models make simple objectives powerful, but memory, communication, sampling speed, and evaluation become central.

Scores Are Incomplete

A model can have good likelihood, sharp samples, useful features, or scientific value; one number rarely captures all of that.

How The Ideas Build

  1. Lectures 1-3: set up unlabeled data, then study exact probability through ordered prediction and invertible transformations.
  2. Lectures 4-6: move through the main generative families: hidden-code models, adversarial generators, and diffusion models.
  3. Lectures 7-8: connect unsupervised objectives to representation learning and large language models.
  4. Lectures 9-10: extend the same ideas to video and semi-supervised learning, where time and limited labels add new constraints.
  5. Lectures 11-13: apply generative modeling to science, 3D scenes, and multimodal systems where outputs must obey outside structure.
  6. Lecture 14: explains the hardware and parallel training moves needed when the models become too large for one machine.

L1 Introduction

Detailed Topic Explanation

Deep unsupervised learning starts from a simple pressure: most data has no clean label, but it still contains structure. Images contain repeated shapes, text contains grammar, video contains motion, and scientific data contains physical regularities. The learner must use the data itself as the teacher. Instead of mapping inputs to provided labels, it builds a model of how data is arranged, how examples can be generated, or what representation makes future tasks easier. A useful way to think about the whole course is this: labels are only one kind of information. Repetition, co-occurrence, smooth change, missing-part prediction, and the ability to reproduce examples are also information. A model can learn from those signals if the training objective forces it to keep the real structure and discard accidental noise. A useful model must decide what kind of regularity matters. If the goal is density, it must assign probability to real examples. If the goal is sampling, it must turn simple randomness into realistic examples. If the goal is representation, it must keep factors that help future tasks. These goals overlap but are not identical, which is why the course compares several model families instead of treating unsupervised learning as one method.

The course introduces families of answers to this pressure. Likelihood models try to assign probability to data. Latent variable models explain observations through hidden causes. GANs learn by comparison with a critic. Diffusion models learn by corrupting and repairing data. Self-supervised methods create their own prediction tasks. The shared first principle is compression with use: learn the hidden regularities that make data predictable, generatable, or useful for another task. This introduction matters because it gives a map for later choices. Autoregressive models make ordered predictions. Flows preserve information through invertible maps. VAEs use hidden codes. GANs use a learned judge. Diffusion uses repair after corruption. Self-supervised learning creates prediction tasks from the input itself. Each family is a different answer to the same question: what signal can raw data provide? The first-principles map is input, hidden structure, training signal, and evaluation. The input is raw x. Hidden structure may be a latent code z, an ordering over parts, a path from noise to data, or an invariant representation. The training signal may be likelihood, reconstruction, discrimination, denoising, or contrastive agreement. The evaluation must match the goal, because a model can have useful features but weak samples, or sharp samples but poor likelihood.

Core Ideas

  • Unsupervised learning uses raw data as the main source of supervision.
  • Generative models learn how data could be produced, not only how to classify it.
  • Representations are useful when they keep important factors and discard noise.
  • Different model families trade tractable likelihood, sample quality, stability, and usable features.
  • Different unsupervised objectives answer different questions about the same data.
  • A useful objective blocks trivial copying and makes hidden structure necessary for low loss.
  • Evaluation must match the intended use: probability, generation, representation, control, or scientific validity.

Approaches Taught

Learn From The Data Itself

Problem
Most useful data does not arrive with hand-written answers, but it still has repeated structure.
How It Works
Create a training task from the example rather than from a human label. Hide part of the input, predict a neighboring part, reconstruct a compressed version, assign likelihood to the full example, or generate a related sample. The model improves only when it discovers repeatable structure that helps solve that self-made task.
Why It Matters
This turns large unlabeled collections into training signal instead of waiting for expensive human labels.
Where It Breaks
The model can learn shortcuts that solve the training task without learning structure that helps later.

Separate Modeling Goals

Problem
A method can be good at likelihood, samples, compression, or features, and those are not the same goal.
How It Works
Sort each method by the object it learns and the evidence it uses. Likelihood models learn p(x), latent models learn hidden z and p(x|z), GANs learn a generator judged by a discriminator, diffusion models learn denoising directions, and self-supervised models learn representations for later transfer. Then judge each method by the goal it was built for.
Why It Matters
It prevents comparing models by one score when they were built to solve different pressures.
Where It Breaks
A method can look strong under one goal while being weak for the actual use case.

Examples Used

  • A pile of unlabeled images still contains edges, objects, lighting, and scene types.
  • A text corpus teaches grammar and style even without manual labels.
  • A model trained to reconstruct images can learn compression without learning a good sampler.
  • A representation that ignores color may help object recognition but hurt medical imaging where color changes can matter.

Equations And Algorithm Moves

  • Choose a modeling goal: likelihood, sample generation, representation, or downstream transfer.
  • Define the observed data x and possible hidden variables z.
  • Train by maximizing likelihood, minimizing reconstruction error, matching distributions, or solving a self-supervised task.
  • Evaluate by sample quality, likelihood, representation usefulness, or task transfer.
  • Write the dataset as samples x ~ p_data(x), where p_data is unknown and only samples are observed.
  • Choose the object to learn: p_theta(x), p_theta(x|z), a generator G_theta(z), a score s_theta(x,t), or an encoder f_theta(x).
  • Define the training signal so real data creates targets: log likelihood, reconstruction error, discriminator loss, denoising target, masked-token target, or contrastive agreement.
  • Check for trivial solutions: identity copying, memorization, collapsed codes, collapsed generators, shortcut augmentations, or benchmark leakage.
  • Match evaluation to the learned object: likelihood for density, FID or human review for samples, linear probe or transfer for representations, and external tests for scientific outputs.

What You Should Be Able To Say

You should be able to explain deep unsupervised learning as learning structure from raw data when labels are missing or incomplete.

L2 Autoregressive Models

Open video

2h 11m · 67323 transcript words

Detailed Topic Explanation

Autoregressive modeling turns generation into a chain rule. Instead of producing the whole image, audio clip, or sentence at once, the model predicts one piece at a time given previous pieces. This makes likelihood exact because the probability of the full object becomes a product of conditional probabilities. The model learns the next pixel, token, or sample from the context already generated. The method is simple in principle but powerful in scale. If a sentence has ten tokens, the model learns token two from token one, token three from tokens one and two, and so on. For images, the same idea can use pixels or patches. For audio, it can use waveform samples or codes. The order creates a training target at every position, so one example gives many prediction problems. The chain rule is exact for any order, but the chosen order changes the learning problem. A left-to-right language model has a natural prefix. An image raster order is artificial: nearby pixels below or to the right are hidden even though they are visually close. The model succeeds when each conditional distribution is easy enough to learn and rich enough to capture the dependencies needed for the full object.

The strength is clarity: training and evaluation use the same conditional prediction objective, and probabilities are tractable. The weakness is ordering and speed. The model must choose an order, and generation is often sequential because later pieces depend on earlier pieces. If early choices are bad, later predictions must live with them. Autoregressive models are powerful because they replace one huge joint problem with many smaller prediction problems. Text already has a natural order, and next-token prediction uses that order directly. But the same idea is less natural for unordered data, because the chosen order can make nearby structure look far away. The model is exact as a probability model only because it commits to a factorization. Training and sampling differ. During training, teacher forcing gives the model the true previous pieces, so every position can be trained in parallel. During sampling, previous pieces are generated by the model itself. This creates exposure to its own mistakes. Sampling controls such as temperature, top-k, or nucleus sampling change whether the model follows the highest-probability continuation or explores lower-probability alternatives.

Core Ideas

  • The chain rule converts a joint probability into ordered conditional probabilities.
  • Training can use teacher forcing because the true previous pieces are known.
  • Sampling is usually sequential and can be slow.
  • Ordering choices shape what context is available at each prediction.
  • The chain rule is exact, but the factorization order controls what context each predictor sees.
  • Teacher forcing gives clean training context; sampling must live with generated context.
  • Autoregressive models provide exact likelihood but pay a sequential sampling cost.

Approaches Taught

Chain-Rule Likelihood

Problem
The full probability of a high-dimensional object is hard to model directly.
How It Works
Choose an order for the components of x, then write the full probability as a product of conditional probabilities. Train one conditional predictor for every position using the true previous components as context. The full log likelihood becomes a sum of next-piece log probabilities, so training is ordinary cross-entropy or negative log likelihood across positions.
Why It Matters
Training and scoring become exact because each conditional probability is a normal supervised prediction problem.
Where It Breaks
Generation is slow and early sampled mistakes become part of the context for later predictions.

Teacher-Forced Training

Problem
During training the model needs clean context, but during generation it must use its own past outputs.
How It Works
During training, feed the true prefix from the dataset into the model at every position, even if the model would have sampled something else. This lets all positions produce supervised losses in parallel. During generation, switch to feeding back the model’s own sampled outputs, one step at a time, until the sequence is complete.
Why It Matters
This makes large sequence models train efficiently on every position of every example.
Where It Breaks
The model can be surprised by its own imperfect samples because training context was cleaner than sampling context.

Examples Used

  • Next-token language modeling predicts the next token from previous tokens.
  • PixelCNN-style image models predict pixels in raster order.
  • In audio generation, a bad early waveform sample can affect later predicted samples.
  • In image generation, raster order hides lower pixels while predicting upper pixels even though they may be visually related.

Equations And Algorithm Moves

  • Factor p(x) as product_i p(x_i | x_<i).
  • Use cross-entropy or negative log likelihood for each conditional prediction.
  • During training, condition on true earlier pieces.
  • During sampling, feed back generated earlier pieces.
  • Choose an order for components x_1,...,x_D; the order may be natural for text or designed for images, audio, or tokens.
  • Use the chain rule p_theta(x)=product_{i=1}^D p_theta(x_i | x_1,...,x_{i-1}).
  • Train by minimizing negative log likelihood: L(theta) = -sum_i log p_theta(x_i | x_<i).
  • Use teacher forcing during training, meaning x_<i comes from the data rather than from the model sample.
  • Sample by drawing x_1, then x_2 ~ p_theta(.|x_1), and continuing until all components are produced.
  • Control randomness at sampling with temperature or truncation methods, trading diversity against risk of low-quality samples.

What You Should Be Able To Say

You should be able to explain autoregressive modeling as exact probability modeling by predicting one ordered piece at a time.

L3 Flow Models

Open video

2h 19m · 64331 transcript words

Detailed Topic Explanation

Flow models start with a simple distribution such as a Gaussian and learn an invertible transformation to the data distribution. Because the transformation can be run both ways, the model can map data to noise for likelihood and noise to data for sampling. The key constraint is invertibility: the transformation must not destroy information, because the inverse must exist. Think of a flow as a reversible machine. One direction turns simple noise into a data-like sample. The other direction turns a real example back into simple noise. Because nothing is thrown away, the model can say exactly how surprising a data point is under the base noise after accounting for how the machine stretches space. A flow is a bijection: every data point has one noise point and every noise point maps to one data point. That one-to-one property is why likelihood is tractable. If the map squeezes a region, density rises; if it stretches a region, density falls. The model therefore learns both shape and volume change. This makes flows mathematically clean but forces architecture choices that normal neural networks do not have to obey.

The central math handle is change of variables. If the model knows how volume changes under the transformation, it can compute the probability of the transformed point. This gives exact likelihood, but it restricts architecture design. Layers must be invertible and have tractable Jacobian determinants. Flow models show the tradeoff between mathematical cleanliness and expressive flexibility. This is why the Jacobian determinant matters. If a map expands a small region, probability density drops; if it compresses a region, density rises. The determinant measures that volume change. Flow layers are therefore judged by two demands at once: can they express complex transformations, and can their inverse and determinant be computed cheaply enough to train? Coupling layers are the practical compromise. Split the vector into two parts. Leave one part unchanged and use it to shift or scale the other part. Because half the vector is unchanged during the layer, inversion is easy and the Jacobian has a triangular form, so the determinant is cheap. Stacking many layers with permutations lets information eventually mix across all dimensions while keeping each step tractable.

Core Ideas

  • Flows learn invertible maps between simple noise and data.
  • Exact likelihood comes from the change-of-variables formula.
  • The Jacobian determinant measures how the map stretches or shrinks volume.
  • Architecture is constrained because every layer must be invertible or tractable.
  • Invertibility gives exact reverse mapping but prevents ordinary lossy compression.
  • The determinant term is not optional; it is how probability mass is conserved under transformation.
  • Coupling and autoregressive layers trade expressiveness for computable inverse and determinant.

Approaches Taught

Normalizing Flow

Problem
We want exact probability and sampling, but flexible generators usually hide the probability of each output.
How It Works
Define an invertible neural map between simple noise z and data x. For sampling, draw z from a known base distribution and run the map forward. For likelihood, invert the data point back to z and add the log probability of z to the log determinant of the inverse Jacobian, which accounts for local volume change.
Why It Matters
It gives a rare combination: generated samples and exact likelihood from the same model.
Where It Breaks
Every layer must be invertible and have a tractable volume term, which limits architecture choices.

Coupling Layers

Problem
A fully general invertible neural network can make the volume term too costly to compute.
How It Works
Split the vector into two parts. Keep one part unchanged and use it to compute scale and shift values for the other part. This makes the inverse easy because the unchanged part is still available, and it makes the determinant cheap because the Jacobian has a triangular structure. Stack layers with permutations to mix dimensions over time.
Why It Matters
This makes deep invertible models practical instead of only mathematically possible.
Where It Breaks
The split structure can reduce mixing unless many layers and permutations are stacked carefully.

Examples Used

  • A warped grid shows how simple noise can be bent into a complex data shape.
  • RealNVP-style coupling layers update part of a vector while keeping inversion easy.
  • If a map stretches a small blob into a large area, each point in that area must receive lower probability density.
  • A coupling layer can update the right half of an image code using the left half, then later swap roles.

Equations And Algorithm Moves

  • Sample z from a simple base p(z).
  • Map x = f_theta(z) for generation.
  • Map z = f_theta^{-1}(x) for likelihood.
  • Compute log p(x)=log p(z)+log|det dz/dx|.
  • Let z ~ p_z(z), usually a standard Gaussian, and x = f_theta(z) where f_theta is invertible.
  • For a data point x, compute z = f_theta^{-1}(x).
  • Use change of variables: log p_x(x) = log p_z(z) + log |det(d f_theta^{-1}(x) / dx)|.
  • For a coupling layer, split x into x_a and x_b, keep y_a=x_a, and set y_b=x_b * exp(s(x_a)) + t(x_a).
  • The inverse is x_b=(y_b - t(y_a))*exp(-s(y_a)), so sampling and likelihood both remain practical.
  • The log determinant for that coupling layer is sum s(x_a), avoiding a full expensive determinant.
  • For an invertible map x=f_theta(z), likelihood uses log p_x(x)=log p_z(f_theta^{-1}(x)) + log absolute determinant of d f_theta^{-1}/dx.
  • A coupling layer keeps part of the vector fixed and uses it to scale or shift the rest, making both inverse computation and determinant computation cheap.

What You Should Be Able To Say

You should be able to explain flows as invertible transformations that keep exact probability computation possible.

L4 Latent Variable Models and Variational AutoEncoders

Open video

2h 8m · 62140 transcript words

Detailed Topic Explanation

Latent variable models explain an observation through hidden variables. An image might be caused by object identity, pose, lighting, background, and style. A VAE turns this idea into a trainable model with two parts: an encoder that guesses a distribution over hidden causes from data, and a decoder that reconstructs or generates data from a sampled hidden code. The VAE view starts from a common-sense idea: what we see is often produced by causes we do not see. A face image comes from identity, pose, lighting, expression, camera, and background. The model invents a hidden code for those causes. The encoder maps an image to a distribution over possible codes, because many hidden explanations could fit the same observation. A VAE has to solve two jobs that pull against each other. The encoder should place similar examples near related hidden codes and keep enough information to reconstruct. The prior should keep the hidden space organized so sampling random z values produces meaningful outputs. If codes are unconstrained, reconstruction is easy but random sampling fails. If codes are forced too strongly toward the prior, they stop carrying the details needed to reconstruct.

The hard part is that exact posterior inference over hidden causes is usually intractable. VAEs use an approximate posterior and optimize a lower bound. The reconstruction term asks the decoder to explain the data. The KL term keeps the hidden-code distribution close to a simple prior so sampling works. This creates a tradeoff: too much pressure on the prior can make codes uninformative; too little can make generation messy. The decoder then asks whether a sampled code can explain the data. Training balances two forces. Reconstruction asks the code to carry enough information to rebuild the example. The prior penalty asks the codes to live in a clean, sampleable space. If reconstruction dominates, sampling from the prior may fail. If the prior dominates, the code may stop carrying useful information. The ELBO is the training compromise. The reconstruction term rewards explaining x from z. The KL term penalizes an approximate posterior q_phi(z|x) that drifts too far from the prior p(z). The reparameterization trick makes sampling differentiable by writing z = mu_phi(x) + sigma_phi(x) * epsilon, with epsilon drawn from a fixed Gaussian. This moves randomness outside the learned parameters so gradients can train the encoder.

Core Ideas

  • Latent variables represent hidden causes or compressed factors behind observations.
  • The encoder approximates hidden causes from data.
  • The decoder generates or reconstructs data from hidden codes.
  • The VAE objective balances reconstruction against a prior-matching penalty.
  • The encoder returns a distribution over hidden codes, not just one fixed code.
  • The decoder learns p_theta(x|z), a distribution of observations given a hidden cause.
  • The KL term keeps codes sampleable; the reconstruction term keeps codes informative.
  • The reparameterization trick turns random sampling into a differentiable computation path.

Approaches Taught

Variational Autoencoder

Problem
Data may be explained by hidden causes, but those causes are not observed.
How It Works
Train an encoder q(z|x) to produce a distribution over hidden codes and a decoder p(x|z) to reconstruct or generate observations from those codes. Optimize a lower bound with two forces: reconstruction rewards codes that explain the input, while KL regularization keeps the code distribution close to a simple prior so random sampling works.
Why It Matters
It gives a trainable way to learn compressed hidden factors while keeping generation possible.
Where It Breaks
The decoder can ignore the code, or the prior pressure can make the code too weak.

Reparameterized Sampling

Problem
Sampling a hidden code blocks ordinary gradient training if handled naively.
How It Works
Instead of sampling z directly from the encoder distribution in a way that blocks gradients, express the sample as z = mu(x) + sigma(x) * epsilon, where epsilon is fixed external noise from a standard Gaussian. The random part is separated from the learned mean and scale, so backpropagation can update the encoder parameters.
Why It Matters
This makes latent-variable models trainable with standard neural-network optimization.
Where It Breaks
The gradient estimator works only for suitable continuous distributions and can still be noisy or poorly balanced.

Examples Used

  • A face image can be explained by latent factors such as pose, identity, and lighting.
  • A handwritten digit can be encoded into a small vector and decoded back into pixels.
  • If every digit image gets an isolated code island, reconstruction may work but sampling between islands produces nonsense.
  • If the decoder is too powerful, it may reconstruct using little information from z, causing posterior collapse.

Equations And Algorithm Moves

  • Choose prior p(z), decoder p_theta(x|z), and encoder q_phi(z|x).
  • Sample z through the reparameterization trick.
  • Optimize reconstruction likelihood plus KL regularization.
  • Generate by sampling z from the prior and decoding.
  • Choose a prior p(z), commonly N(0,I), an encoder q_phi(z|x), and a decoder p_theta(x|z).
  • Optimize the evidence lower bound: ELBO = E_{q_phi(z|x)}[log p_theta(x|z)] - KL(q_phi(z|x) || p(z)).
  • Use z = mu_phi(x) + sigma_phi(x) * epsilon, epsilon ~ N(0,I), so gradients pass through mu and sigma.
  • For a Gaussian encoder, compute KL to N(0,I) analytically from mu and sigma.
  • Train by maximizing ELBO or minimizing reconstruction loss plus KL penalty.
  • Generate by sampling z ~ p(z) and decoding x ~ p_theta(x|z).
  • The ELBO can be read as reconstruction reward minus KL cost: E_q[log p_theta(x|z)] - KL(q_phi(z|x) || p(z)).
  • Posterior collapse happens when the decoder explains x without using z, making q_phi(z|x) close to the prior and leaving the latent code nearly empty.

What You Should Be Able To Say

You should be able to explain a VAE as learning hidden codes that reconstruct data while staying sampleable from a simple prior.

L5 GANs

Open video

2h 32m · 72039 transcript words

Detailed Topic Explanation

GANs set up a contest. The generator tries to produce samples that look real. The discriminator tries to tell real samples from generated samples. The generator improves by finding ways to fool the discriminator. This avoids writing an explicit likelihood and can produce sharp samples because the feedback comes from whether samples look realistic rather than from pixel-by-pixel averaging. GANs replace a hand-written probability with a learned comparison game. The generator does not need to say how likely an image is. It only needs to produce an image that the discriminator cannot separate from real data. The discriminator becomes a moving measurement of what looks fake. This is useful when realism is hard to capture with a fixed formula. GAN training is distribution matching through classification. The discriminator asks: did this example come from the dataset or from the generator? If it can tell, it gives a learning signal. The generator asks: how should I change my samples so the discriminator classifies them as real? The loss is indirect because the generator is not told the correct image for a noise vector; it is only told whether the sample looks like it came from the same distribution.

The price is instability. The generator and discriminator learn together, so the target keeps moving. If the discriminator is too strong, the generator gets weak feedback. If the generator finds a narrow trick, it may produce limited kinds of samples, called mode collapse. GANs are important because they made implicit generation powerful, but they also show why adversarial training is hard to control. The contest is also the source of the trouble. The generator is not chasing a fixed target; it is chasing a discriminator that changes after every update. The discriminator can become too good and give little useful gradient, or the generator can find a narrow way to fool it. That narrow behavior is mode collapse: many inputs produce a small range of outputs. The minimax setup creates a moving game. The discriminator improves at finding current generator flaws. The generator improves at hiding them. At ideal equilibrium, generated samples and real samples are indistinguishable, so the discriminator cannot do better than random guessing. In practice, gradients can vanish when the discriminator is too strong, and the generator can collapse to a few high-scoring sample types instead of covering all modes.

Core Ideas

  • GANs learn an implicit generator without requiring a tractable likelihood.
  • The discriminator supplies a learned training signal by comparing real and fake samples.
  • Sharp samples can emerge because realism is judged distributionally.
  • Training can be unstable because both sides change during learning.
  • GANs learn by matching distributions through a classifier, not by reconstructing examples.
  • The discriminator is a learned loss whose definition changes during training.
  • Equilibrium means fake and real distributions are hard to distinguish, not that every sample is perfect.
  • Mode collapse is a coverage failure: sample quality can look high while diversity is low.

Approaches Taught

Adversarial Training

Problem
Some generators can make samples without giving a usable likelihood to optimize.
How It Works
Alternate two updates. First train the discriminator to output high scores for real data and low scores for generated samples. Then freeze or reuse that discriminator signal to update the generator so its samples receive high realness scores. The generator never sees a target image for each noise input; it only follows gradients from the learned judge.
Why It Matters
It supplies a learned realism signal and can produce sharp samples without pixel-wise averaging.
Where It Breaks
The target changes while training, so learning can oscillate, collapse, or stop giving useful gradients.

Discriminator As Learned Loss

Problem
Hand-written losses often reward blurry averages rather than realistic samples.
How It Works
Use the discriminator as an adaptive loss function. Instead of measuring pixel distance, the loss asks which features make generated samples distinguishable from real samples. As the discriminator improves, it changes the pressure on the generator, pushing it away from current artifacts and toward statistics that real data shares.
Why It Matters
The loss adapts to the data instead of measuring only fixed pixel distance.
Where It Breaks
The discriminator may focus on superficial clues and give feedback that does not match the desired notion of quality.

Examples Used

  • A fake-image detector gives feedback to an image generator.
  • Mode collapse occurs when many random inputs produce similar-looking outputs.
  • A face generator may learn one common face type that fools the discriminator but ignore many ages or lighting conditions.
  • A discriminator may focus on texture artifacts rather than high-level object correctness.

Equations And Algorithm Moves

  • Sample noise z and generate G(z).
  • Train D(x) high for real data and low for generated data.
  • Train G to make D(G(z)) high.
  • Monitor diversity and discriminator-generator balance.
  • Sample real data x ~ p_data and noise z ~ p_z.
  • Generate fake sample x_fake = G_theta(z).
  • Train D_psi to maximize log D_psi(x_real) + log(1 - D_psi(G_theta(z))).

  • Monitor both fidelity and diversity because discriminator loss alone can hide mode collapse.
  • At the ideal Nash equilibrium, p_g(x) matches p_data(x), so the best discriminator outputs 1/2 everywhere because real and fake are indistinguishable.
  • Mode collapse means many z values map to the same narrow set of x values, so sample quality can look high while distribution coverage is poor.

L6 Diffusion Models

Open video

2h 22m · 72846 transcript words

Detailed Topic Explanation

Diffusion models learn generation by first making destruction easy. Add noise to real data step by step until it becomes almost pure noise. Then train a model to reverse the process one step at a time. At generation time, start from noise and repeatedly clean it. This turns a huge generation jump into many smaller denoising decisions. Diffusion uses a training trick that gives the model a clear answer key. Start with a real example, choose a noise level, add known noise, and ask the network to predict the noise or the clean direction. Because the corruption is made by us, the target is known. The model practices repair at many noise levels, from nearly clean data to almost pure noise. Diffusion training creates supervised denoising examples from unlabeled data. Pick a clean example, pick a noise level, add Gaussian noise, and ask the network to recover the noise or the clean signal. The model therefore sees a continuum of tasks: at high noise it must infer broad structure, at medium noise it must decide missing content, and at low noise it must repair details. Generation reverses this learned repair process.

The training target is clear because the added noise is known. The model learns how to estimate or remove noise at different noise levels. Early steps decide broad structure; later steps refine details. Diffusion is stable compared with adversarial training, but sampling can be slow because many reverse steps are needed. Guidance and distillation are common ways to improve control or speed. At sampling time the direction reverses. Start from random noise and repeatedly apply the learned repair rule. The time or noise-level input tells the network what kind of repair is needed. High-noise steps decide broad layout because little detail remains. Low-noise steps refine texture and small structure. This makes training stable, but it creates a compute cost during sampling. The most common parameterization predicts epsilon, the noise that was added. Since x_t is built from x_0 and epsilon by a known formula, predicting epsilon also gives a way to estimate x_0 or the score direction. The time embedding is crucial because the correct denoising behavior changes with noise level. Sampling methods then decide how many reverse steps to take and how much randomness to inject at each step.

Core Ideas

  • Forward diffusion corrupts data with known noise.
  • Reverse diffusion learns many small denoising updates.
  • Noise level or time is an input because each stage needs different behavior.
  • Sampling trades compute for quality and control.
  • The noise target is known because the training process adds the noise itself.
  • Predicting noise, predicting clean data, and predicting score are related parameterizations of the same repair problem.
  • Time conditioning tells the network which denoising task it is solving.
  • Sampling quality depends on both the learned denoiser and the numerical reverse process.

Approaches Taught

Denoising Diffusion

Problem
Making a whole complex sample in one step is difficult and unstable.
How It Works
Create supervised pairs by adding known Gaussian noise to clean data at a sampled timestep. Train a network conditioned on the noisy input and timestep to predict the added noise, clean data, or velocity. At sampling time, start from Gaussian noise and repeatedly apply the learned reverse update to move toward clean data.
Why It Matters
Generation becomes a chain of small repair problems, which is easier to train than a one-shot generator.
Where It Breaks
Sampling can be slow because many reverse steps may be needed for high quality.

Guided Sampling

Problem
A generator must often obey a condition such as a class, text prompt, or desired property.
How It Works
During denoising, combine the normal data direction with a condition direction. In classifier-free guidance, run the same model with and without the condition, subtract the unconditional prediction from the conditional prediction, and scale that difference before updating the sample. The scale controls prompt or condition strength against diversity.
Why It Matters
It turns an unconditional generator into a controlled generator without changing the whole training setup.
Where It Breaks
Too much guidance can reduce diversity or create samples that satisfy the condition in brittle ways.

Examples Used

  • An image slowly becomes static during the forward process.
  • Static becomes a coherent image through repeated reverse cleanup.
  • At high noise, the model can only infer coarse layout such as face-like or room-like structure.
  • At low noise, the model mostly fixes edges, texture, and small artifacts.

Equations And Algorithm Moves

  • Sample clean x_0, time t, and noise epsilon.
  • Construct noisy x_t.
  • Train epsilon_theta(x_t,t) to predict epsilon.
  • Sample by iterating from x_T noise toward x_0.
  • Choose a noise schedule with alpha_bar_t controlling how much clean signal remains at time t.
  • Sample x_0 from data, t from a timestep distribution, and epsilon ~ N(0,I).
  • Construct x_t = sqrt(alpha_bar_t) x_0 + sqrt(1-alpha_bar_t) epsilon.
  • Train epsilon_theta(x_t,t) with mean squared error ||epsilon - epsilon_theta(x_t,t)||^2.
  • Estimate clean data during sampling using x0_hat = (x_t - sqrt(1-alpha_bar_t) epsilon_theta(x_t,t)) / sqrt(alpha_bar_t).
  • Iterate reverse updates from x_T ~ N(0,I) toward x_0, using a DDPM, DDIM, or other sampler.
  • The score view predicts a direction proportional to grad_x log p_t(x), which points noisy samples toward regions with higher data probability at that noise level.
  • Classifier-free guidance combines conditional and unconditional predictions: pred = pred_uncond + s * (pred_cond - pred_uncond), where s controls condition strength against diversity.

L7 Self-Supervised Learning

Open video

2h 31m · 73469 transcript words

Detailed Topic Explanation

Self-supervised learning makes labels out of structure already present in data. Instead of asking humans to label every image or sentence, the method hides, transforms, compares, or predicts parts of the input. The model learns representations because solving the pretext task requires understanding meaningful structure. For images, it may compare augmented views. For language, it may predict missing or next tokens. For video, it may use time and motion. Self-supervised learning asks the data to create its own questions. In contrastive learning, two views of the same item should lead to nearby representations. In masked prediction, the visible part should predict the hidden part. In both cases, the model is forced to represent something stable about the example because surface-level copying is made difficult. Self-supervised learning is not simply “no labels.” It creates labels from the data transformation itself. In contrastive learning, the label is that two views came from the same original example. In masked prediction, the label is the hidden part. In temporal prediction, the label may be what comes next. The design choice is what invariances the task teaches: crop invariance, color invariance, order sensitivity, local detail, or global semantics.

The goal is not always generation. Often the goal is a representation that transfers to later tasks with few labels. Contrastive learning pulls related views together and pushes unrelated views apart. Masked prediction asks the model to fill missing content. The failure mode is shortcut learning: the model may solve the artificial task using superficial cues that do not help downstream. The design of the task decides what the representation keeps. If crop, color, or noise changes are treated as irrelevant, the model learns to ignore them. That helps when those changes do not matter for later tasks. It hurts when the ignored detail is actually important. Self-supervision is therefore not label-free magic; it is a choice about which differences should count. Contrastive learning depends on positives, negatives, and a similarity score. The positive pair should share meaning; negatives should usually not share the same instance. Masked prediction depends on hiding enough content that context is needed, but not so much that the task becomes impossible. Both methods can fail if shortcuts solve the pretext task: for example, using image border artifacts, color statistics, or token frequency instead of semantic structure.

Core Ideas

  • Self-supervision creates training targets from unlabeled data.
  • Representations are judged by transfer, not only by pretext-task accuracy.
  • Contrastive learning compares positive and negative pairs.
  • Masked prediction forces the model to infer missing structure from context.
  • The pretext task defines what information is preserved and what information is discarded.
  • Contrastive methods learn by arranging representations in a space with near positives and far negatives.
  • Masked methods learn by reconstructing missing information from context.
  • Augmentations are assumptions about what changes should not affect meaning.

Approaches Taught

Contrastive Learning

Problem
A model needs useful features without class labels.
How It Works
Generate two augmented views of the same example and encode both into vectors. Pull their vectors close because they share identity, while pushing vectors from other examples away. A temperature-scaled softmax loss such as InfoNCE turns similarity scores into a classification problem: identify the matching view among many distractors.
Why It Matters
It teaches invariances, such as object identity surviving crop or color changes, from raw data.
Where It Breaks
Bad augmentations can erase the very information the representation needs to keep.

Masked Prediction

Problem
The model needs a self-made task that forces it to understand context.
How It Works
Corrupt the input by replacing selected words, patches, or regions with mask tokens or noise. Feed the visible parts through the model and train it to reconstruct the hidden content. The mask pattern controls the difficulty: too little masking allows local shortcuts; too much masking removes the context needed to infer the answer.
Why It Matters
This creates a dense training signal for text, images, and other structured data without labels.
Where It Breaks
The model may learn local fill-in tricks instead of broader meaning if the mask task is too easy.

Examples Used

  • Two crops of the same image form a positive pair in contrastive learning.
  • A masked word or image patch must be predicted from context.
  • A crop augmentation assumes the object identity remains even if part of the image is missing.
  • A language mask task forces the model to use surrounding words rather than a manual label.

Equations And Algorithm Moves

  • Choose an augmentation, mask, or prediction rule.
  • Encode inputs into representation vectors.
  • Optimize contrastive, reconstruction, or prediction loss.
  • Evaluate representations on downstream tasks.
  • Create two augmented views v1=a1(x), v2=a2(x) from the same example and treat them as a positive pair.
  • Encode views as h1=f_theta(v1), h2=f_theta(v2), often followed by a projection head.
  • Use a contrastive loss such as InfoNCE: -log exp(sim(h1,h2)/tau) divided by the sum over positive and negative similarities.
  • For masked prediction, replace selected input parts with mask tokens or noise and predict the original hidden parts.
  • Evaluate representation quality with frozen features, linear probes, fine-tuning, or transfer tasks.
  • Audit shortcuts by changing augmentations, negatives, mask rates, and downstream tasks.
  • InfoNCE forms a softmax over one positive pair and many negative pairs; the loss is low only when the positive similarity is larger than the distractor similarities.
  • For masked prediction, choose a mask set M, hide those parts from the input, and minimize reconstruction loss only on M so the model must use surrounding context.

Approaches Taught

Next-Token Pretraining

Problem
Language has no single label, but every text position supplies a next-piece prediction target.
How It Works
Tokenize text and train the transformer to predict token t+1 from tokens up to t. Each position supplies a target, so one document gives many losses. The model reduces loss by learning syntax, facts, discourse patterns, code structure, and common solution shapes, then generation repeats the same prediction loop autoregressively.
Why It Matters
This simple objective teaches syntax, facts, style, code patterns, and some reasoning habits at scale.
Where It Breaks
A good next-token predictor can still produce false, unsafe, or unhelpful answers.

Transformer Context Mixing

Problem
Each word or token must use information from far-away tokens, not only nearby ones.
How It Works
Represent tokens as vectors, add position information, and use masked self-attention so each token can gather information from allowed previous tokens. Stacked transformer blocks repeatedly mix context and transform each token vector. Caching key and value states during generation avoids recomputing the whole prefix every time.
Why It Matters
It gives language models a scalable way to use long context while training on many positions in parallel.
Where It Breaks
Cost grows with context length, and the model may still miss facts that require exact retrieval or calculation.

Examples Used

  • A web text corpus supplies billions of next-token examples without manual labels.
  • A code model learns syntax and common APIs by predicting code tokens.
  • Predicting code tokens teaches indentation, syntax, library names, and common programming patterns.
  • Predicting dialogue teaches conversational form, but not necessarily honesty or calibrated uncertainty.

Equations And Algorithm Moves

  • Tokenize text into ids.
  • Use transformer blocks to process context.
  • Predict next-token logits.
  • Train with cross-entropy over raw text.
  • Tokenize text into t_1,...,t_n and train on prefixes t_1...t_i with target t_{i+1}.
  • Compute hidden states h_i = Transformer(t_1...t_i) with causal masking.
  • Project h_i to logits over the vocabulary and apply softmax to get p_theta(t_{i+1}|t_<=i).
  • Minimize cross-entropy -log p_theta(true next token) over all positions and batches.
  • Generate by repeatedly sampling a token, appending it to context, and recomputing or caching transformer states.
  • Use post-training or retrieval when the desired behavior is not fully specified by next-token likelihood.
  • Causal masking sets attention to future tokens to minus infinity before softmax, so position i cannot read token i+1 while training.
  • Perplexity is exp(average cross-entropy); lower perplexity means the model assigned higher probability to the actual next tokens.

Detailed Topic Explanation

Semi-supervised learning combines a few labels with many unlabeled examples. The model uses labels to anchor the task and unlabeled data to learn the shape of the input distribution. The method tries to use both: labels anchor the meaning of classes, while unlabeled examples teach where the real examples lie and how decision boundaries should pass through the space. Semi-supervised learning uses a small labeled set to define the task and a larger unlabeled set to shape the decision boundary. The key assumption is that real data forms structure: examples in the same dense region or under small augmentations should often share labels. Pseudo-labeling turns confident predictions into temporary labels. Consistency regularization asks predictions to stay stable under harmless transformations.

The first principle is that unlabeled data is useful when its structure says something about the labels or target behavior. Pseudo-labeling, consistency regularization, and alignment losses all assume that nearby or transformed examples should have compatible predictions. The danger is confirmation error: wrong pseudo-labels can reinforce themselves, and alignment can erase real differences that matter. Distribution alignment adds another pressure. If the model predicts too many examples as one class, or if unlabeled data has a different balance than labeled data, training can drift. Alignment and consistency methods try to keep predictions stable under small changes and keep the output distribution reasonable. These methods help only when their assumptions match the data. Distribution alignment handles class balance and domain shift. If the model predicts too many unlabeled examples as one class, training may collapse toward that class. Core Ideas

  • Semi-supervised learning uses labeled and unlabeled data together.
  • Pseudo-labeling turns confident model predictions into temporary labels.
  • Consistency regularization asks predictions to survive harmless changes.
  • Distribution alignment tries to reduce harmful shifts between domains.
  • Labeled data defines label meaning; unlabeled data reveals the shape of the input distribution.
  • Pseudo-labels are useful only when confidence is meaningful.
  • Consistency regularization turns invariance assumptions into training pressure.
  • Distribution alignment can correct drift or create drift depending on whether its assumptions are true.

Approaches Taught

Pseudo-Labeling

Problem
There are many unlabeled examples and only a small labeled set.
How It Works
Train an initial model on the labeled set, run it on unlabeled examples, and keep high-confidence predictions as temporary labels. Train again using both real labels and pseudo-labels, often with confidence thresholds and augmentations. The method relies on the model being right often enough that extra practice helps more than it reinforces mistakes.
Why It Matters
It converts unlabeled data into extra practice when manual labels are scarce.
Where It Breaks
Wrong confident guesses can reinforce the model's own mistakes.

Distribution Alignment

Problem
The labeled set and unlabeled set may have different class balance or feature statistics.
How It Works
Estimate the model’s average predicted class distribution on unlabeled data and compare it with a desired prior or labeled-data distribution. Rescale or adjust predictions so the aggregate matches that target before using them in the loss. This can prevent class collapse, but only if the target distribution is a reasonable assumption.
Why It Matters
It prevents the model from treating unlabeled data as if it came from a different problem.
Where It Breaks
If the assumed distribution is wrong, alignment can force the model toward false labels.

Examples Used

  • A classifier trained on a few labeled images can use many unlabeled images from the same domain.
  • A model trained on synthetic images may need alignment before working on real camera images.
  • A classifier trained on few labeled cats and dogs can use many unlabeled pet images if predictions are stable under crop and color changes.
  • If unlabeled data contains foxes but labels only include cats and dogs, pseudo-labeling may force foxes into wrong classes.

Equations And Algorithm Moves

  • Train on supervised loss for labeled examples.
  • Generate pseudo-labels for confident unlabeled examples.
  • Apply consistency loss across augmentations.
  • Add alignment loss between source and target distributions.
  • Train an initial model on labeled pairs (x_l, y_l) with supervised cross-entropy.
  • For unlabeled x_u, compute p_theta(y|x_u) and create pseudo-label y_hat when confidence exceeds a threshold.
  • Apply augmentations a(x_u) and require p_theta(y|x_u) to match p_theta(y|a(x_u)) through a consistency loss.
  • Combine supervised loss and unsupervised loss with a weight lambda.
  • For distribution alignment, rescale batch predictions so their average matches a target class prior.
  • Monitor confirmation bias by checking whether pseudo-label errors increase over training.
  • A typical objective is L = L_supervised + lambda_u * L_unlabeled + lambda_align * L_alignment, with weights controlling how much unlabeled data influences training.
  • Entropy minimization pushes predictions on unlabeled examples toward confident class choices, but it is dangerous when the model is confidently wrong.

The model learns a function over 3D locations and viewing directions. For each point, it predicts density and color, which are combined along rays to match training images. A NeRF represents a scene as a continuous function rather than a mesh or voxel grid. Give the function a 3D point and a viewing direction; it returns density and color. A camera ray passes through many points in space. The rendered pixel is the accumulated color along that ray, weighted by how much density blocks or emits light. Detailed Topic Explanation

Multimodal models connect text, images, audio, video, or actions. The problem is that each modality has its own structure: text is token order, images are spatial grids, audio is time signals, and video is space plus time. A multimodal model must encode each form and then align them so a text prompt can refer to an image, an image can be captioned, or a video can be queried. Multimodal models ask how different kinds of data can share meaning. A caption and an image are not the same object, but they can refer to the same scene. Audio and video can describe the same event. A model needs a bridge so that information from one form can guide understanding or generation in another form. Multimodal learning builds bridges. Alignment methods place paired items, such as an image and its caption, near each other in a shared embedding space. Conditioning methods let one modality steer another, such as text guiding image generation or an image guiding a caption. The main challenge is binding: the model must connect the right words to the right visual regions or the right sounds to the right events.

The first-principles operation is alignment across representations. Contrastive learning can pull matching image-text pairs together. Cross-attention can let text guide image features or image features guide text. Generative multimodal systems can condition one modality on another. The failure mode is shallow matching: the model may learn common captions and visual shortcuts without grounding relations, counts, or detailed scene structure. Two main moves appear. Alignment puts paired items near each other in a shared representation space. Conditioning lets one modality directly steer another during generation, often through cross-attention. Both moves are powerful because they make text, images, audio, and other signals usable together. They also inherit bias from pairings in the data and can bind the wrong parts together. Contrastive alignment learns a shared space from positive pairs and negatives. Cross-attention conditioning lets features in one stream query features in another stream. Joint transformers may put all tokens from all modalities into one sequence, while dual encoders keep streams separate until a similarity score is computed. Each design trades speed, fine-grained interaction, retrieval quality, and generation control.

Core Ideas

  • Each modality needs a representation suited to its structure.
  • Alignment connects related items across modalities.
  • Contrastive losses and cross-attention are common alignment tools.
  • A multimodal model can retrieve, caption, answer, or generate across data types.
  • Alignment makes different modalities comparable in one representation space.
  • Conditioning lets one modality control generation or interpretation in another.
  • Fine-grained binding is harder than global matching.
  • Architecture choice controls whether modalities interact early, late, or repeatedly.

A generator needs to use information from another mode while producing its own output.
How It Works

It gives the generator a direct path to use outside instructions or context during generation.

The model can ignore the condition, overfit to it, or bind the wrong words to the wrong visual parts.

Detailed Topic Explanation

Parallelization asks how to make large models run fast enough. Some model families are naturally sequential, like autoregressive generation where token i depends on earlier tokens. Transformers allow more parallel training because all positions in a sequence can be processed together under a mask. Hardware efficiency depends on batching, memory movement, attention cost, and how computation is split across devices. Parallelization is part of the learning story because scale changes what methods are possible. A model may have too many parameters for one accelerator, a batch may be too large, or the training run may take too long. Splitting work across devices sounds simple, but every split creates communication: devices must exchange gradients, activations, weights, or partial matrix products. Large unsupervised models need many devices because the data, parameters, activations, and optimizer states can exceed one machine. But not every computation can be parallelized freely. Matrix multiplications can be split, batches can be split, layers can be split, and sequence positions can sometimes be processed together. Autoregressive generation remains sequential over output tokens because each new token depends on earlier generated tokens.

The first-principles issue is dependency. If one computation truly needs the result of another, it cannot be fully parallelized. If the dependencies can be masked, batched, or rearranged, hardware can do more work at once. This affects which generative models are practical. A mathematically good model may be too slow if it cannot use hardware well. Parallelization is therefore part of the method, not just implementation detail. Separate the bottlenecks clearly. Data parallelism copies the model and splits examples. Model parallelism splits weights or layers. Tensor parallelism splits large operations. Pipeline parallelism sends different microbatches through different layer stages. The right choice depends on memory, bandwidth, compute balance, and whether devices spend time working or waiting. The main bottleneck is often communication, not raw arithmetic. Data parallelism requires gradient synchronization. Tensor parallelism requires devices to exchange partial matrix results. Pipeline parallelism can leave devices idle if microbatches are not scheduled well. Model parallelism solves memory pressure but creates coordination cost. Good parallelization matches the split to the bottleneck: memory, compute, bandwidth, latency, or sequence length.

Core Ideas

  • Parallelism is limited by real dependencies in the computation graph.
  • Transformer training can process many sequence positions at once with causal masks.
  • Autoregressive sampling remains sequential at generation time.
  • Memory bandwidth and device communication can dominate runtime.
  • Parallelism is limited by real dependency structure, not just available hardware.
  • Data parallelism splits examples; tensor parallelism splits operations; pipeline parallelism splits layers.
  • Communication cost can erase compute gains.
  • Training can be parallel across known tokens, while autoregressive sampling is sequential across generated tokens.

Approaches Taught

Data And Model Parallel Training

Problem
Modern models and datasets are too large for one device to train alone.
How It Works
Split the work according to the bottleneck. Data parallelism copies the model on each device and averages gradients across batch shards. Model parallelism splits layers or parameters when the model does not fit on one device. Each split requires synchronization, so the gain depends on communication cost as much as compute cost.
Why It Matters
It makes large unsupervised and generative models trainable within practical time and memory limits.
Where It Breaks
Communication can dominate compute, and a poor split can waste hardware.

Pipeline And Tensor Parallelism

Problem
Even one forward pass may not fit or run efficiently on a single accelerator.
How It Works
Pipeline parallelism assigns different layer groups to different devices and feeds microbatches through them like an assembly line. Tensor parallelism splits large matrix multiplications across devices and combines partial results. Both methods reduce memory pressure, but they introduce bubbles, synchronization points, and numerical-equivalence checks.
Why It Matters
These methods attack memory and speed bottlenecks inside very large models.
Where It Breaks
Bubbles, synchronization cost, and uneven layer sizes can leave devices idle.

Examples Used

  • Training a transformer can compute losses for many positions in one pass.
  • Generating text one token at a time cannot fully parallelize across future tokens.
  • Training a causal transformer can process all positions in a known sequence at once with a mask, but generation must append one token at a time.
  • A model split across GPUs may run slower if the GPUs spend more time exchanging activations than computing.

Equations And Algorithm Moves

  • Represent computation as a dependency graph.
  • Batch independent examples and positions where possible.
  • Use masking to preserve causal correctness.
  • Split tensors or batches across devices when models are too large.
  • For data parallelism, copy model weights to each device, split the batch, compute local gradients, all-reduce gradients, then apply the same update.
  • For tensor parallelism, split a large matrix multiply such as XW across devices by columns or rows and combine partial outputs.
  • For pipeline parallelism, assign layer groups to devices and pass microbatches through stages to reduce idle time.
  • For sequence or context parallelism, split long sequence activations while preserving attention dependencies and communication for needed keys and values.
  • Estimate memory as parameters plus gradients plus optimizer states plus activations, then choose parallelism to fit the largest component.
  • Measure throughput, utilization, communication time, and numerical equivalence to ensure the split preserves the intended training update.
