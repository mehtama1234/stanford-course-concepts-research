Tokenization

Taking text and chopping it into numbered pieces so a computer can work with it. The computer reads these piece-numbers one at a time and learns patterns from them.

Everyday Problem
Imagine you want to teach someone English using flashcards, but they can only handle 10,000 different cards at once. If you make one card for every letter, they'll never learn the rules for combining them. If you make one card for every possible word ever written, you'll need 500,000 cards and they'll still fail on words they've never seen. You need cards that are reusable: small enough to cover everything, large enough that patterns emerge quickly.
First-Principles Reason
A computer can't read text the way your eyes do—it needs numbers. Text is infinite: new words, names, spellings show up all the time. So you pick a fixed list of chunks (usually 30,000–50,000 items) that act like LEGO bricks: you can build any sentence by stacking them. This list is called your tokenizer.
Math Underneath
A tokenizer is a table that maps each chunk of text to a number. 'Hello' might be number 42, 'world' might be 999. When you write 'hello world', the tokenizer turns it into [42, 999]. The trick is choosing smart chunks. Modern tokenizers use subword pieces: they find chunks that repeat across different words. The word 'unbelievably' becomes ['un', 'believ', 'able', 'ly'], maybe numbers [201, 456, 78, 23]. The piece 201 ('un') also appears in 'unable' and 'unlock', so the model learns that 'un' means the same thing in all three words. This reuse is the secret.

Embeddings

Taking a word (or a piece of an image, or a game state) and turning it into a list of numbers that sits at a specific point in a high-dimensional space. Similar words end up near each other in that space; different words are far apart.

Everyday Problem
You walk into a library where every book has only a number on its spine: 4129, 983, 7634. These numbers are arbitrary labels—you cannot tell if book 4129 is science fiction and 983 is a cookbook, or whether 4129 and 7634 are related. You have no way to find books like the one you just read, and no way to know which books often go on the same shelf.
First-Principles Reason
When computers process words, pictures, or actions, they start with arbitrary labels like 4129 or 'cat.' But to learn patterns—which words appear together, which game actions lead to winning, which images look similar—the computer must arrange these items in a space where closeness has meaning. Without that, the computer cannot smooth out its guesses when it gets feedback. It treats every item as completely separate.
Math Underneath
An embedding table is a huge grid of numbers. Each row holds a list of numbers (usually 768 of them) that represents one word. If you want the embedding for word 4129, you grab row 4129 from the table. The distance between two words is calculated by taking their number lists and multiplying them element-by-element and adding up the results—this is called a dot product. If the dot product is large, the words point in the same direction and are 'close.' Training nudges all these numbers so that words that appear together in sentences end up with large dot products, pulling their representations toward each other.

Position And Order

A set of numbers attached to each piece of data that tells the model what slot that piece occupies in a sequence or grid.

Everyday Problem
You hear two sentences: "dog bites man" and "man bites dog." Same three words, but they mean opposite things because the order is different. Now imagine a listener who hears all three words at once, jumbled in a cloud, with no sense of which came first. Without marking each word with its position, that listener cannot tell the two sentences apart.
First-Principles Reason
Modern AI systems called transformers work by comparing every piece of data to every other piece at the same time, all at once. This is different from older systems that read data one piece after another, where the order was automatic. When everything is compared in parallel, the system needs a way to know where each piece came from in the original sequence, or that information is lost forever.
Math Underneath
Each position gets a set of numbers (called a vector) built from repeating waves of different speeds. Position 0 might be [1.0, 0, 0.5, 0, ...], position 1 might be [0.84, 0.54, 0.38, 0.92, ...], position 2 might be [0.41, 0.91, -0.94, 0.75, ...]. The waves move at different rates: some change slowly (positions far apart look very different), some change fast (positions next to each other look similar). This pattern is then mixed together with the data the model sees.

Attention

A method that lets a system read multiple pieces of information and automatically decide which ones matter most for the current task, then blend them together in a specific way. If the system needs answer A, it pulls more from relevant information. If it needs answer B, it pulls more from different information.

Everyday Problem
You're trying to understand a sentence. Every word you read gives context, but not all words help equally. In 'The trophy would not fit in the suitcase because it was too big,' the word 'it' needs to figure out which noun it refers to—the trophy or the suitcase. Your brain does this fast: 'it' is near 'suitcase' but 'it was too big' makes sense if the trophy was the problem. You automatically weight the noun that makes sense harder than the one that doesn't.
First-Principles Reason
When a system processes text or data, each piece of output depends on multiple inputs, but not equally. A mechanism that can learn to rank inputs by relevance and combine them based on content—rather than using a rigid rule like 'always take the most recent' or 'always take an average'—lets the system adapt moment-by-moment. This solves the core problem: how do you decide what to pay attention to when the answer depends on what you're trying to compute right now?
Math Underneath
Each piece of input data gets turned into three learned representations: a query (a fingerprint asking 'what kind of information do I need?'), a key (a fingerprint saying 'what information do I contain?'), and a value (the actual information to pass forward). The query gets compared to every key using a dot product, which is a measure of similarity—larger numbers mean the fingerprints point in similar directions. These similarity scores are then normalized using a function called softmax, which converts raw scores into weights between 0 and 1 that add up to 1, making high scores much larger than low ones. Finally, each value gets multiplied by its weight and all weighted values are added together. The compact formula softmax((Q × K-transpose) / √(dimension)) × V captures this entire operation: the numerator computes how much each key matches the query, dividing by square-root of dimension keeps the scores stable, softmax turns them into weights that sum to one, and multiplying by V applies those weights to retrieve information.

Transformer Block

A repeating layer inside an AI system that lets information flow between different positions, updates each position by combining what it learns, and holds onto old information while adding new updates.

Everyday Problem
Imagine you're reading a long email on a phone screen that shows only one sentence at a time. You read "The bank is closed on Sundays." To understand what "bank" means here, you need to scroll back and see "The river ran past the old bank." Your brain is finite—you can't hold all the context at once. You need a system that repeatedly looks at the relevant parts, updates what you understand, and carries important ideas forward to the next thought. That's what the system inside an AI does when processing text.
First-Principles Reason
Understanding complex text or images requires multiple passes. On the first pass, you might spot that "bank" appears near "river." On the second pass, you notice grammar connects it to a verb. On the third pass, you link it to earlier context about geography. A single lookup doesn't build this layered meaning. You need a reusable recipe that you can repeat: look at what connects to what, reshape the information based on that connection, keep what you learned, and run again. That's why layers stack.
Math Underneath
A transformer block has four pieces that work together. First, multi-head attention mixes information: for each position, measure how similar it is to every other position using a dot product (the sum of multiplied pairs of numbers), then scale that result to keep numbers in a reasonable range, and use those similarity scores as weights to average the information at all those positions. This scaling prevents any one similarity from taking over. Second, a feed-forward network (a small learned function that runs separately at each position) reshapes the mixed information—like adding learned color to a black-and-white image. Third, residual connections (adding the original input back to the output at each step) preserve old information so it doesn't disappear when data moves through layers. Fourth, layer normalization (centering and rescaling the numbers) keeps all values in a comfortable range, which makes the training process (tuning the dials) stable and reliable. These four pieces fit together: mix → reshape → carry old state → keep numbers in range.

Pretraining

A computer learns to recognize patterns by reading through billions of examples of text, code, or images—none labeled with answers—before it's ever asked to do a specific job. Think of it like reading your entire school's library before taking a single exam.

Everyday Problem
You want to teach someone to write well. Paying experts to mark up essays is expensive and slow. But books, articles, and websites are everywhere. Someone who reads millions of words before writing learns rhythm, vocabulary, and style without anyone teaching it—they've absorbed it from examples.
First-Principles Reason
Good answers to specific questions are hard to get and expensive to label. Raw examples—text, images, video—are free and everywhere. A system that learns from raw examples first will need far fewer expensive labeled examples later. This is not a choice; it's the only way to scale.
Math Underneath
The model has millions of internal dials called weights. It makes a guess (next word, or what a fuzzy image should look like), measures how wrong it was, and turns the dials a little in whatever direction makes it less wrong on that example. It repeats this billions of times on different examples. The measure of wrongness is called loss—a single number. Calculus tells you which direction each dial should turn to shrink that loss. When you practice predicting the next word a billion times, the model absorbs structure like grammar and facts without anyone teaching it explicitly.

Fine-Tuning And Preference Learning

Taking a trained program and adjusting the millions of internal dials it tuned during initial training so that it reliably produces the exact outputs you need, not just plausible ones.

Everyday Problem
A chess program trained on game records knows the legal moves and plays reasonably, but doesn't know how to win against strong opponents. A student who memorizes textbooks can recite facts but fails exams because the test asks for understanding, not repetition. Both have learned patterns from examples, but those patterns solve the wrong problem. You need to point them at your actual goal.
First-Principles Reason
When a program learns from raw data, it discovers what shows up most often—which words sit next to each other, which chess moves are legal, which facts appear in documents. But 'most common' is not the same as 'what I want.' To fix this, you take a second step: show the program examples of the correct behavior for your specific task, along with feedback about whether it got them right. The program then adjusts its internal dials to get those specific examples right, which teaches it to prioritize your goal over statistical frequency.
Math Underneath
A program learns by adjusting dials to minimize 'wrongness'—a score that measures how far off its guesses are. Fine-tuning keeps the same program structure but changes what 'wrongness' means: instead of 'did I predict the next word correctly across billions of documents,' it becomes 'did I predict the next word correctly on my task's examples.' The adjustment method stays identical—tiny nudges in the direction that reduces wrongness—but the target is now your specific examples, not common patterns. Preference learning takes this further: when you have two outputs for the same input, one better and one worse, the program adjusts to make the better one more likely. This encodes a person's judgment—'I prefer this answer'—into the program's decision-making.

Reasoning Traces

A language model writes out intermediate steps before giving a final answer, so that each step builds on what came before and earlier work stays visible. Like doing a math problem on paper instead of in your head.

Everyday Problem
You're doing your taxes. If you jump straight to the total deduction, you'll miss something. But if you write down each category—medical, charity, work expenses—and add them up, you catch mistakes. The paper trail lets you look back and fix errors.
First-Principles Reason
Your brain can only hold a few things at once. We write things down on paper to remember them. A language model works the same way: it reads text one token at a time (a token is roughly a word or word-piece), and it has limited space to keep track of what it's read so far. When the model writes down intermediate results as new tokens, it can refer back to those earlier tokens instead of having to remember everything at once. It trades the time to write extra tokens for the ability to look back at earlier work.
Math Underneath
The model generates a longer sequence of tokens than a direct answer would need: [input, step1, step2, ..., stepN, final_answer]. Each new token is predicted based on all the tokens that came before it, using a learned pattern-matching system called attention. Attention asks: which earlier tokens are important for predicting this next token? When the model predicts step2, it can pay attention to step1 and let that earlier work influence what comes next. The extra tokens take more computation time, but they give the model more chances to use earlier work to build toward the answer.

Agents, Retrieval, And Tools

A cycle where a language model (a program trained to predict text) takes one action at a time, gets a result, and uses that result to decide the next action.

Everyday Problem
You ask a librarian a question about a book released yesterday. The librarian cannot answer from memory alone; she never read it. She walks to the shelf, checks the catalog, pulls the book down, reads the new information, returns, and answers you. Her training (what she studied before) is not enough. She needs to move through the world and gather information.
First-Principles Reason
A language model learns patterns by reading millions of examples during training. The patterns it learns are frozen once training stops. Real tasks require knowledge that did not exist during training: today's weather, current stock prices, what is inside a specific database, or the ability to change the world by booking a flight or sending an email. No amount of pattern recognition can know 'today's date' or 'what happened five minutes ago.' The model must step outside itself, retrieve live information, run code, or take real actions, then use those results to answer correctly.
Math Underneath
The model maintains a record of what it knows so far (starting with just the user's question). At each step t, it reads this record and outputs the name of a tool to call and what to ask that tool for. The tool executes and produces a result (observation o_t). The model adds this result to its record. At step t+1, it reads the expanded record and chooses the next tool. The record grows: record_{t+1} = record_t + [tool call] + [tool result]. This repeated cycle—read record, choose action, execute, add result—creates a chain that walks toward the answer. Each new result guides the next decision, narrowing down possibilities.

Evaluation

A systematic test that shows what an AI system can actually do — and where it breaks — across many different kinds of inputs and situations.

Everyday Problem
You hire a tutor for your child's math. The tutor solves every problem from the textbook perfectly. Then your child takes a real test with problems the tutor has never seen, and scores poorly. The tutor had memorized the specific problems, not understood the underlying math. You needed tests that covered the full range of real situations, not just the narrow textbook.
First-Principles Reason
Claims about what a system can do are just words until you test them against real situations. If you only watch the system handle cases you picked, you see a distorted picture — like judging a weatherman's skill by only testing him on sunny days. You must design tests that probe the places where failures are most likely. This forces you to ask hard questions: What does success actually mean? What are the edge cases where things break?
Math Underneath
A metric is a formula that takes outputs (what the model produces) and turns them into numbers or tables you can compare. For example, accuracy counts how many answers are right: accuracy = (number of correct answers) / (total answers). But one number throws away important details. A chatbot might score 85% on math questions but completely fail on logic puzzles; accuracy alone hides this difference. Better metrics split the score by type — one table for math, one for writing, one for reasoning. The truth: every number you report means you have deleted other information, and what you deleted is often as important as what you kept.

Policy

A decision rule that tells an agent: when you see this situation, pick an action using these odds. If the agent sees 'object on table,' the policy says 'push with 30% chance, lift with 50%, wait with 15%, look for better angle with 5%.' The agent samples from those odds and does one action.

Everyday Problem
You are arranging a dinner party. Guests arrive tired or energized based on the route they took, the people they talk to, and how much help you ask them to give. Each choice you make now—who sits where, what you ask someone to do—changes the mood and events that come next. You need a consistent way to decide what to do based on what you're seeing, not a different strategy for every possible table arrangement.
First-Principles Reason
When an action changes the world, you can't use one fixed answer for everything. The situation keeps shifting—each action you take makes a new situation. You need a mapping: a rule that looks at what you see right now and says what to do next. Without this, you have no way to tie observation to action or to improve by learning from what happens.
Math Underneath
The policy π(a|s) is a machine that takes in what you see (s) and outputs the odds of each possible action (a). Picture a glass table with 100 marbles—some red, some blue, some green—representing different actions. When you look at a situation and reach into the marble jar, you pull out 40% red, 50% blue, 10% green. That's a probability distribution: a ranked list of choices, each with odds attached. Why odds instead of one certain answer? Because the best move often depends on hidden things you can't see—like 'is the object fragile?' if you can only see its shape. By using odds, the agent hedges its bets and explores the world carefully. The math π(a|s) just means 'the odds of action a, given that situation s is true.'

Reward

A number you assign to an action or outcome that tells a learning system "this was good" or "this was bad." The system uses this number to learn which choices to make again.

Everyday Problem
You are teaching a dog to sit. The dog hears "sit" and tries something—maybe it crouches, maybe it stays still, maybe it jumps. If you only say "good" or "no," the dog doesn't know why. To learn, the dog needs immediate feedback: a treat right when it crouches (that was good), nothing when it jumps (that was not good). Without this feedback, the dog cannot tell which behavior caused the reward.
First-Principles Reason
Learning requires two things: trying different actions and knowing which worked. A system that tries actions but never gets told "that worked well" or "that didn't" has no way to know which ones to repeat. Reward fills that gap—it is the number that says "this action led to something I value." Everything in learning hinges on this signal: without it, a system is blind.
Math Underneath
One reward number per step tells you only how good that single moment was. But real choices have ripple effects: a small choice now might lead to big consequences later. To measure how good a choice truly is, you add up rewards from that moment forward. If step 1 gets a reward of 2, step 2 gets a reward of 5, and step 3 gets a reward of 1, then the total value of choosing in step 1 is 2 + 5 + 1 = 8. But future rewards matter less than immediate ones—a reward today is more valuable than a reward a year from now. So we shrink the rewards as they get further away: Total = 2 + 0.9 × 5 + 0.81 × 1. We use a multiplier (often written γ, the Greek letter gamma) between 0 and 1 that shrinks each future reward more than the last. This forces the system to care about what happens now, not just the distant future.

Credit Assignment

When you see an outcome, figuring out which choice from your past actually caused it so you can repeat the good choices and avoid the bad ones next time.

Everyday Problem
You bake a cake that comes out burnt. The mistake wasn't adding the wrong ingredient five minutes ago—it was setting the oven temperature wrong an hour earlier. By the time you see the burnt cake, the real culprit is buried in history. How do you know which step to change next time to bake it right?
First-Principles Reason
Everything that happens now is the result of a chain of choices stretching backward in time. If you blame or praise only the last thing you did, you miss the real causes. A system that learns needs a way to ask: which choice from steps or years ago actually created this outcome?
Math Underneath
Imagine a machine learning from rewards that come later. It needs a trick: weight rewards that arrive soon more heavily than rewards that arrive far in the future. We use a discount factor—a number slightly less than 1, like 0.99—that shrinks the importance of distant rewards. The return (total sum of future rewards) is: R_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + ..., where r is the immediate reward at each step, γ (gamma) is 0.99, and the power grows with each future step. This means the first future reward gets multiplied by 0.99, the next by 0.9801, and so on—recent rewards count more. The discount factor solves two problems: it mathematically shrinks distant rewards so learning focuses on nearby causes, and it matches intuition—a reward you get today matters more than one you'll get next year. Without discounting, adding up infinite future rewards gives infinity; with it, you get a real number the machine can actually use to learn.

Policy Gradient

A method for teaching a program to pick better actions by making the choices that led to good results happen more often, and making the choices that led to bad results happen less often.

Everyday Problem
You're learning to cook by trial: no one tells you whether to add salt or sugar first, you just taste the final dish and decide if it's good. How do you figure out which specific moves (stir fast or slow, high heat or low, add this ingredient before that) actually made the difference between a meal you'd eat and one you'd throw away?
First-Principles Reason
When you can try things and see what happens, the most direct path forward is to shift the odds: increase the chance your program picks actions that led to rewards, decrease the chance it picks actions that led to failure. You're not looking for one automatic action; you're learning to favor the ones that work.
Math Underneath
Take how likely your program was to pick a particular action (convert it to a logarithm to make the math simpler), then multiply that by how much better the result turned out compared to what typically happens in that situation. If an action gave a reward of 100 and the program usually gets 70 in that spot, multiply the log-likelihood by +30; if it gave 40, multiply by -30. Do this for every action in every attempt, then push your program's dials in the direction that makes high-multiplier actions more likely and low-multiplier actions less likely.

Actor-Critic

A system with two separate learned parts: one that decides which action to take next, and one that keeps score of how good that action turned out compared to what you'd normally expect from that situation.

Everyday Problem
You're learning to cook. After you make a dish and taste it, you need to know: did this recipe work because it's genuinely good, or did today's ingredients just happen to be fresh? You can't tell by comparing to your memory alone—some meals were good by accident, others were bad because you were tired. You need a steady measuring stick: a baseline that tells you what a 'normal good' tastes like from your current skill level.
First-Principles Reason
When you try an action and see what happens, you face two separate jobs: picking which action to try, and grading whether that action was actually wise. If you solve both jobs with the same system, they tangle. The grading system gets pulled off balance by random luck. Splitting them keeps the grading system stable and unchanging while the action-picker gets clearer, more accurate feedback.
Math Underneath
The actor—the action-picker—is a learned program that looks at the current situation and outputs a choice of what to do, then shifts its choices toward picks that earned high grades. The critic—the grader—is a separate learned program that looks at the current situation and predicts what the total future reward will be from here, and adjusts its predictions to match what actually happens. The critical move: take the actual reward you got, subtract the critic's prediction of a 'normal reward' for that situation, and you get the advantage—the pure credit that belongs to your action, stripped of luck from the state itself. The actor learns by moving toward actions with positive advantage.

Q-Learning

A method where a learning system builds a table (or list) of numbers: for each situation you could be in, and each action you could take, it stores one number that means 'if I take this action now and play smart from then on, how much total reward will I get?' Then whenever it needs to decide, it just picks the action with the highest number.

Everyday Problem
You're choosing between a restaurant dish you know you like and an unfamiliar special. The special might turn out amazing and lead to discovering a new favorite, or it could be bland and waste your meal. You have to choose right now without knowing how it will actually taste or how happy it will make you.
First-Principles Reason
When you're making a choice and the result won't come until later, you can't wait to see the outcome before deciding—you have to guess. The only way to guess smart is to split your thinking into two pieces: the reward you get right away (which you know), plus a guess about the reward you'll get later (which you estimate). By keeping these separate and adding them, you can compare choices fairly.
Math Underneath
The rule is written as Q(s, a) = E[r + γ·max Q(s', a')]. Here, s is your current situation, a is the action you pick, r is the reward that arrives right now, γ (called gamma, a number from 0 to 1) is how much you care about future rewards compared to immediate ones, s' is the next situation you land in, and max Q(s', a') is your estimate of the best reward waiting in that next situation. You plug in the real r, add it to your estimate of the future, and use that sum to update your guess about how good this action truly is.

Offline Reinforcement Learning

You have a pile of records showing what people or robots did in the past and what happened next. You want to learn a good strategy from that pile alone, without trying new things yourself.

Everyday Problem
A hospital has ten years of patient charts showing what doctors did and what happened to each patient. A lab wants to build an AI that learns from these charts to suggest treatments. The problem: the AI cannot experiment on real patients—it can only learn from what's already written down. It has no way to test a new idea or check if a rare treatment was actually good or just got lucky.
First-Principles Reason
When you learn only from old records, you see the world through decisions that were already made. If nobody in the records ever tried something, you have no proof it exists or whether it works. Learning from history alone leaves blind spots: the learner cannot trust its own guesses about actions it never saw actually happen.
Math Underneath
The real problem is a mismatch between the data and the strategy you want to learn—call it distribution shift. Imagine a dataset where doctors chose Drug A for symptom X a hundred times (and it worked most of the time) but Drug B only five times (and it worked all five times). A naive system might think Drug B is magical. But five successes could be pure luck or hidden differences in the patients—we cannot tell. Smart offline methods solve this by (1) refusing to trust rare actions, shrinking down their estimated value, or (2) forcing the learned strategy to stay close to what the data actually did. Both add a penalty term to the learning update: when the system wants to choose an action the data rarely contained, the penalty pushes back.

Model-Based Reinforcement Learning

Building an imaginary copy of how the world works, so you can predict what happens before you act.

Everyday Problem
Imagine teaching a friend to bake bread for the first time. Trial-and-error takes all day: they mix, bake, the crust burns, they adjust, try again, wait for it to cool, adjust again. By evening they've wasted flour and spent five hours. But if they understood the rules first—'if oven is hotter, crust browns in half the time; if dough sits longer, it rises more'—they could predict the result before spending an hour baking. They'd waste less flour and get it right faster.
First-Principles Reason
The world doesn't tell you what happens after you act—it just happens. If you could predict the outcome before you commit, you'd make better choices. A learned model gives you that prediction: 'if I do this, the world will respond that way.' Then you can test out actions in your head instead of only learning by failing in reality.
Math Underneath
A dynamics model is a program you train to complete this sentence: 'Given where I am now (state) and what I choose to do (action), the world will look like this next' (next state). The formula s_{t+1} = f(s_t, a_t) + noise is just that in symbols: the state after the next step is some function f applied to your current state and action, plus randomness (because the world is never perfectly predictable). Once you have this model, you can chain predictions: imagine picking action 1, seeing the predicted state, picking action 2, seeing the next predicted state, and so on down a whole sequence. Then you pick the sequence your model predicts will be best.

Exploration

Trying actions specifically to learn something new, even when you're not sure they'll work right now. In AI learning: picking actions that test unknown territory, not just the one that seems best today.

Everyday Problem
You order the same dish at a restaurant every visit because you know you like it. Three pages of menu remain untouched. The menu has a pasta special that's better than anything you've tasted, but you'll never know because you never look. Sticking with what worked yesterday keeps you from discovering what could work better.
First-Principles Reason
The world hides useful information. Some actions only pay off over time or teach you something crucial that unlocks future rewards. If you only ever pick the action that looks best today, you never gather the evidence to spot genuinely better paths. Learning means understanding the terrain; understanding requires testing ground you haven't checked.
Math Underneath
Exploration changes how a learning system picks actions by adding three types of signal: randomness (pick a random action instead of the best one, on purpose), uncertainty bonus (boost the score of actions you haven't tested much, mathematically), or surprise scoring (reward actions that break your current predictions about how the world works). At the core: the system maintains a probability distribution—a ranked list saying "pick action A with 40% chance, action B with 30% chance, and so on." Randomness increases the chance it picks non-obvious actions. Uncertainty bonus adds a number to each action's score; that number gets bigger the less the system has tested that action, mathematically pushing toward unknowns. Surprise scoring measures how different reality was from what the system predicted and rewards actions that create big differences.

RL For LLMs

A way to teach an AI language model to improve its answers by telling it which complete responses were good or bad, rather than showing it every correct word ahead of time.

Everyday Problem
Imagine teaching a child to cook. You taste the final dish and say 'delicious' or 'this needs salt,' but you never watched their hands during cooking. The child must figure out which of their hundreds of choices—how long to stir, what heat to use, when to add salt—led to that bad taste. Feedback arrives only at the end, not step by step.
First-Principles Reason
A language model writes text by choosing one word at a time, dozens or hundreds of words in a row. When you give a reward score only for the final answer, the model faces a puzzle: 'Which earlier words I chose made this ending good or bad?' This problem—figuring out which of your past choices led to a reward that arrives at the end—is the core challenge in this kind of learning.
Math Underneath
Think of each word choice as a decision, and a whole response as a path of decisions. A reward score measures the final result (like: +1 if the math answer is right, 0 if wrong). The model's strategy is its probability over which word to pick next, given all the words so far. To improve, the model learns to boost the probability of words that showed up in high-reward responses. Technically, the model calculates a score for how wrong each word choice was (its log-probability), multiplies that score by the reward that eventually came from that word, and then nudges the internal numbers (weights) to make high-reward words slightly more likely next time. Why nudging? Because small updates in the direction of reward improve performance while keeping the model close to what it already learned.

Diffusion

A method for generating images or other data that works backwards from random noise: the program learns to gradually clean up pure randomness into something coherent, one tiny improvement at a time, by learning what direction to nudge each pixel.

Everyday Problem
Imagine you need to paint a completely new, realistic painting. You can't just decide all millions of pixel colors at once—your brain would freeze. Instead, you start with rough shapes and gradually refine them: is the lighting right here? Should this edge be sharper? With each tiny decision, the painting gets better. The question is: how do you teach a computer to make those tiny, local refinement decisions instead of trying to jump straight from blank canvas to finished masterpiece?
First-Principles Reason
Any system that needs to create something complex faces this hard truth: trying to decide everything at once almost always fails because there are too many possibilities and they depend on each other. But if you break the problem into many small steps—each one asking only 'how is this slightly better than before?'—then each step is small enough to learn from examples and verify that it's actually working.
Math Underneath
The forward process corrupts a clean image step-by-step: at each step you mix in a bit more random noise using the formula x_t = sqrt(1 - β_t) * x_{t-1} + sqrt(β_t) * noise, where β_t is a number that controls how much noise to add and gets bigger as you go forward. The reverse process learns to undo this: the program trains on clean images that have been corrupted with noise, learns to predict how much noise is currently mixed in, and then removes it. Mathematically, you train a neural network (a program with millions of tunable dials) to estimate the noise, then subtract it back out: x_{t-1} = (x_t - sqrt(β_t) * predicted_noise) / sqrt(1 - β_t). The program learns by doing this thousands of times on different images, comparing its noise guesses to the actual noise that was added, and adjusting its dials to get better.

Score Matching

A way to teach AI systems to figure out which direction to move in when they have a messy, broken sample, so they can gradually turn it into something real. The system learns by looking at a landscape where peaks represent likely, real things—and it learns to feel the slope at any point and move uphill.

Everyday Problem
You are lost in fog on a mountainside at night. You cannot see the whole landscape, but you can feel the slope beneath your feet right now. Each step, you sense whether ground rises or falls. The question: how do you learn to feel the slope correctly, even though no one ever showed you the whole map?
First-Principles Reason
Describing every possible real data point directly is nearly impossible—the space is too vast. But at any single point, there is a simple question: which nearby direction has more real data points? That local direction is far easier to learn than mapping everything. When you want to generate data, you always start in the noise and need to move uphill; so learning these local directions is how generation actually works.
Math Underneath
The score is the gradient of log probability: if you think of likelihood as a hill—where higher means more probable—then the gradient is the uphill direction. In symbols: score = ∇ log p(x). Here p(x) is 'how likely this sample is under real data', log p(x) makes the number easier to work with (logarithm), and ∇ means 'the direction that changes fastest in all directions.' To learn it in practice: take real data, add known noise to corrupt it, then train a neural network (millions of dials) to predict exactly what noise to subtract at each step. This trick is called denoising score matching.

Flow Matching

A method where a model learns to draw arrows through space—each arrow points in a direction and has a speed—such that if you follow those arrows starting from pure random noise, you end up at real data like a photograph or a piece of text. The model learns these arrows by watching examples of how to travel from messy randomness to clean data.

Everyday Problem
Imagine you're guiding someone through a completely dark mansion they have never entered. They start at a random spot on the property (representing noise) and need to reach the treasure room (representing real data). You can't just describe what the room looks like from far away. Instead, you have to leave signs at every inch of ground: turn left here, walk forward 10 steps, climb stairs there. Each sign includes both a direction and a distance. Your visitor follows the signs step by step and arrives at the treasure.
First-Principles Reason
To make a computer generate something complex and realistic, you need a smooth path from simple to complicated, not a single giant leap. Random noise is simple—just static fuzz. Real data (images, text) is complex—billions of organized pixels or precise word choices. A continuous path with learned directions at every spot lets you gradually change from fuzz into something real, like following breadcrumbs through a forest instead of teleporting across it.
Math Underneath
A vector field is an instruction set: for every location in space and every moment in time, it says 'point this way and move at this speed.' In flow matching, the model learns a mathematical function—called v_theta, where theta represents the millions of tuning dials—that takes any location x and any time t and outputs a direction-and-speed arrow. The model trains by measuring how wrong its arrows are: it computes the squared difference between what its arrows predict and what the true path from noise to data actually needs. This squared-difference score is called an L2 loss. The training process nudges the dials to make this loss smaller.

Guidance

A way to point a program that makes pictures or text in the direction you want. The program naturally creates plausible things—a bear might look realistic but forget the book you asked for. Guidance adds a nudge at each step of creation that says: "include the book," so the final result both looks real and matches your request.

Everyday Problem
You ask a friend to draw a teddy bear reading a book. They return with a beautiful, realistic bear—but no book. The drawing is skillful, and everything about the bear is correct, but it completely missed the second half of what you asked for. You need the bear to stay realistic and skillful while actually including the book.
First-Principles Reason
A program that generates images learns by studying millions of real pictures. It becomes very good at making a realistic bear, a realistic forest, or a realistic person. But 'realistic' and 'what you asked for' are not the same thing. When you add a request—like 'bear reading a book' or 'sunset in winter'—the program faces a conflict: keep everything looking natural and real (based on what it learned), while also satisfy your specific request. There is no single fixed rule that works for every request. You need a way to gently push the creation process toward your request at every single moment while it is building the image.
Math Underneath
Image creation happens step by step: the program starts with noise and gradually shapes it into a real image by predicting which way to remove the noise. Guidance changes this prediction by adding information from a score—a number that measures how well the current partial image matches your request. Imagine the program wants to move in direction A (based on what it learned), but your request says move in direction B. Guidance computes direction B by asking: "If I changed this partial image a little, would it match your request better?" Then it blends both directions together using a weight. The final move is: original direction A, plus (weight times how much to move toward direction B). If the weight is too small, the program ignores your request. If it is too large, the image looks distorted and unnatural because the program is being forced too hard against what it learned.

Latent Space

A smaller coordinate system—like a shopping list instead of a whole product—where the model stores the useful pieces of data instead of keeping every raw detail. A computer that learns to spot dogs in photos doesn't need to remember every pixel value; it only needs a few numbers that say 'has four legs', 'pointy ears', 'brown fur'. That's latent space: a list of the key features that matter.

Everyday Problem
Imagine trying to describe a photo by listing every single color value of every pixel—millions of numbers. Your friend's brain doesn't do that. It quickly notices 'sunset, beach, person standing in sand' and remembers just those main points. A computer working with every pixel runs into the same wall: too much data to move around, most of it telling you things you already know. The computer wastes time and memory on noise.
First-Principles Reason
Raw data is bloated. A photo has 196,608 pixel values; a few key facts—'outdoor scene, warm tones, person present'—could sum it up in maybe 50 numbers. Computing with the full data is slow and wasteful. If you find a smaller set of numbers that keeps all the important patterns while ditching the noise, the computer runs much faster and learns what matters rather than drowning in surface detail. This is pure economics: do the compression work once, then operate on the smaller version forever.
Math Underneath
An encoder is a program—a set of connected layers, each with adjustable dials (weights)—that takes raw data and outputs a short list of numbers. A decoder is another program that takes that short list and reconstructs something close to the original. If your input x is a photo and z is the short list, the encoder computes z = f(x) and the decoder computes x_reconstructed = g(z). During training, if the decoder's reconstruction is wrong or blurry, both programs adjust their dials so the short list z carries better clues about what the original photo contained. The squeeze through z (the bottleneck) forces the encoder to throw away noise and keep only structure.

Vision Transformers

A program that divides an image into small square sections, turns each section into a list of numbers, and then lets every section directly compare itself to every other section to figure out which ones matter for its understanding—doing all this comparison in a single pass instead of gradually spreading information through layer after layer.

Everyday Problem
When you look at a photo to spot if a person is smiling, you're not just looking at the mouth. You glance at their eyes, the corners of their face, how their cheeks sit. All those details spread across the image. If your eye could only focus on tiny patches at a time without seeing how far-away parts connect, you'd miss the full picture of the smile.
First-Principles Reason
Images work because shapes, colors, and textures in one place mean something only when linked to distant parts. A face's emotion lives in the relationship between eyes, nose, and mouth—scattered across space. A cat's paw only looks like a paw when connected to the leg it's attached to. Any image-understanding system that looks only at local neighborhoods will miss these connections and fail to recognize what's actually in the picture.
Math Underneath
Slice the image into small rectangular pieces (each maybe 16×16 pixels). Write each piece as a list of numbers. For every piece, calculate how similar it is to every other piece by multiplying the numbers in one list by the numbers in another and summing the result (this measures how much they match). Shrink these scores by dividing by a fixed amount so the numbers stay reasonable. Run these scores through a function that turns them into percentages that add up to 100%. Now, for each piece, add up all the other pieces' number-lists, weighting each one by its percentage. Each piece's result is now a blend of information from the entire image, computed in one step.

Scaling Laws

When you give an AI system more examples to learn from, more computing power, or larger internal structures—its ability to make correct predictions improves in a way you can measure and predict ahead of time.

Everyday Problem
You're building a system that recognizes faces in photos. You can improve it by writing smarter code, but also by showing it more photos and letting it practice longer. Your budget is limited. Should you spend money on faster computers, buy more photos, hire people to label more data, or split the budget? You need a concrete way to predict: which choice gives the most improvement per dollar spent?
First-Principles Reason
Any learning system has real limits: computing power costs money, time costs money, and collecting examples costs money. Imagine you're teaching a person to recognize dog breeds. If you have zero photos and unlimited time, adding more time doesn't help. If you have millions of photos but a slow brain, adding more photos doesn't help either. A learning system works the same way—it always hits one bottleneck first. When you give it more of whatever it's bottlenecked on, abilities jump forward. When you give it more of what isn't bottlenecked, nothing changes. The system reveals which limit is tightest right now, and what happens when you loosen it.
Math Underneath
You collect data from experiments: train on 100 million examples, measure how often predictions are wrong; train on 1 billion examples, measure again; train on 10 billion, measure again. Plot these three points on a graph—horizontal axis is how many examples, vertical axis is how often the system is wrong. The points form a curve. That curve usually follows a simple rule called a power law: if you multiply the examples by 10, the error shrinks by a fixed percentage (say 20% or 30%, not 1%). The curve lets you predict: if I buy 100 times more examples, my error should shrink by roughly that fixed percentage three times in a row. Why does this pattern show up? Because when a system learns something new, it needs roughly twice as many examples as the last harder thing it learned—that compound effect naturally creates this smooth curve.

Generalization

A program learns to solve a problem on one set of examples, but can it handle a completely different set it has never seen? That's generalization—when learning transfers to new cases, not just the ones used during training.

Everyday Problem
You memorize every question and answer in a practice test the night before an exam. Tomorrow, the real exam has different questions. You freeze because you learned the *answers*, not the *method*. Your memorized knowledge doesn't work on anything new.
First-Principles Reason
Any learner (human or computer) faces a hard fact: the past is only a sample. You train on some examples, but the world will serve you new cases you've never encountered. If your learning just picks up accident details in the training examples—quirks that happen to be there but won't appear again—it breaks when those accidents change. The only way to make progress is to find stable structure: the patterns that stay true across both old and new cases.
Math Underneath
Generalization measures the gap between training error (how wrong the program is on examples it learned from) and test error (how wrong it is on brand-new examples). We want small test error—that's what matters in the real world—but we only see training error during learning. The gap widens when a program locks onto noise or quirks unique to the training set instead of the core pattern. To stay safe, we add a penalty term to the loss that punishes overly wiggly solutions, and we split data into three groups: a training set to learn from, a validation set to tune decisions on, and a test set (held back completely) to measure honest performance on truly new data.
