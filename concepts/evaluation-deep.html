Evaluation — how grading the same answer four ways gives four different scores

You read that a reasoning model scored 44 percent on grade-school math. But that same model's exact answers also scored 0 percent, 64 percent, and 40 percent on the identical 25 problems — depending only on how the grading was done. This is the crux: the way you measure an answer is not transparent reporting, it is a design choice. Strict measurement can hide real progress; loose measurement inflates it. Here is what happened when we graded one model four different ways, why the grader is a design decision with teeth, where this idea reappears in training reasoning models directly with rewards, and the trap of trusting a single leaderboard number.

1 · The problem — the same answer, graded three different ways, is suddenly three different scores

When you train a model to answer a math problem, you need a signal: did it get it right or wrong? But 'right' is not always clear. If the model writes 'The answer is 42 because 12 plus 30 equals 42', should that score as correct? What if it writes '12 + 30 = 42. The answer is 42'? What if the actual answer is 42 but the model wrote it twice in the middle of a rambling explanation, never in a clear final form? The choice you make — does the right number have to appear in a boxed final line, or anywhere at all? — is a grading rule, and it can change the score from 0 to 64 percent on the same answers. Once you pick a grader, you are implicitly picking what kind of model you are training: a model optimized for a loose grader behaves very differently from one optimized for a strict one.

So the stakes are real: how you define success shapes what the model learns to do.

2 · The reframe — treat the grader as part of the experiment

Instead of picking one grader and never questioning it, do something stranger: fix the model's outputs, then score them multiple ways. Take a single run of the model (the same 25 problems, the same 25 solutions). Then ask: what if we grade by rule A? Rule B? Rule C? Watch the score move. This turns the grader from an invisible assumption into a visible variable. You see that a 'good score' is not a fact about the model — it is a fact about the grader and the model together. And you see that a difference of 20 percentage points between graders means the score is slippery, not trusted.

The discovered fact: the SAME model on the SAME 25 problems scores 0%, 64%, 40%, or 44% depending only on the grading rule. A lenient grader (number anywhere) inflates the score to 64%; a strict one (exact string match) collapses it to 0%; a careful middle ground (boxed final answer) lands at 44%. This is not noise — it is the definition of 'correct' changing underneath.

4 · Why the grader is a design choice with real teeth

Each grader embodies a different assumption about what 'solving the problem' means. Exact string match says: the model must reproduce the reference solution word-for-word, no improvisation. It is rigorous but brutal — it misses a correct answer phrased differently. 'The number appears anywhere' is permissive: if the right number sits anywhere in the output, call it correct, even if the reasoning was confused or the answer buried in junk. It is lenient but easily gamed — the model can strew correct numbers throughout and get credit even if it has no idea why they are right.

The careful middle (final boxed answer, parsed) says: we trust the model to mark what it thinks is its answer, and we read it carefully. It is neither mechanical nor loosey-goosey. It asks: did the model converge on the right number as its intended final output? This is closer to how a teacher would grade on paper. The 44 percent that rule gives is lower than 64 but higher than 0, and it is the trustworthy one: it credits real progress while not being fooled by a stray correct number the model happened to emit while flailing.

When you train a model by reward, you are implicitly choosing a grader. A reward model that gives +1 for 'the right number anywhere' will push the model toward emitting the answer many times and hedging (44% of output is just throwing numbers at the wall). One that rewards a careful boxed answer will push the model to be crisp and decisive. The grader is not transparency — it is architecture.

5 · The one real weakness — no grader is neutral and all require some choice

The problem is that 'correct' has no view from nowhere. A different benchmark (not GSM8K; say, physics problems with multi-digit answers) might show different spreads between the graders. A different model (one that rambles more, or one that rarely emits the same number twice) might flatten or widen the 0-to-64 gap. And the temptation to cherry-pick — publish the test with the generous grader if your model does well under it, switch to the harsh one if a competitor's model doesn't — is not hypothetical, it is how many benchmarks get gamed over time. There is no grader that works for all problems and all models; the right choice depends on what you care about in real use.

6 · The surprise — this is why reward design in reinforcement learning for language models is so hard

Take this one-grader-four-scores insight and run it forward. When you train a language model with reinforcement learning (RL), you give it a reward signal: right answer, reward plus-one; wrong answer, reward zero. But 'wrong' is the grader rule in disguise. If your reward is 'the right number appears anywhere', the model will learn to emit the answer over and over and hedge. If your reward is 'only the final boxed answer counts', the model learns to be decisive. And if the reward is a strict parser for exact word-for-word match, the model learns to mimic the training data exactly and stops generalizing. This is why training a reasoning model with RL is so fragile: the reward you choose does not just measure progress, it fundamentally shapes what the model becomes. A generous reward leads to output collapse and gaming; a harsh one leads to memorization or giving up. This is also why imitation learning (supervised fine-tuning on human examples) is safer: a human showing the model good solutions embeds a subtle grader ("think like a person would think") that is richer and harder to game than a simple scalar reward. And it connects to why adding intermediate reasoning steps helps: a model that writes out steps is easier to grade at each step, so you can shape the reward more carefully.

7 · Where it is used in practice — understanding that how you grade shapes what the model learns

When training a model to solve math problems with reinforcement learning, the choice between 'reward if the right number appears anywhere' versus 'reward only if it is the final boxed answer' will train radically different models. Benchmark leaderboards report a single accuracy number, but that number depends entirely on how answers are graded—strict word-for-word match or permissive 'contains the right idea'. Evaluation frameworks for coding assistants choose whether to grade on 'produces working code that passes tests' or 'produces code that matches the reference style exactly'.

When you fix the model's outputs and grade them multiple ways, you see the same answers score differently based only on the grading rule. A loose grader (number appears anywhere) inflates the score and pushes the model to hedge and repeat answers. A strict one (exact word-for-word match) collapses the score and trains the model to memorize. A careful middle ground (final answer parsed honestly) gives a trustworthy signal. The grader is invisible until you expose it; then you see it is a design choice with real consequences for what the model learns to do.

The way you measure success is not transparent reporting—it is architecture, because the reward signal the model trains on implicitly encodes what 'correct' means, fundamentally shaping the model's behavior.
