Agents, Retrieval, And Tools

Putting a model in a loop where it can look things up, call tools, and react to results.

What real-world problem is this about?

The problem is that many tasks need current facts, external actions, or checks the model cannot store in its weights.

Why does this problem exist?

A useful system often needs perception, memory, action, and correction, not only prediction.

What is the mathematical idea underneath?

The loop is state, action, observation, update. At each step the model chooses an action based on the current context, then new evidence changes the next context.

Why is this concept important?

It connects language models to search, code execution, databases, browsers, and multi-step workflows.

What breaks without it?

The model is limited to stale internal knowledge and cannot verify or change the outside world.

Naive Starting Point

Start with the simplest version: The problem is that many tasks need current facts, external actions, or checks the model cannot store in its weights. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because a useful system often needs perception, memory, action, and correction, not only prediction. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Agents, Retrieval, And Tools: The loop is state, action, observation, update. At each step the model chooses an action based on the current context, then new evidence changes the next context. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Agents, Retrieval, And Tools, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: a model asked for today's weather cannot answer reliably from its weights alone. It needs to call a weather API, read the result, and then respond. CME295 Lecture 7 frames agentic LLMs exactly this way: until now the LLM was on its own; now the goal is to let it interact with the outside world and other systems through RAG, tool calling, and agents.

What the Lectures Emphasize

The agentic LLM lecture emphasizes a shift from standalone prediction to system interaction. It recaps reasoning models, then moves to RAG, tools, and agents as practical techniques for connecting an LLM to external knowledge bases and actions. That makes the agent loop a systems idea built around observation, action, and updated context.

Common Misunderstanding

A common misunderstanding is that an agent is just a bigger prompt. The important change is not wording; it is the loop. The model chooses an action, receives an observation, updates its context, and decides again. That loop creates new failure modes: bad retrieval, tool misuse, stale observations, and compounding errors.

How to Recognize This in a New Paper or Model

In a new paper, recognize agentic structure whenever a model is wrapped in retrieval, tools, environment actions, memory, planning, or observation feedback. The shared primitive is closed-loop search: prediction becomes one part of a larger act-observe-update cycle.

Connected Concepts

The same primitive reappears near policy, retrieval, planning. Across the three courses, the shared pattern is search, composition, feedback: choose what to keep, how to move, what feedback means, or how to measure whether the behavior really improved.
