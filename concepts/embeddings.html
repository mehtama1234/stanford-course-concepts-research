Embeddings

Learned coordinates that let a model compare things by arithmetic.

What real-world problem is this about?

The problem is that IDs like 17 or 9421 do not say what a word, patch, state, or action means.

Why does this problem exist?

A learning system needs a space where similar things can be placed near each other and useful directions can be adjusted by training.

What is the mathematical idea underneath?

An embedding table maps each item to a vector. A vector is just a list of numbers; training moves those numbers so useful relationships become easier to compute.

Why is this concept important?

Embeddings turn symbols into a shared workspace for attention, prediction, retrieval, and generation.

What breaks without it?

The model would treat related symbols as unrelated labels and could not smoothly share what it learns.

Naive Starting Point

Start with the simplest version: The problem is that IDs like 17 or 9421 do not say what a word, patch, state, or action means. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because a learning system needs a space where similar things can be placed near each other and useful directions can be adjusted by training. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Embeddings: An embedding table maps each item to a vector. A vector is just a list of numbers; training moves those numbers so useful relationships become easier to compute. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Embeddings, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: a tokenizer may assign "cat" the ID 4129 and "dog" the ID 983, but those numbers do not mean cat and dog are related. An embedding replaces each arbitrary ID with a learned vector. During training, contexts that use animals, objects, actions, or visual features in similar ways push their vectors into useful arrangements. In the CME295 recap, tokenization is followed immediately by representation: once text is divided into atomic units, the next step is to represent those tokens as embeddings. CME296 uses the same idea more geometrically when it talks about moving from discrete representation to continuous space.

What the Lectures Emphasize

The language course emphasizes embeddings as the first learned representation after tokenization: the model has pieces, but it still needs meaningful numerical coordinates. The diffusion course emphasizes the same representational move in continuous generative dynamics, where position in space and movement through space matter. The RL course uses vectors more as function-approximation machinery. Together they show that embeddings are not only word lookup tables; they are the general idea of making similarity and change computable.

Common Misunderstanding

A common misunderstanding is that an embedding directly stores a human-readable definition. It does not. It is a bundle of learned numbers useful for the model's next operations. Two vectors being close does not mean they share one obvious human property; it means the training objective made their coordinates useful in related computational situations.

How to Recognize This in a New Paper or Model

In a new paper, recognize embeddings whenever raw items are moved into a learned coordinate system before the main algorithm starts. The object may be a token, image patch, state, action, document, preference, or latent variable. The shared primitive is geometry: turn identity into position so distance, direction, averaging, and retrieval can do work.

Connected Concepts

The same primitive reappears near tokenization, latent space, representation learning. Across the three courses, the shared pattern is geometry, compression: choose what to keep, how to move, what feedback means, or how to measure whether the behavior really improved.

Lecture Argument
The CME295 agentic LLM lecture links retrieval directly to embeddings: when the system needs to retrieve outside information, it computes embeddings for chunks or queries so nearby vectors can be used as lookup candidates.
Example Or Analogy
Retrieval is the concrete case. The model cannot search a pile of text by raw words alone; it needs numerical coordinates so a query and a useful document chunk can land near each other.
Mathematical Claim
An embedding maps text or another object into a vector space. Retrieval then compares vectors, often by similarity score, and returns items whose coordinates are close enough to the query.
Caveat Or Warning
This span supports embeddings as a retrieval interface, not the stronger claim that vector closeness always captures the user's true information need. Bad chunking or misleading similarity can still retrieve the wrong evidence.
Why This Span Matters
It anchors embeddings in a practical agent workflow: learned coordinates become the bridge between a language model and external memory.
