Fine-Tuning And Preference Learning

Steering a broad model toward behavior people actually want.

What real-world problem is this about?

The problem is that predicting likely text is not the same thing as being helpful, safe, concise, or correct.

Why does this problem exist?

Raw imitation learns what appears in data. Usefulness requires extra feedback about which possible responses people prefer.

What is the mathematical idea underneath?

Tuning changes probabilities: make wanted answers more likely and unwanted answers less likely. Preference learning turns comparisons between answers into a training signal.

Why is this concept important?

It is the bridge between a base model and an assistant, tutor, coder, or agent.

What breaks without it?

The model may be fluent but misaligned with the task, the user, or the deployment setting.

Naive Starting Point

Start with the simplest version: The problem is that predicting likely text is not the same thing as being helpful, safe, concise, or correct. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because raw imitation learns what appears in data. usefulness requires extra feedback about which possible responses people prefer. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Fine-Tuning And Preference Learning: Tuning changes probabilities: make wanted answers more likely and unwanted answers less likely. Preference learning turns comparisons between answers into a training signal. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Fine-Tuning And Preference Learning, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: a pretrained model can autocomplete a recipe, a bug report, or a rude internet thread. Fine-tuning teaches it the behavior format wanted for a particular use case, such as answering like an assistant. CME295 describes supervised fine-tuning as taking the pretrained model and teaching it exactly which tokens to predict for higher-quality task data. CS224R then asks how pretrained language models become chatbots through preference optimization.

What the Lectures Emphasize

The LLM tuning lecture emphasizes fine-tuning as the second stage after pretraining: smaller but higher-quality data teaches task behavior. It also separates supervised fine-tuning from preference tuning, where tone, safety, and human preference are shaped later. That staged view prevents confusing broad knowledge with deployable behavior.

Common Misunderstanding

A common misunderstanding is that fine-tuning simply adds facts. It more often changes behavior: format, tone, instruction following, domain style, and what outputs are likely. It can also overwrite or narrow behavior if the tuning data is too small or biased.

How to Recognize This in a New Paper or Model

In a new paper, recognize fine-tuning when a pretrained model is adapted with task-specific examples, instruction data, adapters, LoRA, supervised demonstrations, or preference data. The shared primitive is steering an existing representation rather than learning the whole world again.

Connected Concepts
