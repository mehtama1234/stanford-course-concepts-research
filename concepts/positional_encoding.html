Position And Order

A way to tell the model where each piece sits in a sequence or image.

What real-world problem is this about?

The problem is that the same words or image patches mean different things depending on where they appear.

Why does this problem exist?

Attention compares items as a set unless order information is added. Order must be represented explicitly if order matters.

What is the mathematical idea underneath?

Position information is added as numbers that vary by location. The model can then learn patterns such as before, after, nearby, or far away.

Why is this concept important?

It lets transformers handle grammar, layout, time, and spatial structure.

What breaks without it?

The model may know which pieces exist but lose the arrangement that makes them meaningful.

Naive Starting Point

Start with the simplest version: The problem is that the same words or image patches mean different things depending on where they appear. A beginner might try to solve this with a fixed rule, a lookup table, or one direct guess. That works only while the situation is tiny and clean.

Why the Simple Approach Fails

The simple approach breaks because attention compares items as a set unless order information is added. order must be represented explicitly if order matters. Once the input grows, feedback arrives late, or many explanations compete, the system needs a reusable mechanism instead of a special case.

The Mathematical Object

The useful object is the thing the model can change or compare while learning Position And Order: Position information is added as numbers that vary by location. The model can then learn patterns such as before, after, nearby, or far away. Think of it as the handle the algorithm can grab.

The Operation

The operation is to apply that object repeatedly: read the current situation, produce a numerical signal, and use feedback or comparison to adjust the next step. For Position And Order, this is the move that turns a vague goal into an executable procedure.

Worked Mini-Example

Mini-example: "dog bites man" and "man bites dog" contain the same words but mean different things. A transformer attention layer can compare all tokens directly, but that direct comparison loses the built-in order signal that an RNN gets from processing one token after another. The CME295 lecture explains this exact problem: because tokens interact directly rather than sequentially, position information is lost unless the model injects it. Position embeddings add a learned location signal to token embeddings.

What the Lectures Emphasize

The transformer tricks lecture emphasizes position embeddings as a repair for the transformer's strength. Direct token-to-token links make attention parallel and flexible, but they remove the natural before-and-after structure of a sequence. The original transformer solution was a dedicated embedding per position, added to the token embedding.

Common Misunderstanding

A common misunderstanding is that attention automatically knows order because tokens are listed in order in the input file. The architecture only receives numbers. Unless position is encoded in those numbers, the model has much weaker access to sequence order.

How to Recognize This in a New Paper or Model

In a new paper, recognize positional reasoning whenever a model adds, rotates, biases, indexes, or otherwise marks where information came from. The mechanism may be absolute embeddings, relative positions, RoPE, ALiBi, patch positions, time embeddings, or spatial coordinates. The shared primitive is geometry for order: make location available to computation.

Connected Concepts

The same primitive reappears near attention, transformer block, vision transformers. Across the three courses, the shared pattern is geometry, invariance: choose what to keep, how to move, what feedback means, or how to measure whether the behavior really improved.
