RL For LLMs

Teaching a language model to make better choices by showing it which complete outputs were good or bad.

What real-world problem is this about?

Imagine teaching a child to cook. You can taste the final dish and say 'delicious' or 'needs salt,' but you didn't watch every hand motion. The child must figure out which of their hundred choices led to the bad taste. Feedback comes at the end, not during each step.

Why does this problem exist?

A language model generates text one token at a time. If you reward only the final answer, the model must work backward: which earlier decisions led to this good ending? This is the core RL problem—mapping reward from outcome to actions spread across time.

What is the mathematical idea underneath?

Treat token choices as actions and sequences as trajectories. A reward function scores the full response (say, +1 for correct math answer, 0 for wrong). A policy is the model's learned probability over next tokens given prior context. To improve the policy, weight actions by the reward they led to: actions in high-reward sequences get boosted. Formally, gradient updates shift log-probability of actions upward in proportion to their estimated return (future discounted reward). Why gradient? It moves probabilities in the steepest direction toward improving reward while staying near the original distribution.

Why is this concept important?

Feedback on outcomes (correct or not, user preference, reasoning trace quality) is far cheaper and easier to collect than labeled next tokens. This unlocks training on tasks where humans can judge a full answer but not prescribe step-by-step behavior.

What breaks without it?

Without connecting outcome feedback to token choices, a model can only learn from imitation of known-good text. It cannot refine its behavior beyond the training examples and cannot optimize for new metrics (reasoning speed, conciseness, safety).

Naive Starting Point

A beginner might assume: 'Just find which response is better and copy its tokens.' This sounds simple—if response A is better, make the model more likely to pick those exact tokens.

Why the Simple Approach Fails

The approach breaks when the same correct tokens can come from different reasoning paths, or when conditioning matters. Copying A's tokens without understanding which mid-generation decisions were key teaches brittle behavior. Also, a reward at timestep 1000 cannot directly update the token choice at timestep 10—credit must propagate backward through the sequence.

The Mathematical Object

The policy model itself, parameterized as neural network weights. Specifically, the conditional probability distribution P(next_token | previous_tokens) that the model learned. You adjust these weights via gradient steps that raise log-probability of tokens in high-reward sequences.

The Operation

For each generated sequence: (1) Run the model to generate a full response. (2) Score it with a reward function (math correctness, user preference, verifier output). (3) Compute the gradient of log-probability for each token, weighted by the return from that point onward. (4) Take a gradient step to increase those log-probabilities. Repeat across many sequences to shift the distribution.

Worked Mini-Example

Suppose a model generates '5+3 is 8' (correct) and '5+3 is 9' (wrong). The first earns reward +1, the second 0. We ask: which token choices in sequence 1 deserve credit? All of them, proportionally. So we increase the probability of every token in 'is 8' and decrease the other sequence's tokens. But there's a catch: token '8' comes at the end, and '5' at the start, yet both contributed to correctness. The algorithm estimates how much each token's position mattered by tracking return (remaining reward) from that point forward. If 'is 8' contributes most of the value, tokens earlier in the sequence get partial credit. Repeated on thousands of problems, the model learns to favor correct reasoning patterns.

What the Lectures Emphasize

CS224R frames RL for LLMs as treating token generation as policy behavior shaped by reward signals. The key challenge is credit assignment: determining which of the hundreds of tokens in a long reasoning trace earned the final reward. CME295 connects this to reasoning methods, showing that preference learning and outcome-based feedback form the foundation for modern reasoning models. Both lectures stress that simple reward signals (correct or incorrect) propagate poorly—researchers now use process rewards (intermediate correctness) and reasoning traces to allocate credit more precisely.

Common Misunderstanding

Students often think RL for LLMs is just 'reward good outputs.' The hard part is that a reward arriving at the end must influence thousands of earlier token choices fairly. Without careful credit assignment, the model learns spurious correlations or gaming (e.g., writing longer answers because verbosity correlates with correctness in training, not because it improves real reasoning).

How to Recognize This in a New Paper or Model

In a paper, spot RL for LLMs when the text says a language model is trained on outcome feedback—phrases like 'reward model,' 'preference learning,' 'RL from feedback,' 'RLHF,' 'GRPO,' 'rejection sampling,' or 'process verifier' all point to it. The distinguishing signal is credit: the method must decide how to distribute a signal from a full response back to individual token choices.

Connected Concepts

In CME295, this follows preference learning (which compares outputs) and feeds into reasoning traces (which structure intermediate feedback). In CS224R, RL for LLMs is the direct application of Markov Decision Process and policy gradient theory to language: tokens are actions, context is state, and rewards drive learning. In diffusion models, a similar credit problem appears when training on sample quality—you must trace each pixel's contribution to the final loss.
