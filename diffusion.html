Course Spine

Diffusion and flow models study how to generate structured visual data by moving from something simple to something complex. The course keeps returning to six facts: direct generation is too hard, local directions are learnable, representation changes cost, guidance changes control, architecture changes what information can be used, and evaluation must check several kinds of failure.

Big Picture From First Principles

Start with one ordinary fact: a realistic image is too many choices to make all at once. The model needs a path. Diffusion, score matching, flow matching, latent spaces, guidance, architectures, training, and evaluation are different answers to the same pressure: how do we move from something easy, like random noise, into something structured, like a useful image?

The course keeps rebuilding one loop. Pick a representation, choose a path through that representation, learn the local direction of improvement, follow that direction to make samples, and then check whether the result is realistic, controlled, diverse, and useful.

Generation Needs A Path

Noise is easy to sample and images are hard to sample. The core problem is learning a reliable route between them.

Small Moves Beat One Leap

Diffusion breaks image generation into many cleanup steps, each easier to learn than the full image at once.

Direction Can Replace Probability

Score matching learns which way a noisy point should move without writing down the full data probability.

Flow Means Learned Motion

Flow matching learns arrows that carry simple samples toward data-like samples.

Compression Saves Work

Latent spaces let the model work in a smaller code where important structure remains but raw pixel cost drops.

Guidance Adds Control

A generated image must often obey a prompt or condition, so the sampling direction needs a steering signal.

Architecture Carries Information

The network must combine local detail, global layout, time, and conditions at every update.

Evaluation Has Many Axes

A sample can look good, ignore the prompt, copy data, or fail rare cases, so one score is not enough.

Lecture 1

Lecture 1 - Diffusion

Open video

1h 46m · 12646 transcript words

Detailed Topic Explanation

Diffusion breaks image generation into tiny steps. The key insight is to reverse an easy forward process. First, take a clean training image and gradually add random Gaussian noise (a known process you control). Keep adding noise until the image becomes pure static. This forward process is easy—you know exactly what you added. The learning problem is the reverse: teach a model to undo one small step of noise at a time. At each step, the model sees a noisy image and the current noise level, then predicts how much noise was added. At generation time, start from random noise and repeat many small cleanup steps—each one removing a bit of predicted noise—until structure emerges into a complete image. Why this works: early steps recover broad layout because only large structures survive the noise; later steps sharpen fine details. The cost is speed (many steps needed); the gain is a clear, supervised training target that the model can optimize.

The forward process adds noise in a specific way. At each step t, the image becomes a weighted combination of the previous image and independent Gaussian noise, using weights that form the noise schedule. These weights guarantee the overall variance stays constant—this is called variance-preserving. Because Gaussian noise has special mathematical properties (the sum of independent Gaussians is also Gaussian), you can skip sequential steps: directly compute the noisy image at step t from the clean image and a single noise sample, without going through steps 0, 1, ..., t−1. At training time, the forward process q is fully known, so you can create any number of training examples by sampling random t values and random noise. The reverse process, which we learn with parameters θ, tries to predict what noise was added. The loss is simple: squared difference between the predicted noise and the actual noise that created each training example. Why this design: when the model sees a nearly random image, it should predict strong noise removal; when it sees a nearly clean image, it should predict weak removal. A time conditioning input tells the model which stage it is in. Without this, the model could not distinguish between 'almost clean' and 'very noisy' images, making large errors. During generation, you start with x_T (random noise) and repeatedly estimate x_{t-1} using the trained model's noise prediction, adding a small amount of controlled stochasticity at each step (the variance of the reverse process is also Gaussian). By the final step, you have x_0, a clean image.

Core Ideas

  • The forward process corrupts real images with known Gaussian noise on a schedule, so training examples with clear targets can be created without human labels.
  • The reverse process learns to undo one small denoising step instead of generating an entire image at once, turning generation into an iterative refinement loop.
  • A time or noise-level input is essential because the model must change its behavior depending on the current noise level—heavy removal for high noise, light removal for low noise.
  • Sampling reverses the forward process: start from random noise and repeat the denoising step using the trained model's predictions, gradually revealing structure.

Approaches Taught

DDPM-style denoising

Problem
Directly turning random noise into a clean image in a single step is mathematically and computationally too hard; the jump from millions of random values to a coherent image has no clear learning signal. A model needs intermediate targets to learn stable representations.
How It Works
Add known Gaussian noise to real images during training according to a predefined schedule, creating training pairs of (noisy image, noise level) → noise added. Train a neural network to predict the added noise given the noisy image and noise level, using squared error loss. The forward process is Markovian: each step only depends on the previous step and a noise sample. Crucially, you can jump directly to any timestep without going through intermediate steps, thanks to Gaussian properties, enabling diverse training examples. At inference (generation), start from random noise and repeatedly apply the learned model: predict the noise in the current image, remove some of it, add controlled Gaussian stochasticity, and move to the next less-noisy step. Repeat until reaching the clean image.
Why It Matters
Transforms an intractable generation problem into a sequence of supervised regression problems, each with explicit, measurable targets. The noise prediction task is statistically stable: the model learns to extract signal from noise at different levels, which mirrors how perception works. Training is efficient because the forward process is fully known; you never need human labels. Sampling is flexible: you can adjust the number of steps, the schedule, or introduce guidance without retraining. This approach enabled the first high-quality image generation from pure noise at scale.
Where It Breaks
Sampling is slow: generating one image requires forward passes through the model once per step, typically 1000 steps, taking seconds to minutes. Early errors in high-noise steps corrupt downstream steps irreversibly—if step 900 predicts noise incorrectly, step 899 starts from a wrong image. The noise schedule is a hyperparameter; a poor choice can make some noise levels undertrained or too easy, wasting model capacity. If the model's variance is poorly calibrated, diversity and quality both suffer.

Noise scheduling

Problem
The model must learn to denoise at all corruption levels, from nearly clean (low noise) to pure static (high noise), but these stages have very different difficulty. Without careful design, some stages become too easy (model learns trivial solutions), others too hard (model fails to learn), and sampling efficiency varies unpredictably.
How It Works
Define a sequence of noise levels β_1, β_2, ..., β_T that gradually increases, starting with small additions and building toward heavy corruption. The schedule determines two things: first, which corruption levels the model practices (coverage), and second, how much the image changes at each step (difficulty). A common choice is linear in β or in the log of signal-to-noise ratio. Early in the forward process (low t), β_t is small, so the model learns to remove fine details like texture and edges; later (high t), β_t is large, and the model learns to recover broad structure like object shape and spatial layout. The cumulative product α_bar_t = Π α_i encodes total corruption: when α_bar_t is near 1, little noise has been added; when near 0, almost all signal is lost. This schedule is fixed before training; different schedules affect learning dynamics and generation quality.
Why It Matters
The schedule directly controls training efficiency and generation quality. A well-designed schedule ensures the model sees a balanced mix of easy and hard tasks: easy tasks (light noise) teach fine-grained features, hard tasks (heavy noise) teach global structure. During sampling, the schedule controls step size and information flow. Larger steps between schedule points speed up generation but risk information loss; finer steps preserve quality but slow sampling. The schedule is also tied to the mathematical form of the loss: different schedules result in different loss weights, influencing which noise levels the model prioritizes. Early work showed that carefully tuning the schedule can match or improve results of poorly scheduled alternatives, making it a critical design choice.
Where It Breaks
A linear schedule in β may concentrate most corruption in a small range of timesteps, leaving other timesteps undertrained and brittle. If β increases too quickly, the model trains only on very noisy images and fails to learn fine details; if too slowly, sampling becomes inefficient. A schedule that is too uniform can waste capacity on noise levels that are either too easy or too hard for the model. Mismatched schedules between training and sampling (e.g., training with one schedule but sampling with another) cause a train-test mismatch, degrading generation quality and diversity.

Deterministic denoising (DDIM)

Problem
DDPM-style denoising requires hundreds to thousands of sequential steps to generate a single image, making real-time or interactive applications impractical. The model's predictions accumulate errors over many steps; reducing the number of steps without retraining causes quality collapse due to the stochasticity in the reverse process compounding errors.
How It Works
Observe that the key property used during training is the marginal distribution of x_t given x_0 (the relationship between clean image, noise, and corruption level). This marginal is independent of how the forward process is defined—only its final result matters. Design an alternative forward process that preserves this marginal but removes the stochasticity between steps. Define a family of forward processes parameterized by σ (sigma) such that the marginal matches DDPM, but set σ = 0 to remove noise between generation steps. The reverse process becomes deterministic: given x_t and the model's noise prediction, compute x_{t-1} directly without sampling. This deterministic mapping is mathematically valid because the underlying marginal is the same; the model trained on the DDPM loss can be reused without retraining. At generation time, skip steps by jumping along a subset of timesteps (τ_1, τ_2, ..., τ_S) instead of stepping through all T timesteps. The effective speedup is T/S. Optionally, add back stochasticity by setting σ > 0 if diversity is needed.
Why It Matters
Reduces generation time from minutes to seconds while maintaining image quality, enabling interactive and real-time applications. The deterministic version allows the same model to trade off speed and quality: fewer steps for speed, more steps for quality, without any retraining. This is critical for deployment. The mathematical insight—that only the marginal matters—is general and applies to any diffusion model, making it broadly useful. Empirically, deterministic denoising produces comparable or better quality than stochastic denoising with the same number of steps because errors do not accumulate as quickly.
Where It Breaks
Skipping too many steps (large speedup) causes quality degradation because the model never trained on those large jumps in timesteps; it must extrapolate, leading to inconsistent predictions. The effective speedup saturates: speedups beyond ~50x typically show visible artifacts. If σ is set too high trying to recover diversity, stochasticity returns and the speedup benefit is lost. The schedule of skipped timesteps matters: uniform skipping may miss important noise levels. Deterministic sampling gives no diversity at inference—all outputs with the same initial noise are identical, so if you want multiple samples, you must resample the initial noise.

Examples Used

  • A clean photo of a face gradually becomes gray static when random noise is mixed in at increasing strengths over 1000 steps, transforming a high-resolution image into unrecognizable static.
  • At generation time, gray static gradually refines into a face as the model predicts and removes noise at each step, recovering first rough shapes, then features, then fine details like skin texture and hair.
  • The same principle applies outside images: a structured protein molecule corrupted into atoms can be recovered by iteratively removing noise; a clean 3D scene gradually obscured by fog can be reconstructed.
  • A model trained on cat images learns that certain patterns of noise in high-noise images (t near 1000) are part of ears, so it removes those patterns; at low-noise stages, it refines whiskers by removing fine-grain noise.

Equations And Algorithm Moves

  • Define a noise schedule β_t (beta at time t) for t = 1 to T, where each β_t ∈ (0,1) says how much Gaussian noise to add at step t; larger β means stronger noise.
  • Forward process: given clean image x_0, compute x_t as a weighted combination α_t·x_{t-1} + √(β_t)·ε, where ε is standard Gaussian noise and α_t = 1 − β_t; this can be simplified to x_t = √(ᾱ_t)·x_0 + √(1 − ᾱ_t)·ε, where ᾱ_t is the cumulative product of alphas.
  • Training loss: minimize the squared error between the model's predicted noise ε_θ(x_t, t) and the actual noise ε used to create x_t, averaged over random samples of t, x_0, and ε.
  • Reverse process for generation: initialize x_T as random Gaussian noise, then for t = T down to 1, compute x_{t-1} using the model's noise prediction, adding controlled Gaussian noise with variance determined by the schedule.
  • Convergence happens because Gaussian distributions are closed under linear combinations and marginals; the KL divergence between learned and true reverse distributions has an analytical form that reduces to the noise prediction loss.

What You Should Be Able To Say

You can now explain diffusion as learning to reverse a known, gradual corruption process one small step at a time, rather than producing a whole image in one leap. You understand that the forward process creates training data with clear targets, and the reverse process uses noise prediction to denoise iteratively.

Lecture 2 - Score matching

Open video

1h 48m · 12725 transcript words

Detailed Topic Explanation

The solution is to learn the score: the gradient of the logarithm of probability, not probability itself. Imagine a map showing the height of a mountain—if you know the slope (gradient) at every point, you can hike uphill without knowing the exact elevation everywhere. The score is that slope field. Thanks to logarithm properties, the gradient of log-probability eliminates the intractable normalization constant. More importantly, it points in the same direction as the raw probability gradient but stays numerically stable even in low-probability regions. To make this learnable, we use denoising score matching: add known Gaussian noise to real training images, then train a network to predict the noise that was added. The key insight is that predicting that noise is mathematically identical to estimating the score of the noisy distribution—we get the score for free by training a denoiser. This connects directly to Lecture 1: DDPM's noise prediction is score estimation in disguise.

Here is why each part matters. First, why the gradient of log-probability? The raw gradient of p(x) has two killers: the partition constant Z makes it intractable, and when p(x) is tiny in low-probability regions, dividing by p(x) causes numerical explosions. Taking log turns division by Z into subtraction (which vanishes under gradients), and turns ratios into logs, which stay numerically tame. Second, why add noise? The true score of clean training data is impossible to supervise because we never observe it directly. But the score of a Gaussian is trivial to compute: it points toward the mean. When we add known Gaussian noise to clean images, the conditional score (the direction from noisy image back to the original clean image) becomes tractable. We can compare predictions to this true conditional score. Third, why does this work? The math shows that minimizing the loss between predicted and true conditional scores is equivalent to minimizing a loss that would work for the full noisy distribution. The magic word here is Tweedie's relation: the denoising direction (what a network learns to predict) mathematically equals the score of the noisy data. Finally, the danger: we can only train on noise levels where real noisy data appears frequently. If noise is too small, the training distribution has high density only near training points, and the learned score is terrible in the empty space between them. If noise is too large, the distribution becomes so blurred that what we learn is not the score of the true data. The solution is to train one network that predicts scores at many noise levels simultaneously—this is Noise Conditional Score Networks (NCSN). During sampling, you start with heavy noise (where rough directions suffice) and gradually decrease noise, using more refined score estimates as you get closer to true data.

Core Ideas

  • The score is grad_x log p(x), a direction field pointing uphill toward higher-probability regions, learned without knowing the normalization constant.
  • Denoising score matching converts the intractable task of learning the true score into a tractable one: add noise, predict the noise, and the noise prediction equals the score.
  • Different noise levels require different score estimates, creating a bias-variance tradeoff: small noise means high accuracy but poor coverage of low-density regions, high noise means coverage but accuracy far from true data.
  • Annealed sampling bridges the tradeoff: start with high noise levels and gradually decrease, using coarse directions early and refining as you approach real data.
  • Predicting noise in DDPM is mathematically the same as learning the score: they are linked through a simple coefficient relationship.

Approaches Taught

Score matching

Problem
The full data probability density is unknown and its normalization constant is intractable to compute. Computing the gradient of the probability directly is therefore impossible. We need a way to learn which direction in image space points toward real data without knowing the true probability value.
How It Works
Instead of estimating probability, train a network to predict the score: the gradient of log-probability. This gradient can be thought of as a direction field where each arrow points toward higher-probability regions. To supervise this, use the mathematical fact that the score of a Gaussian distribution can be computed exactly (it equals (mean - x) / variance). By adding known Gaussian noise to training images, we create a situation where the true score is computable: it points from the noisy image back toward the original clean image. The network is trained by minimizing the squared difference between its predicted score and this true conditional score, using the loss function that compares s_θ(x_t, t) against the true Gaussian score.
Why It Matters
Learning the score solves the generation problem. If you know the direction to move at every point in image space, you can perform Langevin dynamics: start from random noise and repeatedly step in the direction of the score plus a small random perturbation. This walks you toward regions of high probability, generating realistic samples. The score avoids the intractability of learning probabilities while still providing all the direction information needed for sampling. Score matching is also numerically more stable than computing probability gradients because log-probability remains well-behaved even when probability values are tiny.
Where It Breaks
The learned score is only accurate in regions of high probability under the training distribution. If noise is too small, the noisy distribution has high density only near training points, so the learned score is terrible in the gaps between points—Langevin dynamics would get stuck or wander aimlessly. If you try to sample from random noise using only a low-noise score, you will fail because your starting point is in a region the network never trained on. The solution requires training a single network that predicts scores at many noise levels and using annealed sampling: start with high noise (where the score covers the entire space) and gradually decrease noise, refining the trajectory.

Denoising score matching

Problem
Score matching requires supervising the network against the true score, which we cannot compute for the real unknown data distribution. The score of the clean data distribution is intractable just as the probability itself is. We need a practical way to generate training pairs of (noisy image, true score) for the network to learn from.
How It Works
Denoising score matching solves this by using a clever indirection. Instead of trying to learn the score of the true data distribution directly, we learn the score of a noisy version of that distribution. Here is the procedure: take a clean training image x₀, add Gaussian noise with standard deviation σ to produce a noisy image x_t = x₀ + σ·ε. The key insight is that x_t follows a Gaussian distribution conditioned on x₀ (the mean is x₀ and the variance is σ²). The score of this Gaussian is exactly grad log q(x_t | x₀) = (x₀ - x_t) / σ². This is tractable because we know x₀ and σ and the noise ε. Train the network s_θ(x_t, t) to minimize the squared difference between its prediction and this true conditional score. A mathematical equivalence (proved by expanding squared norms and recognizing that certain terms vanish under optimization) shows that minimizing loss against the conditional score is equivalent to minimizing loss against the true score of the full noisy distribution q_σ(x_t).
Why It Matters
Denoising score matching converts an impossible learning problem into a tractable one. Every training step, you have a ground truth score: the direction from noisy image back to clean image. You can compute this direction analytically for any noise level. The network learns by direct supervised regression on these directions. Once trained, the network can be used in Langevin sampling: starting from noise, repeatedly predict the score and step in that direction plus noise. The connection to Lecture 1 is crucial: DDPM's noise prediction is exactly this same conditional score learned through a different parameterization. Predicting the noise ε and predicting the score s are mathematically equivalent; they are linked by the relationship s = -ε / σ.
Where It Breaks
The training loss is weighted by the probability density of the noisy distribution q_σ. This means if a particular (x_t, x₀) pair is unlikely under q_σ, the network receives little training signal on that pair. When training with small noise σ, the distribution q_σ has high density only near the training points and very low density in the gaps. The network becomes accurate near training examples but wildly inaccurate in empty space. During sampling, if you start from random Gaussian noise and use the score from small σ, you fail because random noise is in the low-density region where the network was not trained. The bias-variance tradeoff is tight: small σ gives accurate scores close to true data but poor coverage of the space from which sampling must start; large σ gives coverage but learns a score that is far from the true data distribution.

Examples Used

  • A blurry photograph with added noise can be sharpened by following arrows pointing toward the clean image, one small step at a time—those arrows are the score.
  • A point cloud shaped like a ring can be generated from random noise by first using coarse score estimates to guide points toward the ring's rough neighborhood, then using finer estimates to settle onto the ring itself.
  • If you know which direction is uphill everywhere on a mountain but not its absolute height, you can hike from any starting point to the peak; the gradient (uphill direction) is all you need.
  • Training a network to predict added Gaussian noise lets you avoid computing the impossible partition constant; the network naturally learns the score because denoising and score-matching are mathematically equivalent.

Equations And Algorithm Moves

  • Define the score as s(x) = grad_x log p(x), the direction in image space that increases log-probability. It is a vector pointing toward where real images live.
  • For Gaussian noise with mean μ and variance σ², the score is exactly (μ - x) / σ², pointing directly toward the mean. This is the only case where the score is computable by hand.
  • Corrupt clean data x₀ by adding Gaussian noise: x_t = x₀ + σ·ε, where ε is standard Gaussian. This creates a noisy distribution q_σ(x_t).
  • Train a network s_θ(x_t, t) using the loss: minimize E[(s_θ(x_t, t) - grad log q_σ(x_t | x₀))²], where the true conditional score is known because it is the Gaussian score. By Tweedie's relation, this is equivalent to learning the score of q_σ.
  • Sample by Langevin dynamics: x_{i+1} = x_i + α·s_θ(x_i, t) + √(2α)·ξ_i, where α is step size and ξ is Gaussian noise. This ensures you follow the score while exploring.
  • Use annealed sampling: start with large σ (high noise) and gradually decrease to small σ, using the same network at each step. Early steps are rough and explore broadly; late steps refine the final image.

What You Should Be Able To Say

You can now explain that the score is a learned direction field telling you how to move a noisy sample toward real data, that denoising and score-matching are mathematically the same under Gaussian noise, and that sampling requires balancing coarse guidance from high-noise estimates with fine guidance from low-noise estimates.

Lecture 3 - Flow matching

Open video

1h 47m · 12595 transcript words

Detailed Topic Explanation

Flow matching reframes generation as motion through space. Imagine a cloud of random points distributed like Gaussian noise. Your goal is to move every point to where it should be to form real data. Instead of thinking about noise fading, think about arrows: at every location in space and every moment in time, the model learns an arrow that says move this way at this speed. This arrow is called a velocity field. The velocity is what the model learns. Training works by picking a real data point and a noise point, drawing a straight line between them (or any smooth path), and teaching the network to output the velocity that would carry a point along that path. When you average this over thousands of pairs, you get a velocity field that smoothly transports all noise into the data distribution. At inference, you start with noise and follow these learned arrows using an ODE solver (which just means follow the arrow in tiny steps). The result: clean samples appear, deterministically, with no stochastic steps needed.

The key insight is that the training target can be direct and tractable. In diffusion, you teach the network to predict noise; in flow matching, you teach it to predict velocity directly. Since you choose the path (usually a straight line), you know exactly what the velocity should be at every point on that path. This is elegant: the target for training is simply data minus noise. The network sees a noisy version of data (a point on the path) and learns to predict where it should go. The practical advantage is a clean squared-error loss with no divergence operators or complicated relationships to unwrap. However, the path choice matters deeply. Different paths lead to different velocity fields. Straight-line paths are simple but may result in curved trajectories at test time, requiring many ODE solver steps for accuracy. This is why reflow exists: you can run the learned model to generate new data-noise pairs, then retrain on those pairs to straighten the trajectories. Each reflow makes paths closer to straight lines, enabling faster sampling. The tradeoff is that straightening requires retraining and accumulates numerical errors from ODE integration. So practitioners balance sampling speed against retraining cost and quality degradation.

Core Ideas

  • Velocity field: a map of arrows at every location and time, showing direction and speed for a sample to move.
  • Probability path: a sequence of distributions from noise to data, the bridge the model must learn to cross.
  • Conditional velocity: for a single data point and noise point, the straight-line path gives a simple target velocity of data minus noise.
  • ODE solver: follows the velocity field in tiny steps, turning learned arrows into a deterministic generative trajectory.
  • Straightness improves efficiency: straighter paths require fewer ODE steps to reach the target distribution at test time.
  • Training loss is direct regression: minimize the squared difference between predicted velocity and true velocity along the path.

Approaches Taught

Flow matching

Problem
Generation requires transporting a noise distribution to data. Diffusion and score matching use indirect proxies (noise prediction, score estimation). Learning velocity directly is cleaner but demands defining a path and a training target. How do you make velocity prediction tractable and ensure the resulting field reaches the data distribution?
How It Works
Define a probability path (often linear interpolation) from noise to data. For each data-noise pair, the path gives a ground-truth velocity: the derivative of the path at each point, typically data minus noise. Train a neural network to predict this velocity given a position and time, minimizing squared error. Aggregate over many pairs to build a velocity field for the entire distribution. The mathematical structure (continuity equation) guarantees that following this field transports the noise distribution to the data distribution. At inference, start from noise and integrate the ODE dx/dt = v_θ(x, t) using a numerical solver, stepping forward from t=0 to t=1 to obtain samples.
Why It Matters
Velocity is simpler than noise or scores: it is directly the direction of motion. The training loss is a plain regression without divergence operators or expectation tricks. The inference procedure is deterministic, needing no stochastic sampling steps or Langevin dynamics. Straight-line paths give velocity targets (data - noise) that are trivial to compute. The approach scales to high dimensions and high-resolution data, as shown by state-of-the-art image and video generation models.
Where It Breaks
Straight-line paths may not be optimal; the learned velocity field at test time follows curved trajectories due to averaging effects when training paths intersect. This requires many ODE steps for accurate sampling. Numerical ODE integration error accumulates, especially with few steps. Lipschitz violations in the learned field can cause trajectory divergence or collapse. Reflow improves straightness but costs retraining iterations and introduces discretization error that compounds if reflow repeats too many times. Path selection matters: poor choices lead to inefficient or low-quality samples.

ODE sampling

Problem
Once a velocity field is learned, the field must be converted into actual samples. The field is just a mathematical function; sampling requires following it. How do you reliably integrate the ODE dx/dt = v_θ(x, t) in finite time with limited computational budget, especially when the velocity field is rough, approximate, or non-linear?
How It Works
Numerically solve the ordinary differential equation (ODE) using an iterative solver. Start from x_0 sampled from the noise distribution and repeatedly step forward: x_{t + Δt} = x_t + v_θ(x_t, t) · Δt (Euler method) or higher-order methods (Runge-Kutta, etc.). Each step follows the velocity field, pushing the sample toward the data distribution. Continue until reaching t=1, where the sample is drawn from the data distribution. Small steps are accurate but slow; large steps are fast but may miss curves in the velocity field, landing off-target. The number of steps (NFE, number of function evaluations) controls the speed-accuracy tradeoff.
Why It Matters
ODE integration is the only way to use a learned velocity field at test time. It is deterministic (no randomness), unlike Langevin sampling in score matching. Fewer steps mean faster generation, which is critical for real-time applications. Higher-order solvers can sometimes reduce steps needed without sacrificing accuracy. Adaptive step sizing can concentrate computational effort where the field is rough and coarse steps where it is smooth. The approach connects flow matching to classical numerical methods, allowing practitioners to leverage decades of ODE solver research.
Where It Breaks
Too few steps (e.g., one step) causes severe discretization error; the solver misses bends in the trajectory and produces low-quality or off-distribution samples. Too many steps slow inference prohibitively. Non-linear velocity fields (which flow matching produces) cannot use fast approximations like DPM-Solver that assume linearity. The learned velocity field itself may be rough due to finite model capacity, making it hard for solvers to follow. Lipschitz discontinuities in v_θ can cause the ODE solution to branch or diverge. No free lunch: trading steps for speed trades off sample quality, and the quality floor depends on how well the velocity field was learned.

Examples Used

  • Imagine a city with a vector field like a traffic map: at each intersection and each hour, arrows point in a direction with a speed limit. Particles (cars) follow those arrows. In flow matching, the model learns this traffic map so that starting from anywhere in the suburbs (noise), following the arrows gets you to downtown (data) by time t=1.
  • A cloud of random dots shaped like a Gaussian can be transported into the shape of a crescent moon by learning velocity arrows that push dots from the Gaussian towards the crescent. Training on many dot pairs (one from Gaussian, one from crescent) teaches the network which arrows to place where.
  • A blurry photograph that sharpens over time: at t=0, every pixel is noise. At t=1, every pixel is sharp and correct. The velocity field says how fast and in which direction each pixel must change color or intensity to reach its final value by time t=1.
  • An ODE solver as a hiker following trail markers: at each location, a marker points the next direction to walk and how fast to go. Tiny steps forward following the markers lead from base camp to the summit without getting lost.

Equations And Algorithm Moves

  • Choose a probability path p(x_t) interpolating from noise distribution p_0 at t=0 to data distribution p_1 at t=1, e.g., x_t = (1-t)·noise + t·data
  • Define the conditional velocity field u(x|x_data) for points on that path as the derivative of the path, e.g., for straight-line paths, u = x_data - x_noise
  • Train a neural network v_θ(x, t) to predict that conditional velocity using squared-error loss: min E[(v_θ(x, t) - u(x|x_data))²]
  • Aggregate over data-noise pairs and time to obtain a marginal velocity field that works for the entire distribution, weighted by the probability of each data point being the target
  • Sample new data by starting at x_0 ~ p_0 and numerically integrating the ODE dx/dt = v_θ(x, t) from t=0 to t=1, using small steps

Detailed Topic Explanation

Two ideas solve these problems. First, work in a compressed latent space instead of raw pixels. Train an autoencoder—a pair of neural networks—where the encoder shrinks images into small, dense codes (the latent space), and the decoder expands those codes back to images. Run the entire diffusion process inside the latent space where a 1024×1024 pixel image becomes a much smaller code, reducing compute from millions of dimensions to maybe a few hundred. The decoder then adds back fine detail when you turn the latent result into pixels. Second, steer generation with guidance. Train the diffusion model to sometimes receive a condition (text, image, label) and sometimes not. At sampling time, compare the model's prediction when you give it a condition versus when you don't. Push the prediction toward the conditioned version, scaled by a guidance weight. Higher guidance makes the result follow your condition more closely but reduces diversity.

Latent diffusion requires an autoencoder trained to compress without losing information the model needs. The encoder learns to discard pixel-level noise and redundancy—things like individual slight color shifts—while keeping semantic meaning: what the image actually shows. This is why autoencoders produce blurry reconstructions if trained naively (pixel-level loss penalizes every tiny mismatch equally). The trick is to add perceptual loss, which compares images through feature maps from a pre-trained network instead of raw pixels, and adversarial loss, where a discriminator rewards realism. These push the decoder to produce sharp, faithful details. Guidance works through a mathematical trick. Using Bayes' rule, you can express conditional probability (image given condition) in terms of unconditional and conditioned predictions. Classifier-free guidance skips learning a separate classifier by training one model that handles both cases. The gradient direction from (conditioned minus unconditional) tells you how to nudge the sample. Multiplying by a weight w lets you control strength: w=0 ignores condition, higher w locks onto it more strongly but may create oversaturated, unnatural artifacts or lose creative variation.

Core Ideas

  • Latent space shrinks a million-pixel image into a manageable compressed code by discarding redundancy while preserving what the image is actually showing.
  • An autoencoder encoder compresses; a decoder expands back to pixels, allowing diffusion to work cheaply in the latent bottleneck.
  • Perceptual and adversarial losses teach the decoder to reconstruct fine detail and sharpness, not just semantic structure.
  • Classifier-free guidance trains one model to predict both with and without a condition, using the difference as a steering signal.
  • The guidance weight w controls how strongly the sample follows the condition: higher w means better prompt match but fewer variations and possible artifacts.
  • Latent diffusion splits jobs: the encoder prioritizes semantic meaning, the diffusion model learns clean structure, and the decoder adds perceptual detail.

Approaches Taught

Latent diffusion

Problem
Running diffusion directly on pixel space requires enormous compute. A 1024×1024 RGB image is 3 million numbers. Images also contain massive redundancy: neighboring pixels are similar, fine noise is not semantically meaningful. Diffusion in pixel space is slow and wastes modeling capacity on irrelevant detail.
How It Works
Train an autoencoder to compress images into smaller latent codes. The encoder uses convolutions and pooling to shrink a 1024×1024×3 image to (say) 64×64×4, a ~160× reduction in dimensions. Run the entire diffusion or flow-matching process inside this latent space—train the model to denoise or predict velocity in the latent bottleneck, not pixels. At inference, sample noise in latent space, iteratively denoise using the learned model, then pass the final latent through the decoder to get pixels. The decoder reconstructs detail and sharpness.
Why It Matters
Latent diffusion reduces compute by orders of magnitude, enabling faster training and inference. It also keeps the model's focus on semantic structure—what the image shows—because the encoder discards pixel-level noise. The diffusion model learns to navigate a smoother, more meaningful space. This separation of jobs (encoder captures meaning, decoder adds perceptual detail) is both faster and produces higher quality images than naive pixel-space diffusion.
Where It Breaks
Autoencoders with naive pixel-loss reconstruction produce blurry outputs because L2 loss penalizes all pixel differences equally, so the model averages ambiguous regions to minimize error. Compression can also lose fine texture and edge sharpness. If the latent space is not well-structured, the diffusion model struggles to learn. If the decoder is not powerful enough or lacks adversarial training, the final pixels may look flat or lack detail. Too much compression (very small latent) discards semantic information. Too little (large latent) doesn't save compute.

Classifier-free guidance

Problem
A diffusion model trained unconditionally generates random valid images, not images matching a user's intent. Adding separate classifier-based guidance requires training an extra classifier on noisy images (expensive, not easy to obtain) and computing its gradients at every denoising step (slow). Users want a single model that can be steered toward text prompts, visual concepts, or attributes without extra infrastructure.
How It Works
Train a single diffusion model that receives a condition (text embedding, image embedding, class label) some of the time and no condition other times. During training, drop the condition with probability p (typically 10–20%), forcing the model to learn both conditional and unconditional predictions using the same weights. At sampling, run two forward passes: one without condition to get noise prediction ε_unconditional, one with condition to get ε_conditional. Compute the guided prediction as: ε_guided = ε_unconditional + w * (ε_conditional - ε_unconditional). Here w is the guidance weight. This difference (ε_conditional - ε_unconditional) acts as an implicit classifier signal, telling you how the prediction changes when the condition is provided. Multiplying by w amplifies that signal.
Why It Matters
Classifier-free guidance needs no separate classifier, no expensive backward passes, and only one model. It is elegant: the same network trained on both conditional and unconditional examples implicitly learns what the condition changes. The guidance weight gives users a simple, intuitive control knob. At w=1 (no amplification), the result is a reasonable compromise between condition and unconditional diversity. Higher w (say w=7) strongly enforces the condition. This lets practitioners tune prompt adherence without retraining. It works with any condition that can be embedded: text, images, sketches, class labels.
Where It Breaks
When w is too high, images become oversaturated, distorted, or plasticlike. Colors may oversaturate, facial features may contort, anatomies may break (extra limbs, merged faces). Diversity drops sharply; many prompts produce nearly identical samples. If w is very low, the prompt is barely followed. The model may also produce artifacts like checkerboard patterns or color banding if guidance is aggressive. If the condition embedding is poor quality (noisy, uninformative), guidance amplifies noise rather than semantic intent. Training with too low an unconditional drop rate can hurt: if you rarely show the model unconditional data, the unconditional branch learns poorly, making guidance ineffective or jerky.

Examples Used

  • A 1024×1024 RGB image is 3 million numbers; latent diffusion compresses it to around 48×48×8 = 18,432 numbers, a ~160× reduction, making training and sampling vastly faster.
  • An autoencoder trained naively with pixel loss produces blurry output because L2 loss between pixels averages ambiguous parts. Adding a perceptual loss (comparing deep features instead) and GAN loss (penalizing unrealism) sharpens reconstruction.
  • In guidance, the unconditional model predicts noisy snow patterns. The conditioned model (given 'red car') predicts snow plus red-car-shaped features. Guidance pushes the sample toward the car direction by w times the difference, making the result strongly red-car-like.
  • Guidance weight 1 produces safe, diverse results that loosely follow the prompt. Weight 7 makes images locked onto the prompt but may oversaturate colors, distort anatomy, or look plastic. Weight 0.5 weakens control significantly.

Equations And Algorithm Moves

  • Encoder E maps image x to latent z: z = E(x). E typically uses convolutions and pooling to reduce spatial dimensions. Outputs mean and variance so z is sampled from a distribution, not deterministic.
  • Decoder D reconstructs: x_recon = D(z_sampled). D uses transpose convolutions to upsample. Training minimizes reconstruction loss, perceptual loss (feature map difference), and adversarial loss (discriminator fooling).
  • Diffusion runs in latent space. For training, encode clean latent z_0, sample z_t as a noisy blend at timestep t, train model to predict noise or velocity. For inference, sample z_T from noise, iteratively denoise using learned model, decode to pixels.
  • Classifier-free guidance at sampling: given noisy latent z_t, run model twice—once unconditional (ε_unconditional) and once with condition c (ε_conditional). Predicted noise becomes: ε_guided = ε_unconditional + w * (ε_conditional - ε_unconditional). This is equivalent to pushing along the direction of the conditional gradient.
  • Training the guidance model: with probability p_unconditional (often 10%), drop the condition and train on unconditional prediction. Otherwise train on conditional prediction. Both paths share the model weights so it learns both behaviors from the same network.

Lecture 5 - Architectures

Open video

1h 46m · 13529 transcript words

Detailed Topic Explanation

Architecture is the body that carries the diffusion idea forward. You have derived what to predict: noise, a score function (gradient of the log probability), or a velocity vector that points toward clean images. But predicting these requires a model with specific design choices. A convolutional network like U-Net specializes in local patterns and can use skip connections to preserve detail while building a global understanding through down-sampling. A transformer-based architecture cuts the image into patches and lets distant patches directly attend to each other through self-attention, capturing long-range relationships that convolutions miss. Both approaches inject time and conditioning information differently: embeddings that modulate features layer by layer, or extra tokens that interact through attention. The architecture you choose determines what information the model can see and combine when making each prediction step.

The core tension is between local and global reasoning. Convolutions operate on neighborhoods—a small window slides across the image, learning to detect edges, textures, and corners. This is efficient and stable, but a single pixel needs many layers of convolution to see the whole image (this is called receptive field growth). U-Net solves this by down-sampling (shrinking) the image through pooling and strided convolution, building a compact global representation at the bottleneck, then up-sampling back to the original size. Skip connections bypass the bottleneck to carry fine detail forward, so edges and texture survive the reconstruction. Transformers remove this locality constraint entirely: self-attention lets every patch compare itself to every other patch in one operation, so distant regions can influence each other immediately. But attention has quadratic memory cost in sequence length, and adding text or class information requires careful design—either modulation (scaling and shifting features by condition-derived coefficients), cross-attention (letting patches query text tokens), or joint attention (treating all tokens equally). Time embeddings are injected everywhere because the same noisy input needs different updates at different noise levels. The tradeoff is that U-Nets are memory-efficient for high-res images but may miss global correlations, while transformers capture anything-to-anything relationships but scale worse with resolution.

Core Ideas

  • The loss defines what to predict, but the architecture defines what information can be used to make that prediction.
  • Convolutional layers like those in U-Net learn local features efficiently but need skip connections to preserve detail during up-sampling.
  • Transformer blocks using self-attention let distant image regions and text tokens directly interact, capturing global structure in fewer layers.
  • Time embeddings using sinusoidal functions tell the model which denoising stage it is in; condition embeddings inject text or class information.
  • Adaptive layer normalization modulates patch embeddings by scaling, shifting, and gating them as functions of time and condition.
  • Multi-modal diffusion transformers use joint or cross-attention to let image patches and text tokens influence each other during each denoising step.

Approaches Taught

U-Net denoising architecture

Problem
An encoder-decoder network must combine fine spatial detail (edges, textures) with broad context (global shape and layout) when predicting updates to a noisy image. A simple feedforward encoder loses detail in its compact representation, and a simple decoder cannot recover it. Additionally, the output must match the input dimensions exactly so the velocity or noise prediction can be added to the noisy latent in each step.
How It Works
U-Net uses an encoder that down-samples the input through convolutions and pooling, compressing spatial resolution while increasing the receptive field (each output element sees a larger area of input). This creates a bottleneck representation containing global structure. Skip connections copy feature maps from each encoder level to corresponding decoder levels before up-sampling occurs, concatenating them together. The decoder up-samples using transpose convolution (learnable up-sampling with filters) and regular convolution, progressively restoring spatial resolution. At each decoder layer, concatenated skip-connection features provide fine detail that was computed during encoding but would otherwise be lost in the bottleneck. The time step is injected by adding time embeddings to features at multiple layers. Class or text conditioning may be added via additional feature channels or by modulating layer normalization parameters.
Why It Matters
U-Net's design elegantly solves the local-global tradeoff without quadratic memory cost. Down-sampling rapidly grows the receptive field, so the model understands global image structure with fewer layers than pure convolution. Skip connections are biologically and intuitively motivated: detail flows around the bottleneck, preventing information loss. The architecture is parameter-efficient and has worked well in practice from medical image segmentation (its original use, 2015) through diffusion models (DDPM, Stable Diffusion). It remains the backbone for many real-world image generation systems because it scales to high resolutions reasonably well and produces sharp outputs.
Where It Breaks
U-Net struggles with long-range dependencies where the model must compare or match fine detail across distant image regions that are far apart spatially. Example: generating a teddy bear sitting next to a mirror requires the bear's texture on the left side to match its reflection on the right side. Convolutions localize information to neighborhoods, and even with a large receptive field, information mixing through multiple layers can distort fine correspondences. Additionally, U-Net becomes memory-heavy at high resolutions because even down-sampled feature maps consume significant VRAM, limiting the model's ability to handle 4K+ image generation without external tricks like tiling.

Diffusion transformer

Problem
Large-scale image and video generation requires a model that can capture long-range structural relationships and scale well with compute and data. Vision transformers showed that pure attention-based processing works for image understanding. The question is whether the same scaling laws apply to image generation: can we cut images into patches and use self-attention to let every patch globally interact, improving generation quality?
How It Works
Diffusion Transformer (DiT) represents the latent image as non-overlapping P×P patches (e.g., 8×8), treating each patch as a token, similar to word tokens in NLP. Each patch is linearly projected to an embedding vector of dimension D. Time and class label embeddings are created using sinusoidal functions (for time) and learned vectors (for class), then combined via addition or concatenation. These are passed through an MLP to produce adaptive layer norm parameters: alpha (gating coefficient), gamma (scaling vector), beta (bias vector). Patch embeddings are passed through stacks of diffusion transformer blocks. Each block contains: (1) layer normalization, (2) modulation by alpha, gamma, beta, (3) multi-head self-attention where queries, keys, and values all come from patch embeddings (allowing any patch to attend to any other), (4) residual connection, (5) layer normalization, (6) separate modulation, (7) feed-forward MLP, (8) residual connection. Position information is injected via learned or fixed embeddings added to patch embeddings, or via rotary position embeddings (RoPE) applied to queries and keys in attention. After all transformer blocks, embeddings are linearly projected back to match input latent shape, producing the predicted velocity or noise.
Why It Matters
Self-attention removes the locality bias of convolution: each patch can directly compare itself to any other patch in a single operation, enabling the model to capture any correlation across the image. This architectural flexibility matches the scaling laws observed in transformers for language: larger models trained on more data produce better results. Because patches reduce sequence length (a 32×32 image with 8×8 patches has only 16 tokens), attention is tractable even for modest image resolutions. Modern variants like multi-modal diffusion transformers (MM-DiT) extend this to jointly process text and images, using either single-stream attention (all tokens together) or dual-stream (separate streams for text and images that cross-attend). DiTs have become the dominant architecture in 2024–2026 for state-of-the-art image generation (Flux, Stable Diffusion 3, new models in 2025–2026) because they scale predictably: doubling model parameters and compute reliably improves sample quality.
Where It Breaks
Self-attention has O(N²) memory cost in sequence length N, so high-resolution images with many small patches become prohibitively expensive. Example: a 1024×1024 latent with 8×8 patches creates 16384 tokens; attention would require 268M comparisons. Additionally, adaptive layer norm applies the same scaling/shifting to all patches regardless of content: if the prompt is 'teddy bear next to white walls,' all patches are modulated identically, so brown texture is emphasized everywhere (problematic for the bear but not the walls). This motivated multi-modal variants using cross-attention or joint attention, where text tokens interact selectively with image regions. Weak design of time or condition injection can also lead to the model ignoring the prompt entirely, making the generation unconditional despite conditioning information being present.

Multi-modal Diffusion Transformer (MM-DiT)

Problem
Text-to-image generation requires the model to incorporate detailed text instructions while maintaining the image structure and detail that self-attention provides. Simple approaches like adaptive layer norm apply the same text-derived scaling to all patches, ignoring spatial context. Example: a prompt 'brown teddy bear next to white walls' should increase brown features only in the bear region, not globally; white should be enhanced only where walls are. How can text condition the model without a global broadcast?
How It Works
Multi-modal Diffusion Transformer uses joint or cross-attention to let image patches and text tokens interact dynamically. In single-stream joint attention, text token embeddings are concatenated with patch embeddings into a single sequence. Self-attention then runs across the combined sequence, so each patch can attend to relevant text tokens and vice versa. In dual-stream (or double-stream) variants, image and text go through separate self-attention blocks, but after each block there is a cross-attention layer where one modality queries the other: image patches use text tokens as keys and values, or vice versa. Some models use hybrid arrangements with both single-stream and dual-stream blocks. Time is still injected globally via adaptive layer norm (since all patches are at the same time step), but text conditioning is made spatially selective: patches can decide which words matter to them. During self-attention, the learned query and key transformations naturally create affinities—the word 'bear''s key may score high with patches in the bear region but low in the wall region.
Why It Matters
MM-DiT solves the spatial grounding problem: text conditioning becomes content-aware rather than broadcast. This improves prompt following and prevents unwanted texture bleeding. Empirically, multi-modal models released in 2024–2026 (Stable Diffusion 3 and later) show better alignment between prompts and outputs than earlier approaches. The flexibility to use joint or dual streams allows model designers to trade off efficiency (single-stream is faster) against fine-grained modality separation (dual-stream learns specialized projections for text vs. image). These models achieve state-of-the-art results and remain the standard for commercial and research image generation.
Where It Breaks
Joint attention on long text sequences (many tokens) plus high-resolution images (many patches) creates sequences of thousands of tokens, pushing attention cost into impractical territory (terabytes of intermediate activations). Dual-stream approaches reduce this but require more tuning. Additionally, if the model learns to ignore text tokens early in training, the conditioning signal becomes dormant; careful initialization (e.g., zero-initialization of gating parameters) is needed to prevent this. Cross-attention can also create unintended alignments if the model's learned keys do not meaningfully separate text concepts—e.g., the word 'bear' might attend equally to all patches if the learned projections do not build semantic meaning.

Examples Used

  • A U-Net preserving edge detail: high-resolution feature maps from early convolutional layers are concatenated to the decoder, so sharp edges survive the bottleneck compression.
  • A diffusion transformer with self-attention: if you want to generate a teddy bear next to a mirror, distant patches can directly attend to each other to match the bear's texture in the mirror without mixing information through many convolutional layers.
  • Text conditioning with adaptive layer normalization: at an early noisy stage (t=0.1), the model emphasizes brown and round features for a fluffy brown teddy bear; at a later clean stage (t=0.9), it emphasizes fine fur texture instead.
  • Joint attention in multi-modal transformers: text tokens like 'teddy bear' and 'reading book' can interact with image patches in the same attention layer, allowing patches to decide which words are relevant to their location.

Equations And Algorithm Moves

  • Represent the noisy latent as spatial features (U-Net) or divide it into P×P patches, treat each as a token for attention (DiT). Inject positional information so the model knows where each patch is.
  • Embed the time step t as a vector of sinusoidal functions at different frequencies (e.g., sin(t/10000^(i/D)) and cos(t/10000^(i/D)) for dimension i in D-dimensional space), matching how humans represent time at different scales.
  • Embed the condition C (class label or text tokens) using learned embeddings or pre-trained language models, producing vectors of the same dimension as patch features.
  • Combine time and condition embeddings and pass through a small MLP to produce adaptive layer norm parameters: alpha (gate), gamma (scale), beta (bias). Apply these element-wise to patch embeddings.
  • Run patch embeddings through transformer or convolutional blocks. In transformers, compute self-attention as softmax(Q·K^T/√D)·V where Q (queries), K (keys), V (values) come from patch embeddings, optionally rotated by position-dependent rotation matrices (RoPE).
  • Output predictions matching input shape (noise, score, or velocity). For iterative generation, use the predicted velocity with an ODE solver (e.g., Euler step: z_{t+dt} = z_t + velocity·dt) to move toward clean images.

Lecture 6 - Model Training

1h 40m · 12382 transcript words

Detailed Topic Explanation

Training a diffusion model means repeatedly showing the network corrupted images and teaching it to predict the correction. Each training step samples a random noise level (timestep), corrupts a clean image to that level, runs the model to get a prediction, measures the error against what should be predicted, and updates the weights. But uniform random timestep sampling trains the model equally on easy tasks and hard tasks. When noise is very high, the model can only predict where images go on average—an easy task. When noise is almost zero, minor tweaks suffice—also easy. The hard work happens in the middle, where the model must decide fine details, placement, and style. If you sample timesteps uniformly, the model gets trained less on these critical middle steps. In practice, people sample timesteps from a logit-normal distribution that emphasizes middle steps. This means the model spends more training time learning to handle the hard decisions. Additionally, the same noise level perceived by humans depends on image resolution—a noisy low-resolution image loses more information than a noisy high-resolution one because high-resolution images have redundant pixels that average out noise. So you need to adjust the noise level for different resolutions to maintain perceived noise consistency.

Time-sampled training hinges on the insight that not all timesteps require equal training effort. Early timesteps (very noisy) are easy because there is almost no signal in the input, so the model learns to predict the average direction toward real data. Late timesteps (nearly clean) are easy because the image is already almost correct, requiring only small refinements. Middle timesteps are genuinely hard: the model must decide global structure, local detail placement, texture, colors, and dozens of semantic choices with incomplete information. Using uniform sampling distributes training evenly across easy and hard timesteps, which wastes training on easy tasks and undersupplies the hard ones. The logit-normal distribution fixes this by mapping a standard normal distribution through a logit transform, which concentrates probability in the middle and allows tuning via mean and standard deviation. Separately, noise perception depends on resolution due to spatial correlation in images. A pixel in a high-resolution image is typically surrounded by pixels of similar value, so even if one pixel gets noise, nearby pixels average it out. In a low-resolution image, each pixel carries more visual weight, so noise affecting it causes greater information loss. The formal correction involves scaling the timestep by a factor that depends on the square root of resolution, ensuring consistent perceived noise across different image sizes. This resolution-aware timestep shifting ensures that training at different resolutions teaches the model consistent denoising behavior.

Core Ideas

  • Timesteps are not created equal: very noisy and nearly clean steps are easy to train, but middle steps are genuinely hard and require more training attention.
  • Logit-normal distribution over timesteps concentrates training effort on the middle, critical stages where the model must make hard semantic decisions.
  • Perceived noise depends on image resolution because high-resolution images have redundant spatial information that averages out Gaussian noise, while low-resolution images lose more when noise is added.
  • Timestep shifting adjusts the noise level for different resolutions to maintain perceptually consistent difficulty, so the model learns the same denoising strategy across resolutions.
  • Sampler distillation trains a student network to mimic what a teacher network does in many sampling steps, but in fewer or even a single step, trading a small quality loss for large speed gains.
  • Progressive distillation iteratively trains students to match teachers in half the steps, building up from T steps to T/2 to T/4 until reaching one step, keeping each task at roughly constant difficulty.

Approaches Taught

Time-sampled training

Problem
During training, the model must learn to handle all stages of generation, from extremely noisy to nearly clean. But not all stages are equally difficult: very noisy stages and nearly clean stages are easy—the model has little signal to work with at high noise, so it can only predict average directions, and at low noise, it only needs to fix minor details. The genuinely hard work happens in the middle, where the model must make many interconnected decisions about global structure, local details, texture, and semantics with incomplete information. Uniform sampling of timesteps wastes training effort by spending equal time on easy tasks.
How It Works
Instead of sampling timesteps uniformly from zero to one, sample from a logit-normal distribution that concentrates training probability around the middle timesteps. Construct this distribution by drawing a value x from a normal distribution and computing timestep t = sigmoid(x). By adjusting the mean and standard deviation of the normal distribution, you shift where training effort is concentrated—typically toward t around 0.5 where the hard decisions happen. Additionally, adjust the timestep for different image resolutions using the formula t_corrected = t + correction_factor * sqrt(resolution), which accounts for the fact that high-resolution images have redundant spatial information that reduces perceived noise, while low-resolution images have less redundancy and perceived noise is higher. This ensures that the model experiences perceptually similar noise levels across resolutions, learning consistent denoising behavior. Each training step remains the same: corrupt an image to the sampled timestep, run the model, measure loss, and update weights.
Why It Matters
Concentrating training on middle timesteps significantly improves model quality because those timesteps contain the hard decisions that distinguish good generations from poor ones. The model spends more training iterations learning to handle global structure and complex detail placement, rather than wasting effort on the easy extremes. Adjusting timesteps for resolution consistency ensures the model learns the same denoising strategy whether operating at high or low resolution, making the model more robust and generalizable. Without this, models can fail at certain resolutions or produce inconsistent quality.
Where It Breaks
If you use uniform timestep sampling, the model becomes well-trained on easy tasks and poorly trained on hard middle tasks. At generation time, the model fails to make good global structure decisions and produces incoherent or low-quality images. Additionally, if you ignore resolution-dependent perceived noise and apply the same timestep to all resolutions, the model learns inconsistent denoising strategies: what it learns at high resolution may not transfer correctly to low resolution or vice versa, causing quality to degrade when switching resolutions or when generating multi-resolution images.

Sampler distillation

Problem
A fully trained diffusion model or flow model typically requires many sampling steps (often hundreds or thousands) to generate a high-quality image. Each step involves running the model forward, which costs compute time. In production, running that many steps per image request is slow and expensive. You want to generate images much faster while retaining most of the quality, but directly asking a smaller model to match the full teacher's output in one step is impossibly hard—it would be like asking a student painter to create a masterpiece in a single stroke. You need a way to trade a small quality loss for a large speed gain.
How It Works
Sampler distillation trains a new student network to reproduce the multi-step denoising trajectory of a teacher network in fewer steps. Start with a trained teacher that takes many steps (T steps). Train a student to match what the teacher produces when taking every other step, so the student goes from very noisy to clean in T/2 steps. Once the student is trained, use it as the new teacher and train another student to match this teacher in T/4 steps. Continue iteratively—each student matches the previous student in half the steps—until you have a student that goes from noise to clean in just one or a few steps. This progressive approach keeps each learning task at roughly constant difficulty: each student only needs to learn how to make a moderately-sized denoising move, not an impossible jump. You can also use direct distillation where a student is trained via regression loss (mean squared error or perceptual loss like LPIPS) to predict the output of the teacher network. The teacher's predictions—whether noise, clean images, or velocities—serve as the regression target. By iteratively reducing steps or using consistency losses that enforce the student's predictions at different noise levels to agree, you gradually teach the student to require fewer function evaluations.
Why It Matters
Sampler distillation enables fast generation that is practical for production. A one-step or few-step model can generate images in milliseconds rather than seconds or minutes, making interactive applications and high-volume services feasible. The quality loss is often minimal—users may perceive no difference between a one-step distilled model and a 1000-step original, especially if the original was already oversampling (using more steps than necessary). This allows the model to scale to millions of users without prohibitive compute costs. The technique applies to any diffusion or flow model and works independently of the model architecture, making it broadly useful.
Where It Breaks
If you try to distill too aggressively—reducing steps too quickly or without enough training iterations per student—the student fails to learn the teacher's trajectory accurately. The result is that generated images lose fidelity, diversity, or semantic accuracy. They may become blurry or lose fine details because the student makes moves that are too large and misses the refined corrections that happen in the later steps. Additionally, direct MSE regression loss can cause regression to the mean, where images become blurry and lack crisp details because the loss equally penalizes all pixel differences without regard to perceptual quality. Using perceptual losses like LPIPS helps, but requires additional computation. If you don't properly regularize the student (for example, by using consistency losses or slow-moving average weights), the student can collapse to trivial solutions like always predicting zero. Another failure mode is that distillation assumes the teacher's multi-step trajectory is optimal; if the teacher itself was trained suboptimally or with uniform timestep sampling, distillation will propagate those suboptimalities.

Examples Used

  • A teddy bear image at timestep t=0 (extremely noisy) is almost pure noise, so the model can only predict the average shape of teddy bears in the training set, making the task easy.
  • At timestep t=0.5 (middle noise), the image shows rough structure but is missing eyes, precise texture, fur color, and pose details, forcing the model to make hard decisions about which details to fill in.
  • A low-resolution thumbnail with noise loses more visual information per pixel than a high-resolution image with the same noise level, because the high-res image has neighboring pixels that partially recover the corrupted value.
  • Progressive distillation with a 1000-step teacher starts by training a student to match the teacher in 500 steps, then uses that student as the new teacher for a 250-step student, continuing until a one-step model is learned.

Equations And Algorithm Moves

  • Sample a timestep t from a logit-normal distribution (not uniform) by drawing x from a normal distribution and computing t = sigmoid(x), which concentrates probability around t=0.5 and can be tuned by shifting and scaling the normal distribution.
  • For high-resolution images, rescale timestep t to t_new = t + correction_factor * sqrt(image_resolution), ensuring the model sees consistent perceived noise across different resolutions.
  • Sample a clean image and random Gaussian noise, then construct the corrupted state x_t using the forward process rule that blends the clean image and noise according to t.
  • Run the model f_theta(x_t, t) to predict noise, clean image, velocity, or another equivalent target depending on the chosen parameterization.
  • Compute the loss as the mean squared error (or other regression loss) between the model's prediction and the true target, then update theta with gradient descent, monitoring performance across all timestep ranges.

Detailed Topic Explanation

Evaluating an image generator is fundamentally different from evaluating classifiers because there is no single target to compare against. A classifier either predicts the right class or it does not; an image generator has infinite valid outputs. The problem splits into two dimensions. First is aesthetic quality: Does the image look like real photography? Are objects physically plausible? Is there unwanted blur, artifacts, or text errors? Second is prompt adherence: Does the image actually show what the prompt requested? If you ask for two dogs and one ball, do you get exactly that? Both dimensions matter independently: a photorealistic image that ignores the prompt is useless, and a prompt-accurate image that looks broken is also wrong. Beyond these two lie other concerns—does the model copy training data exactly, producing memorized samples? Does it fail on rare prompts or specific demographic groups? Does it generate unsafe content? Practical evaluation therefore requires multiple measurements working together. Distribution-level metrics compare the aggregate statistics of generated images to real images, measuring whether the overall distribution looks right. Prompt-alignment metrics check whether specific objects, counts, relationships, and styles from the text appear in the output. Human evaluation adds ground truth but is expensive and subjective. The key insight is that no single metric is sufficient; you must think of evaluation as a bundle of independent tests, each measuring a different failure mode.

The evaluation problem arises because generation is not a classification task. When your model generates an image, you cannot point to a reference image and say "your output should look exactly like this." Instead, you ask: does the generated distribution match the real distribution in meaningful ways? FID (Frechet Inception Distance) operationalizes this by embedding both sets of images through a pretrained network like Inception, which extracts high-level features like texture, color, and composition. You then summarize each distribution by its mean vector (where the center of the cloud is) and covariance matrix (how spread out and oriented the cloud is). The FID formula measures the distance between these two statistical summaries—lower is better. This captures both quality (location) and diversity (spread), but it hides individual failures: a model might achieve good FID while producing the wrong objects. For prompt adherence, CLIP scores measure text-image alignment in a shared embedding space, but dot products can miss fine-grained semantic distinctions. Newer approaches like VQA scores ask a model to answer "Does this image show X?" directly, embedding both modalities together rather than separately. The deepest challenge is that metrics can become targets: if you optimize FID alone, you might sacrifice prompt-following. If you optimize prompt alignment alone, you might sacrifice visual quality. This is why practitioners use multiple metrics in tandem and increasingly lean on multimodal LLMs as judges, which can provide reasoning for their scores and detect failure modes humans care about but metrics miss.

Core Ideas

  • Image evaluation is not comparing single outputs to references, but comparing statistical distributions of generated versus real image sets.
  • FID scores measure both quality and diversity by comparing mean and covariance of feature vectors extracted by a pretrained network.
  • CLIP and related alignment metrics check whether the generated image matches the prompt, but they are imperfect because dot products in embedding space lose semantic subtlety.
  • Multimodal LLMs can be used as judges to grade images on multiple dimensions like realism and prompt faithfulness, providing interpretable rationales alongside scores.
  • No single metric fully captures whether a generator works; multiple independent tests must each detect different failure modes.
  • Human evaluation remains necessary for ground truth but is slow, expensive, and subjective, so automation must complement rather than replace it.

Approaches Taught

Distribution-level evaluation

Problem
A generated image can look good in isolation, but the set of all generated images must resemble the set of real images in aggregate. If your model produces sharp but low-diversity images, or realistic but poor-quality images, a single reference-based comparison would be unfair because many valid outputs exist for each prompt. You need a measurement that compares statistics of the entire distributions, not individual samples.
How It Works
Pass both real images and generated images through a pretrained feature extractor, typically the Inception network, which outputs high-level feature vectors representing texture, color, composition, and semantic content. For each set, compute the mean vector (center of the cloud in feature space) and covariance matrix (spread and orientation). FID (Frechet Inception Distance) calculates the Wasserstein distance between two Gaussian approximations of these distributions, yielding a closed-form formula: the squared Euclidean distance between means plus a trace term comparing covariance shapes. Practically, this involves computing FID_50k, comparing 50,000 generated images to 50,000 real images. Lower FID indicates better alignment between distributions.
Why It Matters
FID provides a single, reproducible, distribution-aware metric that captures both quality and diversity without requiring manual construction of reference images. It scales to large datasets and allows comparison across different generator architectures. FID has become the standard benchmark in the field, enabling published comparisons. It directly addresses the fundamental problem that no single correct output exists: by comparing distributions, it sidesteps the need for a reference.
Where It Breaks
FID can be high even when the model produces poor semantic understanding. For instance, a model might generate two dogs and three balls for a prompt requesting two dogs and one ball—each object looks realistic, the overall distribution of colors and textures matches real data, yet the semantic content is wrong. Additionally, FID assumes both distributions are approximately Gaussian, which is often false for real image data; highly structured failures like mode collapse (where the model produces only one type of output) can be masked if that mode is realistic. FID also depends heavily on the choice of feature extractor; a different pretrained network might yield very different scores.

Prompt-alignment evaluation

Problem
A realistic image is still wrong if it does not obey the request. You might generate a photorealistic picture of a dog and a book, but if the prompt asked for a bear and a book, the output is a failure. Prompt-following requires checking that specific objects, their counts, spatial relationships, colors, styles, and attributes all appear as requested. Distribution metrics do not measure this because they operate on aggregate statistics and do not parse semantic content.
How It Works
CLIP score measures text-image alignment by independently encoding the prompt and image through separate CLIP encoders (text encoder and image encoder) trained on caption-image pairs, then computing cosine similarity between the resulting embeddings. A higher score suggests alignment. VQA score improves on this by feeding both the prompt and image jointly into a multimodal LLM and asking a yes-or-no question like 'Does this image show [prompt]?', then returning the probability that the model outputs 'yes'. PickScore fine-tunes a CLIP-like architecture on human preference data to provide a holistic score combining aesthetics and adherence. These approaches operationalize prompt-following by transforming it into a similarity or classification problem in embedding space, allowing automated measurement without human review.
Why It Matters
It directly measures whether the model is controllable by text, ensuring that the user can steer the generator to produce requested content. Without prompt-alignment evaluation, a model might score well on realism metrics but be useless in practice because users cannot reliably obtain what they request. Prompt-alignment scores separate quality (does it look good?) from controllability (does it do what I asked?), making it possible to identify and fix semantic failures separately from visual failures.
Where It Breaks
CLIP scores use dot products of compressed embeddings, which lose fine-grained semantic distinctions. Swapping 'teddy bear' and 'book' in a prompt might not substantially change the CLIP score, even though it changes the semantic meaning entirely. VQA scores depend on the multimodal LLM's ability to understand the prompt and image; subtle spatial relationships (e.g., 'to the left of' vs. 'next to') may be misunderstood. Both approaches can miss errors that matter to users: an image might contain all requested objects but with wrong colors, wrong counts (two dogs instead of one), or broken spatial relations (a person floating above a chair instead of sitting in it). Additionally, these metrics are not differentiable and are expensive to compute at scale, making it impractical to optimize them directly during training.

Examples Used

  • A prompt asks for two dogs and one red ball. A model generates one dog and two balls, failing the count test. FID might still be reasonable if the individual objects look realistic, showing that distribution metrics miss object-count errors.
  • An image shows a teddy bear reading a book, anatomically correct and photorealistic. But the bear's hands have six fingers each, and the book text is unreadable gibberish. FID scores high; human evaluation catches the failure.
  • Two generations both show a "green car on a beach." One is beautiful but has the car inside the water. The other has correct spatial relations but muddy colors. Human judges rank them differently; single-number metrics cannot resolve this tie.
  • A model excels on common prompts like "sunset landscape" but consistently fails on rare scenarios like "a person holding a banana while standing on their head." Benchmark averages hide this systematic failure.

Equations And Algorithm Moves

  • Compute FID: Embed real images x and generated images x' through Inception network to get feature vectors. Calculate mean vectors μ_real and μ_gen, and covariance matrices Σ_real and Σ_gen. FID equals the squared distance between means plus a trace term comparing covariance spread; lower FID means distributions align better.
  • Compute CLIP score: Encode the input prompt as text embedding e_text and the generated image as e_image using a pretrained CLIP model trained on image-caption pairs. Take the cosine similarity or dot product of these embeddings; higher similarity suggests the image and prompt align, but the score is coarse because both are compressed into single vectors.
  • Compute VQA score: Encode both the prompt and image together into a multimodal LLM. Ask a yes-or-no question like 'Does this image show [prompt content]?' Look at the probability that the model outputs 'yes'; this probability is the score. This embeds both modalities jointly rather than separately, capturing more semantic nuance than CLIP.
  • Compute LPIPS (Learned Perceptual Image Patch Similarity): Pass both the original image and generated image through a pretrained network like VGG to extract feature maps at multiple layers. Compute per-layer distance weighted by learned coefficients tuned to match human perception. This penalizes pixel shifts less than MSE because it works in feature space rather than raw pixels.
  • Use MLLM-as-Judge: Give a multimodal LLM the image, prompt, and a detailed rubric specifying what good looks like for aesthetics and prompt adherence. Ask the model to output a chain-of-thought reasoning first, then a structured score. The reasoning explains failure modes; the score quantifies performance. Unlike metrics, this is interpretable and can catch subtle failures.

Detailed Topic Explanation

Diffusion starts from random noise and iteratively removes it over many steps to reach clean data. Each step makes a small correction. The practical bottleneck is speed: sampling requires many sequential steps, so a 1000-step model cannot run on a phone or serve users in real time. Researchers attack this with three approaches: faster solvers that skip or jump between steps, consistency models that train a network to jump directly from any noise level to the final clean image, and distillation that trains a smaller model to match a large model's outputs in fewer steps. The key trade-off is that fewer steps means the model must be more accurate at each step. Beyond speed, diffusion adapts to new modalities. Video adds a time dimension, so frames must be consistent and motion plausible. The architecture extends diffusion to handle sequences of images, using temporal convolutions and causality constraints to prevent future frames from affecting past ones. 3D generation produces shapes and scenes by either generating multiple 2D views that agree on geometry, or by generating a 3D representation directly. Both video and 3D require solving a new problem: consistency across time or viewpoint. A shape must look correct from every angle, not just one camera view. A video must not flicker or change object identity between frames. Evaluating these extensions requires new metrics and careful measurement of temporal coherence and geometric correctness.

Why is faster sampling so hard? In standard diffusion, step t-1 depends on step t, which depends on step t-2, and so on. This sequential dependency means you cannot simply run step t and jump 10 steps ahead without losing information. A consistency model solves this by training a network such that from any point on the noise path, a single forward pass predicts the final clean image. This is mathematically possible because the reverse diffusion path is deterministic given the score, but it requires the model to learn a much harder function: predicting the endpoint from anywhere on the path. Distillation uses a different strategy. You train a teacher model first, then train a student model to match the teacher's output but in fewer steps. The student learns to approximate multiple teacher steps in a single student step. The tradeoff is that each student step must be more decisive. For video, the problem is more complex. A simple approach would be to treat each frame independently, but this causes flicker and incoherence. Instead, video models use causal convolutions in their VAE encoder. Causal means the representation of frame t depends only on frame t and earlier frames, not future ones. This lets the model stream frames through without loading all frames into memory at once. Then during diffusion, the model uses 3D convolutional layers that operate across space and time simultaneously, allowing frames to influence each other across the temporal dimension. The spatial consistency within a frame comes from standard 2D convolutions, while temporal consistency comes from these 3D temporal convolutions. For 3D generation, the challenge is that a shape must look right from every possible viewpoint. One method generates multiple 2D images from different camera angles, then checks if they are geometrically consistent by projecting them into a shared 3D space. Another method uses a 3D representation like a voxel grid or a signed distance function, then renders it to images. Both approaches add evaluation steps: you must check not just that each view looks good, but that the views agree on the underlying geometry. The failure mode is obvious: you get conflicting geometry that looks like an impossible object when viewed from different angles, or temporal incoherence where objects flicker or change identity between video frames.

Core Ideas

  • Diffusion requires many sequential steps because each step corrects the last. Faster methods must make each remaining step more accurate, creating a hard accuracy-versus-speed tradeoff.
  • Consistency models train a network to predict the final clean image directly from any noise level, eliminating step sequences but requiring a very precise map from noise to endpoint.
  • Distillation trains a smaller student model to approximate multiple teacher steps in fewer steps, making each student step more decisive and harder to learn.
  • Video generation must maintain temporal consistency: frames cannot flicker or change object identity between time steps, requiring causal architectures and temporal convolutions.
  • 3D generation produces shapes that must look correct from every viewpoint, not just one camera angle, requiring geometric consistency checks and multi-view validation.
  • Evaluating fast methods requires measuring not just speed but quality loss, while video and 3D methods require new metrics for temporal coherence and geometric correctness.

Approaches Taught

Fast generation methods

Problem
Producing high-quality diffusion or flow-matched samples currently requires 50 to 1000 sequential denoising steps, taking minutes to generate a single image. This sequential dependency makes interactive and large-scale deployment impossible. Each step corrects errors from the previous step, so removing steps means the remaining model must be extremely accurate. Balancing speed with quality is the fundamental tradeoff in faster generation methods.
How It Works
Three main strategies reduce the number of steps. First, faster ODE solvers use higher-order numerical methods to jump between noise levels more efficiently, cutting steps by a factor of 2–5. Second, consistency models train a network to predict the final clean image directly from any intermediate noise level, collapsing the entire path into one or a few inference steps. The network learns a map from (noisy_image, noise_level) to clean_image that is valid at every noise level on the diffusion path. Third, distillation trains a student network on outputs from a large teacher network, learning to approximate multiple teacher steps in one student step. The student minimizes the MSE between its output and the teacher output, effectively compressing the teacher's knowledge into fewer steps. All three approaches shift the computational burden from sampling time to training time: faster sampling requires more expensive pre-training.
Why It Matters
Speed determines whether diffusion can be deployed in interactive applications, on mobile devices, or at scale in production systems. A model that takes five minutes per image cannot power a web service with user-facing latency constraints. With consistency or distillation, a model can generate in one or two steps instead of 100, making real-time generation feasible. This moves diffusion from a research tool to a practical technology that can compete with other generation methods on latency and cost.
Where It Breaks
Faster methods sacrifice quality and sometimes diversity for speed. A consistency model trained to predict the endpoint from any noise level must compress all the complex structure of the diffusion path into a single map, so details are often lost. Distillation inherits the teacher's failures and adds new ones: the student must guess what the teacher would output in intermediate steps it never saw during training. In practice, a one-step consistency model produces blurry images compared to the original 100-step model. A distilled model on 4 steps instead of 100 may generate plausible but less detailed images. For example, a portrait might be generated quickly but with vague facial features or missing fine texture. The speedup is real but comes with visible quality loss that not all applications can tolerate.

Video and 3D generative extensions

Problem
Single-image diffusion does not handle time, motion, or viewpoint consistency. Videos are sequences of images where consecutive frames must not flicker or change object identity. 3D shapes must appear correct from every viewpoint, not just one camera angle. Standard diffusion treats each data point independently, so extending it to video or 3D requires solving new consistency problems: temporal coherence across frames and geometric coherence across views. Without these constraints, video generators produce temporal artifacts and 3D generators produce geometrically impossible objects.
How It Works
Video generation extends the diffusion pipeline to handle temporal sequences. Images are first compressed by a video VAE that reduces spatial dimensions using 2D convolutions and temporal dimensions using 3D (time-aware) convolutions. The VAE's encoder is causal, meaning each frame's latent representation depends only on that frame and earlier frames, not future ones. This enables streaming: you can encode frames sequentially without loading the entire video into memory. During diffusion, the model operates on space-time patches of latent codes and uses a diffusion transformer with 3D convolutions that attend across spatial and temporal dimensions simultaneously. The self-attention mechanism allows space-time patches to interact, ensuring frames influence each other's denoising. The result is temporal coherence: the model learns to move objects consistently across frames and avoid identity shifts. For 3D generation, one approach generates multiple 2D views from different camera angles. The model uses view-conditional generation, where the diffusion model is told which viewpoint it is generating for. Then a geometric consistency check projects these views into a shared 3D space and validates that they agree on depth and surface normals. Another approach generates a 3D representation directly, such as a voxel grid or a signed distance function, then renders it to 2D images. Both methods require evaluating not just individual views but the coherence of the shape's geometry across all views.
Why It Matters
Video and 3D generation expand the scope of what diffusion can do beyond single static images. Video is essential for creative applications: generating realistic motion, editing video content, and producing synthetic footage at scale. 3D generation enables virtual world building, product design, and game asset creation. These are high-value applications with large markets. By extending diffusion to these modalities, researchers have made the same core ideas (noise → structure → data) work on richer, more complex outputs. This shows that diffusion is not tied to images but is a general principle for sampling from complex data distributions.
Where It Breaks
Video generators trained without temporal consistency produce flickering, where objects appear to jump or vanish between frames, and identity shifts, where a person's face or a car's color changes inconsistently. Temporal metrics reveal these failures by comparing consecutive frames. For instance, optical flow between adjacent frames may show impossible motion (objects teleporting), or perceptual embeddings of objects across frames cluster into separate groups instead of staying coherent. For 3D generation, geometric incoherence appears when views disagree on shape. Rendering a generated 3D model from multiple angles may reveal an impossible object: a chair that has a solid front but a hollow back, or a head with misaligned features when viewed from the side. Multi-view consistency metrics measure this by comparing rendered images to ground truth 3D geometry or by checking if depth maps from different views project consistently into a shared 3D space. A concrete example: a video of a person waving may generate a hand that flickers in and out of existence as the noise schedule progresses through frames. A 3D model of a person might look perfect from the front but have a deformed back when rotated.

Examples Used

  • A standard diffusion model with 1000 steps takes minutes to generate one image. A consistency model trained to predict the endpoint directly can generate an image in one or two steps by predicting the final clean result without intermediate corrections.
  • A video model must render a teddy bear moving across a room such that the bear's identity remains consistent across 30 frames, and its shadow and reflections follow plausible physics. If the model uses independent frame generation, the bear might flicker or teleport between frames.
  • A 3D shape generator trained to generate a chair must produce geometry that looks correct when viewed from above, from the side, and from behind. A naive model might generate a front-facing chair that has an impossible back, revealed only when rendered from another angle.

Equations And Algorithm Moves

  • Consistency models solve the ODE dx/dt = v_theta(x, t) directly from any t to the final state, meaning x_final = Consistency_network(x_current, t_current) predicts the endpoint in one step. Why: eliminates sequential dependencies.
  • Distillation trains a student network to approximate T teacher steps in S student steps where S << T, minimizing the MSE loss between student and teacher outputs. Why: reuse teacher knowledge while reducing compute by the step ratio T/S.
  • Video diffusion operates on space-time patches with dimensions (1 + T) by f by f by c in latent space, where T is frames and f is spatial compression. Why: temporal compression exploits redundancy between consecutive frames just as spatial compression exploits pixel correlations.
  • Causal convolutions in video VAE ensure each frame's encoding depends only on that frame and earlier frames, not future frames. Why: enables memory-efficient streaming and ensures temporal information flows backward, not forward.
  • 3D geometric consistency is checked by rendering multi-view predictions into a shared coordinate system and measuring agreement on depth and surface normals. Why: verifies that the model learned a coherent 3D structure, not just plausible individual views.
